# Lan Copy v0.10.3 智能表格作为 CSV 可选标记计划

更新日期：2026-11-19。状态：**已批准并完成实现，自动化验证通过，待人工验收**。

## 背景与目标

v0.10.0 把智能表格做成了与“内网空间、碎片快传、打印队列”并列的独立页面，使用前需要进入 `/tables` 再从全部 CSV 中选择文件。这个入口把“表格”抬成了独立对象，与用户心智不一致：表格只是某个 CSV 文件的一种可选查看/编辑方式。

本版目标：

1. 移除顶栏“智能表格”入口与独立 `/tables` 页面，智能表格不再作为独立对象出现。
2. CSV 文件默认仍是普通文件；在文件行菜单中可把它**标记为智能表格**，标记后文件行显示“表格”标记。
3. 点击“表格”标记或双击已标记的 CSV，在内网空间内联打开该文件的表格视图；未标记 CSV 双击仍是原始文件预览。
4. 标记持久化到应用数据目录，重启后保留；可在行菜单中取消标记。
5. 保留现有 CSV 表格 API、插件 API、版本校验、原子写入和文件锁语义。

## 已确认的边界

- 标记是**按文件、可选、可取消**的 UI 状态，不写入 CSV 内容，不改变文件版本号。
- 表格视图只在内网空间内联打开，不占用独立路由；刷新页面后回到文件列表。
- 已标记的 CSV 才在文件列表中显示“表格”标记并提供默认表格入口；未标记 CSV 仍可预览、下载、改名、删除。
- 标记只影响浏览器入口；现有表格 API 继续以显式 `path` 访问任意合法 `.csv`，不要求先标记，保持 v0.10.0 协议兼容。
- 标记状态跟随 Lan Copy 内部的移动、重命名和删除操作；外部程序直接移动文件时允许留下不可见的旧标记，后续可重新标记。
- 不改变插件镜像、Manifest、生命周期事件、表格 API 权限、动作头、文件锁、原子替换和恢复语义。

## 非目标

- 不做多文件批量标记、收藏夹、标签体系或跨设备账号同步。
- 不把标记写入 CSV、文件名、扩展名或共享目录内的 sidecar 文件。
- 不新增独立表格路由、独立页面或顶栏入口。
- 不重新设计表格编辑器；查询、筛选、排序、分页、行新增/编辑/删除保持现有能力。
- 不改变插件通过 Bearer 令牌访问表格的方式，也不把插件挂载到共享目录。
- 不实现外部进程改名后的标记自动跟随；不监听共享目录之外的变更。

## 一、标记存储与 API

### 1.1 存储

新增 `tablestore` 内的标记状态，单独保存在应用数据目录：

```text
<dataDir>/table-marks.json
{"paths":["data/orders.csv","reports/inventory.csv"]}
```

- 只接受共享根目录内、扩展名为 `.csv` 的普通文件；路径使用 `/` 分隔的相对路径。
- 标记文件由 `tablestore.Store` 统一管理，使用互斥锁保护内存集合。
- 启动时加载；文件不存在视为空集合；JSON 损坏或字段非法时启动失败并指出文件，避免静默丢失状态。
- 保存时排序路径，使用临时文件、`fsync`、原子 `rename` 和目录同步，文件权限 `0600`。原子写实现复用 `filestore` 现有配置保存方式或抽出的最小 helper，不新增 `utils` 包。
- 标记不改变 CSV 字节，不触发文件生命周期事件，只触发目录列表刷新事件。

### 1.2 启动加载

- `tablestore.Store` 增加 `LoadMarks(dataDir)`；`app` 组装时在创建 Server 前调用，失败则按现有配置错误处理方式启动失败。
- 测试中可加载临时目录；未加载标记时视为空集合，不影响表格查询与更新。

### 1.3 HTTP 接口

新增写接口：

```http
POST /api/tables/mark
X-Lan-Copy-Action: tables
Content-Type: application/json

{"path":"data/orders.csv","marked":true}
```

- `marked=true`：校验路径为合法 CSV 并可解析，写入标记；文件不存在返回 404，非 CSV/非法路径/无效 CSV 返回 400。
- `marked=false`：删除标记；文件已不存在也允许取消，便于清理。
- 返回 `{"path":"data/orders.csv","marked":true}`，并通知文件列表刷新。
- 沿用 `tables` 动作头与同源校验；继续使用现有表格错误映射。

### 1.4 文件列表

`GET /api/filesystem` 的条目增加可选字段：

```json
{"name":"orders.csv","path":"data/orders.csv","directory":false,"table":true}
```

- 仅当文件是 `.csv` 且存在标记时返回 `table: true`；其他条目省略该字段。
- HTTP 层在返回前把标记集合与目录条目合并，标记仍由 `tablestore` 管理，不进入 `filestore` 的业务语义。
- 旧客户端忽略新字段，保持兼容。

### 1.5 移动、重命名与删除

在文件系统变更成功后同步标记：

| 操作 | 标记处理 |
| --- | --- |
| 文件重命名/移动 | 标记从旧路径迁移到新路径 |
| 文件夹重命名/移动 | 迁移该前缀下的全部标记 |
| 删除文件 | 删除该路径标记 |
| 删除文件夹 | 删除该前缀下的全部标记 |

- 这些同步是 best-effort：文件操作已成功时，即使标记保存失败也只记录日志，不回滚文件操作；内存状态仍会更新，下一次保存可恢复。
- 外部程序改名/移动不会触发上述同步；旧标记不可见，若同一路径重新出现 CSV 则可能重新生效，文档中注明。

## 二、文件列表交互

### 2.1 行内标记

- `FileEntry` 增加 `table?: boolean`。
- 已标记 CSV 在文件名后显示一个小型“表格”标签，复用现有 `file-tag` 视觉，但使用独立颜色与 `aria-label="打开智能表格：<文件名>"`。
- 标签是按钮：点击阻止行选择，直接打开该文件的表格视图；键盘可聚焦并回车触发。
- 未标记 CSV 不显示标签，不改变原有“新”标签、图标、排序和搜索行为。

### 2.2 行菜单

仅对单个 `.csv` 文件增加：

| 状态 | 菜单项 |
| --- | --- |
| 未标记 | “标记为智能表格”、“预览” |
| 已标记 | “打开表格”、“预览原文件”、“取消表格标记” |

- 非 CSV 文件菜单不变。
- 标记/取消标记调用 `/api/tables/mark`，成功后刷新当前目录并提示；失败保留原状态并提示错误。
- 标记后不自动打开表格，用户通过标签或双击进入；避免一次点击同时改变状态和切换视图。
- 多选时不显示批量标记项，保持本版范围。

### 2.3 打开方式

- 双击已标记 CSV：打开内联表格视图。
- 双击未标记 CSV：沿用原始文件预览。
- 行菜单“预览原文件”：已标记 CSV 仍可查看原始文本，不被表格视图锁死。
- 表格视图关闭后回到文件列表，焦点回到触发元素。
- `Escape` 关闭表格视图；切换目录、前进后退、打开其他预览时清理表格视图状态。

## 三、内联表格视图

`SmartTable.vue` 从“全量 CSV 管理页”收敛为单文件内联编辑器：

- 新增 `path` 属性与 `close`、`preview` 事件；移除文件列表、新建表格、搜索 CSV、选择文件等逻辑。
- 顶部工具栏：返回列表、文件名与路径、刷新、预览原文件、下载、关闭（移动端）。
- 保留查询、列筛选、排序、分页、主键选择、行新增/编辑/删除、版本冲突提示和插件调用示例。
- 版本冲突仍显示 409 文案并自动重新加载当前文件；文件被删除时显示错误并保留返回列表入口。
- 空表头、非法 CSV、超限文件等错误沿用现有提示。
- 不再调用 `listTables`；前端移除对应 API 函数，后端 `/api/tables` 列表接口保留以兼容外部调用。
- 组件挂载时直接加载 `path`；父组件使用 `:key="path"` 保证切换文件时重建状态。

样式：

- 新增内联容器，复用现有 `.tables-*` 表格样式，去掉 `.tables-layout`、`.tables-sidebar`、`.table-create-card` 等仅全量页面使用的布局。
- 内联视图占满 `explorer-main`，表格区域独立滚动，页面本身不产生双滚动条。
- 360–1280px 宽度下工具栏可换行、无横向溢出；移动端保留关闭按钮。

## 九、风险与限制

- 移除独立页面会影响已有 `/tables` 书签，本版用 302 保留可达性，但不会恢复当时选中的表格。
- 标记状态依赖应用数据目录；删除或迁移数据目录会丢失标记，CSV 本身不受影响。
- 外部程序改名不会迁移标记；旧标记不可见，不会阻止文件操作。
- 标记保存发生在文件操作之后，极端磁盘错误下可能出现文件已移动但标记未持久化；服务日志记录错误，内存状态仍正确。
- 内联表格比原全页面空间更窄，复杂表格需要横向滚动；通过独立滚动区和工具栏换行处理。
