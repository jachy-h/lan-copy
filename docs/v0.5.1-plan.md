# Lan Copy v0.5.1 计划

制定日期：2026-10-26。基于当前工作区的 Vue 迁移审查制定，不是已发布 tag 的审计。本文定义目标、实施阶段和验收条件；审查基线通过不代表本版修复或发布验收已经完成。实际实施状态与验证证据见 [v0.5.1 实施进度](v0.5.1-progress.md)。

## 背景与目标

保留 Vue 3 + TypeScript + Vite、多页面入口、Go 标准库 HTTP 服务及嵌入式资源的方案。它符合单进程、单二进制和离线运行要求，也保留了根目录 `go run .` / `go build .`。当前主要问题在资源构建闭环和预览生命周期，不需要重新选型或扩展前端框架。

v0.5.1 修复 PDF 关闭竞态，统一 HTML/样式产物处理，补齐预览与生产服务的集成验证，并完善 vendor 依赖校验与缓存策略。

## 范围与架构约束

- 保持单进程、单二进制、嵌入式前端，以及根目录 `go run .` / `go build .`；最终运行不依赖 Node.js 或 CDN。
- 保留当前 Vue/TypeScript/Vite 选型、多页面 URL、API、访问策略、文件与文本数据格式、上传恢复和更新身份校验。
- 仅为实际需求提取小型预览适配器或 composable，不引入新的通用状态库、路由框架、后端框架或空包。
- 本版不新增产品功能、预览格式或 MCP，不顺带升级所有依赖；确需升级时记录原因、影响与验证。

## 实施阶段与退出条件

### 阶段一：修复 PDF 异步销毁竞态（P1）

位置：`frontend/src/preview/engine.js:79-98`、`:365-379`。

`showPDF()` 等待动态 import 后直接调用 `getDocument()`；`destroy()` 只能销毁调用当时已经存在的 `pdfTask`。用户在首次模块下载期间关闭预览，随后 import 完成，会创建一个已经失去组件所有者的 PDF 加载任务。代码在 PDF promise 完成后也缺少终止检查，存在继续创建工具栏和写入旧容器的路径。

复现方法：使用 jsdom DOM，将 PDF 动态 import 替换为可控的延迟 Promise；调用 `mountPreview()`，等待进入 import 后调用 `destroy()`，再解析模块。结果为 `pdfTasksStartedAfterDestroy=1`、`pdfTasksDestroyed=0`。该验证证明任务创建竞态，不代表已经测量真实浏览器的内存泄漏量。

实施要求：在 import、文档加载、取页等异步边界后检查终止状态；确保延迟创建的任务也会销毁。增加关闭后 import 才完成、连续切换 PDF、关闭期间文档加载完成的回归用例。

**验收：** 关闭后不再创建无所属组件的 PDF 任务，旧任务不会写入新预览；加载中关闭、连续切换与重复销毁有行为回归用例，正常分页和缩放保持可用。

### 阶段二：统一 HTML、CSS 与资源同步（P2）

位置：`frontend/vite.config.ts:23-36`、`frontend/scripts/sync-assets.mjs:14-24`、`web/*.html`。

Vite 构建三个 HTML 页面，但同步脚本只从五个 TS 入口收集 JS 和 CSS，生产仍使用独立维护的 `web/*.html`。因此 `check-assets` 通过只证明选中的资源一致，不能证明生产 HTML 与开发 HTML 一致。

当前组件没有 SFC 样式块，所以暂未触发样式遗漏；一旦添加 `<style scoped>`，Vite 会提取 CSS，而生产手写 HTML 没有自动注入这些 CSS 链接。脚本也没有遍历 `dynamicImports` 与 `assets`，未来采用应用内懒加载或导入字体/图片时，可能出现本地开发正常、生产文件缺失。这里属于明确的构建覆盖缺口，不能描述为当前已有动态 chunk 404。

以 `frontend/*.html` 为唯一页面源，构建时生成并同步生产 HTML，保留现有 `/`、`/transfer.html`、`/preview.html` URL，不新增 Go 模板层。同步完整可部署资源，校验实际生产 HTML 引用的资源，而不只比较 JS 文件。

**验收：** 每个生产页面有唯一源码来源；SFC 样式、动态 import、图片/字体和嵌套资源均可在 Go 内嵌服务中加载。资源检查覆盖新增、修改、删除和 HTML 引用；同步失败保留原可用产物，干净检出仍能直接构建 Go。

### 阶段三：完善预览类型与生产行为验证（P2）

位置：`frontend/tsconfig.json:15`、`frontend/src/preview/engine.d.ts`、`frontend/src/components/PreviewPage.test.ts:6`。

`engine.js` 仍是约 382 行的 JS 实现；`.d.ts` 仅描述挂载/销毁接口，无法检查内部逻辑。预览组件测试 mock 掉整个引擎，只验证调用和销毁，不验证其取消逻辑、文档解析或 Worker 释放，所以问题 1 能通过现有检查。

生产 `/preview.html` 允许 `wasm-unsafe-eval`，共享空间内嵌预览所在页面使用另一套 CSP；开发 Vite HTML 又没有经过 Go 的页面安全头。这是需要实测的运行条件差异，不能仅靠静态文件返回 200 判断所有 PDF 都正常。

逐步将预览引擎迁入 TypeScript，按实际需要划分格式适配器并统一销毁契约。保留 Vitest 单测，另增加针对真实 Go 嵌入产物的浏览器集成检查，覆盖 PDF（含需要图像解码的样本）、DOCX、XLSX、反复开关、断网、Range 和资源释放。不要为了通过测试放宽所有页面 CSP。

**验收：** 预览实现进入类型检查范围；测试覆盖实际引擎的取消与资源回收，不能仅 mock 挂载接口。弹窗和独立预览均在真实 Go 服务上验证，记录浏览器、文件样本和结果；未具备环境的项目明确保持未验证状态。

### 阶段四：明确升级缓存策略（P2）

位置：`frontend/vite.config.ts:33-36`、`internal/httpserver/routes.go:61-73`。

产物使用固定文件名，静态服务没有显式 Cache-Control。当前检查没有证明升级后各浏览器都会重新获取一致版本的 HTML、JS 和共享 chunk，因此存在缓存导致版本混用的风险；本次未复现浏览器缓存故障。

采用内容 hash 文件名，由 HTML 生成过程写入引用；HTML 显式重验证，带 hash 的资源使用长期缓存。补充服务升级后刷新页面的集成验收；保持固定路径的 vendor 等资源显式要求重验证。

**验收：** HTML 与资源响应头匹配所选命名策略；从旧版页面升级并刷新后能加载一致的新版本。验证旧标签页后续触发懒加载时的可恢复行为，不因缓存策略破坏文件下载及预览 Range 语义。

### 阶段五：vendor 校验与最终回归（P2）

位置：`web/vendor/{pdfjs,docx-preview,sheetjs}/README.md`。

手工 vendor 本身合理，尤其是完全离线运行和 SheetJS 的官方分发来源。问题是 npm 检查与产物同步检查均不负责验证这些实际运行的第三方文件。

维护一份统一清单，记录来源、版本、许可、tarball integrity 和选中文件摘要；添加显式的更新/验证命令，CI 验证仓库文件摘要，开发文档说明如何检查上游公告。普通 Go 构建不联网下载这些库。

**验收：** 校验命令能检测第三方文件被修改或遗漏；更新命令验证上游包完整性并保留许可证。固定工具链下干净安装、前端检查、Go 回归与受影响构建入口通过；Docker、跨平台运行及发布包验证分别记录，不能用交叉编译代替平台运行验收。

## 按实际需要纳入的清理

- 多个 `createApp()` 目前共享一个 Vue runtime，不等于重复打包 Vue；可继续采用这种渐进式挂载。随着共享状态和生命周期协调增多，可按页面收拢到一个根组件。
- `FileExplorer.vue` 集中处理列表、选择、上传、SSE、预览和 DOM 事件；应按实际职责提取 composable，不按行数机械拆组件。
- 该组件为静态预览 dialog 注册的部分匿名监听器没有在卸载时解绑；当前完整页面生命周期下影响有限，未来支持重挂载时会积累监听。建议统一用 AbortController 或具名回调清理。
- `App.vue` 和 `src/pages/mount.ts` 是未被实际页面使用的迁移脚手架，可以清理，避免误导后续开发。
- Docker 和普通 `go build .` 使用已提交资源，符合无 Node 运行/构建入口兼容目标；应继续由 CI 保证这些资源与源码一致。
- 固定 Node/npm 和 lockfile 有利于发布复现；建议增加开发环境一键切换/诊断命令，而不是绕过 `engine-strict`。
