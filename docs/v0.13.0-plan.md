# Lan Copy v0.13.0 插件上传 Hook 与确认弹窗计划

更新日期：2026-11-23。状态：**已批准并完成实现，自动化与端到端验证通过，待人工验收**。

## 背景与目标

插件目前通过 `file.uploaded` 生命周期事件获知上传结果，但事件是异步的、只投递不等待结果，插件无法把“这次上传需要用户确认”的页面带回给上传者。发票插件因此只能在上传后自动 OCR 并直接写表，缺少人工校对环节。

本版增加一个同步的**上传 Hook**：

1. 文件上传事务提交成功后，Lan Copy 调用插件 Manifest 中声明的上传 Hook。
2. Hook 可以做目录、文件类型、大小等快速校验，并返回一个插件页面路径。
3. Lan Copy 把返回的页面放进当前文件页的弹窗 iframe 中展示。
4. Hook 失败、超时、插件未运行都不影响上传成功；失败只记录日志。
5. 页面只能位于当前插件的 `/plugin-app/<插件ID>/` 代理下，不接受任意外部 URL。

首个使用场景是发票插件：上传到监听目录后弹出确认页，页面展示发票预览和 OCR 字段，用户修改并确认后再写入指定智能表格。

## 已确认的决策

- **识别时机**：Hook 只做快速校验并立即返回页面；OCR 由插件页面异步触发/轮询，避免上传响应等待 6–10 秒。
- **弹窗粒度**：一次上传只返回一个弹窗；页面内用列表/标签展示多张发票。核心协议仍支持多个弹窗，前端按队列依次展示。
- **发票写入模式**：上传走人工确认；移动、重命名和手动扫描保持现有自动归档。发票插件增加“上传后人工确认”开关并默认开启。
- **修改范围**：同时修改 `lan-copy` 核心和 `lan-copy-extensions/invoice-ocr` 插件。
- **目录过滤**：沿用发票插件现有 `watch_folders` 配置；Lan Copy 对所有上传调用 Hook，插件自行判断是否处理并返回 `204`。
- **签名**：复用 `LAN_COPY_EVENT_TOKEN`，使用与生命周期事件相同的 HMAC-SHA256 签名方案。
- **页面约束**：只接受插件相对路径，由 Lan Copy 统一拼接 `/plugin-app/<插件ID>`；拒绝绝对 URL、协议头和 `..`。
- **失败语义**：Hook 不重试、不阻塞上传结果；上传成功与 Hook 成功相互独立。

## 非目标

- 不做通用 Webhook 市场、任意 URL 回调、插件间通信或远程地址代理。
- 不做 Hook 的持久化队列、补发、重放或投递记录页面。
- 不在 Lan Copy 内渲染发票业务表单；页面由插件提供。
- 不改变现有生命周期事件的异步语义、投递重试和订阅规则。
- 不改变智能表格 API、插件鉴权模型、插件 UI 代理路径。
- 不为移动、重命名、手动扫描提供确认弹窗。
- 不做账号登录、SSO 或插件页面级权限控制。
- 不引入 iframe `sandbox`：插件页面需要同源调用自身后端；信任边界仍是“只安装可信插件”。

## Manifest 扩展

`Manifest` 增加可选字段：

```json
{
  "uploadHook": {
    "path": "/hooks/upload",
    "timeoutSeconds": 5
  }
}
```

规则：

| 字段 | 规则 |
| --- | --- |
| `uploadHook` | 省略或 `null` 表示不接收上传 Hook |
| `uploadHook.path` | 必填，`/` 开头的绝对路径，≤256，不含 `..`、查询串、片段、空白和控制字符 |
| `uploadHook.timeoutSeconds` | 1–30，默认 5 |

- 旧插件不声明 `uploadHook` 时行为完全不变。
- 新插件声明 `uploadHook` 后，旧版 Lan Copy 会因严格 JSON 拒绝安装；文档注明最低版本为 v0.13.0。
- `schemaVersion` 保持 1，不提升协议主版本。
- 不增加 `directories` 字段：目录规则属于插件业务配置，不写死在镜像 Manifest 中。

## Hook 请求协议

Lan Copy 在 `POST /api/upload-tree` 提交成功后，对每个声明了 `uploadHook` 且处于 `running` + `healthy` 的插件发起一次请求。一次上传批次只调用一次，不按文件逐个调用。

```http
POST /hooks/upload
Content-Type: application/json
X-Lan-Copy-Hook: file.uploaded
X-Lan-Copy-Hook-Id: hook-01J...
X-Lan-Copy-Timestamp: 1763435045
X-Lan-Copy-Signature: v1=<hex>
```

请求体复用生命周期事件信封：

```json
{
  "schemaVersion": 1,
  "id": "hook-01J...",
  "type": "file.uploaded",
  "occurredAt": "2026-11-23T03:04:05Z",
  "data": {
    "destination": "发票",
    "files": [{ "path": "发票/a.pdf", "size": 182344 }],
    "directories": [],
    "counts": { "files": 1, "directories": 0 },
    "truncated": false
  }
}
```

签名：

```text
HMAC-SHA256(key = LAN_COPY_EVENT_TOKEN, message = timestamp + "." + 原始请求体)
```

- 与 `/events` 使用同一密钥和时间戳窗口；建议插件校验 5 分钟内。
- 不重试；网络错误、超时、非 2xx 都只记录日志。
- 单插件超时来自 Manifest，调用之间并发执行，避免多个插件串行叠加延迟。
- 只在上传批次至少包含一个文件时调用。
- `files` 沿用 `file.uploaded` 的 100 项上限；`truncated=true` 时插件应提示用户分批上传。

## Hook 响应协议

成功响应（2xx）：

```json
{
  "schemaVersion": 1,
  "dialogs": [
    {
      "title": "确认发票信息",
      "path": "/review/01J..."
    }
  ]
}
```

- `204` 或空响应体表示这次上传不需要弹窗。
- `dialogs` 省略、为空数组也表示不弹窗。
- 每个插件最多返回 5 个弹窗，一次上传总计最多 10 个；超出截断并记录日志。
- `title` 可选，默认使用插件名称；最长 100 字符，剔除控制字符。
- `path` 必填，必须以 `/` 开头，不能是 `//`、不能包含协议头、`..`、空白、控制字符或 `#`；允许查询串；最长 1024。
- `path` 不允许以 `/plugin-app/` 开头，避免重复前缀。
- Lan Copy 最终生成 `"/plugin-app/" + pluginID + path`，并再次校验路径，不信任插件返回值。
- 返回页面要求插件 Manifest 声明了 `ui`；未声明时忽略并记录日志。
- 响应体上限 64 KiB；2xx 但 JSON 无效时忽略，不影响上传。

## 后端实现

### 1. `internal/plugin/manifest.go`

- `Manifest` 增加 `UploadHook *ManifestUploadHook`。
- 新增 `ManifestUploadHook` 类型和默认超时归一化。
- 校验路径、超时范围；未知字段仍然拒绝。
- 补充 `manifest_test.go` / `validate_test.go` 用例。

### 2. `internal/plugin/upload_hook.go`

新增上传 Hook 执行器：

```go
type UploadHookDialog struct {
    PluginID   string
    PluginName string
    Title      string
    Path       string // 插件内相对路径
}

func (m *Manager) RunUploadHooks(ctx context.Context, data FileUploadedData) []UploadHookDialog
```

实现要点：

- 在锁内收集候选实例、Manifest、地址、Hook 路径、超时和 `LAN_COPY_EVENT_TOKEN`，锁外发请求。
- 只选择 `StatusRunning` 且 `HealthStatusHealthy`、`InternalAddress` 非空的实例。
- 复用 `internal/plugin.Client.Do`，保持重定向策略、响应上限、调用指标和超时分类一致。
- 使用 `Request.Body` 发送已序列化的 JSON，并手动设置 `Content-Type` 和签名头。
- 并发调用各插件；单个插件失败只记录日志。
- 校验并清洗响应中的 `title` / `path`，返回按 plugin ID 稳定排序的结果。
- 新增 `upload_hook_test.go`：签名、请求体、并发、超时、非 2xx、无效 JSON、非法路径、未运行/不健康实例、UI 缺失。

### 3. `internal/httpserver/plugin_events.go`

抽出可复用的上传事件数据构造：

```go
func uploadEventData(destination string, files []fileInfo, directories []string) plugin.FileUploadedData
```

`publishUpload` 与 Hook 调用共用，避免两套字段逻辑。

### 4. `internal/httpserver/upload_tree.go`

- 提交成功、`notifyFilesChanged()` 和 `publishUpload()` 之后调用 Hook。
- Hook 使用请求上下文；客户端断开时取消等待。
- 在 201 响应中增加可选字段：

```json
{
  "files": [...],
  "directories": [...],
  "pluginDialogs": [
    {
      "pluginId": "invoice-ocr",
      "pluginName": "Invoice OCR",
      "title": "确认发票信息",
      "url": "/plugin-app/invoice-ocr/review/01J..."
    }
  ]
}
```

- `pluginDialogs` 为空时省略，保持旧客户端兼容。
- Hook 失败不改变 201 状态码。
- `Server` 增加 `runPluginUploadHooks` 测试覆盖字段，生产为 nil 时走 `s.plugins.RunUploadHooks`。

### 5. 路由与安全头

- 不需要新增公开路由；Hook 是 Lan Copy 主动调用插件。
- 主页面 CSP 显式增加 `frame-src 'self'`，允许同源插件页面嵌入。
- `/plugin-app/` 代理继续删除 Lan Copy 自己的 `X-Frame-Options` 和 CSP；插件页面必须自行允许被同源 iframe 嵌入（`frame-ancestors 'self'`）。

## 前端实现

### 1. `frontend/src/upload/progress.ts`

### 2. 上传响应解析

`FileExplorer.vue` 当前 XHR 成功回调忽略响应体。改为：

- 解析 `xhr.responseText`，失败时按空对象处理。
- 读取 `pluginDialogs`，校验为数组并过滤无效项。
- 上传成功后把弹窗加入队列；不因弹窗失败而把上传判为失败。
- 冲突重试循环保持原逻辑，最终成功响应才取弹窗。

### 3. 新增 `frontend/src/components/PluginDialog.vue`

- 使用原生 `<dialog>` + `showModal()`，大尺寸响应式弹窗：
  - 桌面宽度 `min(1120px, calc(100% - 32px))`，高度 `min(88dvh, 900px)`；
  - 窄屏接近全屏。
- 头部显示插件名、标题、关闭按钮；内容区是 `<iframe>`，无边框、占满剩余高度。
- `iframe` 使用 `referrerpolicy="no-referrer"`。
- 监听 `message`：
  - 必须 `event.origin === location.origin`；
  - 必须 `event.source === iframe.contentWindow`；
  - 支持 `lan-copy:plugin-dialog:close`；
  - 支持 `lan-copy:plugin-dialog:complete`，可带 `message` 和 `refresh`。
- 组件只发出事件，不直接操作文件列表，便于测试和复用。

### 4. `FileExplorer.vue` 队列

- 完成：关闭当前，刷新目录和目录树，显示插件返回的提示或默认“插件操作已完成”。
- 上传完成后立即把弹窗加入队列；列表刷新可以同时进行。

## 安全边界

| 项 | 固定行为 |
| --- | --- |
| Hook 鉴权 | `LAN_COPY_EVENT_TOKEN` + HMAC-SHA256 + 5 分钟时间窗 |
| 触发范围 | 只调用本程序管理、运行中且健康的插件实例 |
| 页面地址 | 只接受插件相对路径，统一拼接 `/plugin-app/<id>`，拒绝外部 URL |
| Hook 失败 | 不影响上传结果，不重试，不写入用户可见错误 |
| Hook 超时 | Manifest 限制 1–30 秒，默认 5 秒 |
| 响应大小 | 64 KiB |
| 弹窗数量 | 单插件 5 个、单次上传 10 个 |
| 同源页面 | 插件页与 Lan Copy 同源，页面可调用 Lan Copy API；只安装可信插件 |
| 目录过滤 | 由插件配置决定；Lan Copy 不做业务目录硬编码 |

## 兼容性

| 组合 | 行为 |
| --- | --- |
| 新核心 + 旧插件 | 旧插件无 `uploadHook`，上传行为不变 |
| 旧核心 + 新插件 | 新 Manifest 字段被严格解析拒绝，安装失败；需先升级核心 |
| 新核心 + 新插件 + 关闭确认 | Hook 返回 204，生命周期事件自动归档保持原行为 |
| 新核心 + 新插件 + 开启确认 | 上传弹窗确认后写表；移动/重命名/扫描仍自动 |

端到端（与 invoice-ocr 1.3.0 一起）：

1. 构建并安装新核心与发票插件。
2. 在发票插件配置监听目录和智能表格。
3. 上传一张发票到监听目录。
4. 确认上传完成、弹窗出现、页面内 OCR 完成并展示字段。
5. 修改一个字段，点击确认，检查表格新增一行且值正确。
6. 重复上传同一文件，确认不会产生重复行。
7. 上传非发票文件，确认页面提示无法识别且不写表。
8. 关闭插件或让 Hook 超时，确认上传仍成功且不弹窗。
9. 在手机宽度检查弹窗可滚动、可关闭、iframe 不溢出。

## 风险与后续

- 插件页面与 Lan Copy 同源，拥有与主页面相同的 API 能力；这是现有插件 UI 的既有信任模型，不新增隔离层。
- 发票插件重启会丢失未确认的审核会话；文件仍在共享目录，可用“立即扫描现有发票”补归档。后续可考虑持久化会话。
- Hook 只拿到前 100 个文件路径；超大文件夹上传需要分批或后续扩展协议。
- 页面异步 OCR 需要插件自行实现轮询和状态管理；核心只负责弹窗和消息桥。
