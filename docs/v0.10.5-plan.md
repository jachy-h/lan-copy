# Lan Copy v0.10.5 资源面板占用统计计划

更新日期：2026-11-20。状态：**待批准**。

## 背景与目标

设置弹窗的“资源”页目前只有一行由 `/api/files` 全量列表临时汇总出的存储占用，上传并发数、暂存空间和下载任务的实际占用都没有展示。用户能看到限制值，却看不到这些资源当前被占用了多少。

本版目标：

1. 在设置 → 资源页用一组统计卡片展示“已占用的资源”：
   - 共享文件：已占用字节数与文件数。
   - 上传任务：进行中数量与并发上限。
   - 暂存空间：已预留字节数与配置上限。
   - 下载任务：进行中数量。
2. 新增一个只读聚合接口，一次返回上述数据，避免前端自己拉取文件列表计算。
3. 统计在打开设置、切换到资源页和点击刷新时更新；局域网访客也能看到同样的只读统计。
4. 不改变现有的上传并发、暂存空间、空闲超时配置与写入权限。

## 已确认的边界

- 统计是只读的瞬时快照，不记录历史峰值、不提供趋势图。
- 只暴露聚合数字，不返回文件名、路径或传输方信息。
- 访客可读，与现有资源页的只读配置一致；配置写入仍只允许本机同源请求。
- 统计不改变上传/下载的限流、预算、超时和关停确认语义。
- 共享文件统计继续按共享根目录内所有可见普通文件递归汇总，与 `/api/storage` 语义一致。
- 暂存空间统计使用 `filestore.Resources` 内已预留的字节数，不扫描暂存目录的磁盘占用；事务提交或回滚后实时释放。
- 上传任务统计使用现有 `Resources.Begin/End` 计数；下载任务统计使用现有传输跟踪器。
- 不新增轮询和 SSE 推送，只在用户打开面板、进入资源页或手动刷新时读取。

## 非目标

- 不显示磁盘剩余空间、每块磁盘容量或系统内存/CPU。
- 不显示单个上传/下载的名称、进度、来源 IP 或所属设备。
- 不做按目录的存储占用明细、排行榜或清理建议。
- 不修改 `/api/storage`、`/api/files`、`/api/settings/upload-resources` 的请求和响应结构。
- 不改变上传并发、暂存空间限制的校验范围和配置持久化方式。

## 一、后端统计

### 1.1 `internal/filestore/resources.go`

新增只读快照：

```go
type ResourceUsage struct {
    ActiveUploads int   `json:"activeUploads"`
    StagedBytes   int64 `json:"stagedBytes"`
}

func (m *Resources) Usage() ResourceUsage
```

- 在同一把互斥锁内读取 `active` 与 `staged`，保证与 `Begin/End/Reserve/Release` 一致。
- 继续保留现有 `Snapshot()` 只返回 `ResourceConfig`，避免改变已有调用方。

### 1.2 `internal/httpserver`

新增 `GET /api/resource-usage`，响应：

```json
{
  "storage": {"bytes": 1048576, "files": 12},
  "uploads": {"active": 1, "limit": 3},
  "staging": {"usedBytes": 5242880, "limitBytes": 21474836480},
  "downloads": {"active": 2}
}
```

- 设置 `Cache-Control: no-store`。
- 只注册 GET；其他方法由 `http.ServeMux` 返回 405。
- 不做本机限制，局域网访客可读；响应中不含敏感明细。
- `storage` 复用 `s.files.Usage()`；失败时返回 500 和“无法统计共享存储”，避免显示半套统计。
- `uploads`/`staging` 在 `s.uploadResources == nil` 时返回 `0/0`，前端显示为“未启用”。
- `limitBytes = stagingGiB * 1 GiB`；`limit` 为该时刻配置的并发上限。
- `downloads.active` 来自 `s.transfers.snapshot()`。
- 新增处理器文件 `internal/httpserver/resource_usage.go`，路由注册在 `routes.go` 的资源设置附近。

### 1.3 分层

- HTTP 层只负责聚合与响应格式、访问策略和状态码。
- 上传占用由 `filestore.Resources` 自己提供；下载计数由传输跟踪器提供；HTTP 不另建共享可变状态。

## 二、前端资源页

### 2.1 数据加载

- `SettingsDialog.vue` 新增 `ResourceUsage` 接口和 `resourceUsage` 状态。
- `loadResources()` 先请求 `/api/resource-usage`，再请求 `/api/settings/upload-resources` 读取配置。
- 删除当前通过 `/api/files` 全量遍历计算占用空间的逻辑。
- 打开设置时加载一次；`switchTab('resources')` 时重新加载。
- 在资源页增加“刷新”按钮，点击后重新读取统计和配置。
- 统计失败时保留配置区域可用，只把统计区显示为错误提示。

### 2.2 展示

资源页标题下改为统计区，后续保留现有三个上传限制输入框和保存按钮：

```text
共享文件      1.0 MiB · 12 个文件
上传任务      1 / 3 进行中
暂存空间      5.0 MiB / 20.0 GiB
下载任务      2 个进行中
```

- 使用 `dl`/`dt`/`dd` 语义结构，数值使用等宽数字样式。
- 上传任务与暂存空间显示进度条（`<progress>`），最大值为配置上限；上限为 0 时显示“未启用”并隐藏进度条。
- 共享文件与下载任务只显示数量，不显示进度条。
- 数字继续复用现有 `formatBytes`；文件数与任务数使用中文量词。
- 保留 `aria-live="polite"` 的加载/错误状态，避免每次刷新都打断读屏。
- 布局在 360–1280px 下为单列；宽屏为两列统计卡片，不产生横向溢出。

### 2.3 文案

- 页面说明改为：“查看共享文件、上传、暂存空间和下载的当前占用，并设置上传并发数、临时接收空间和连接空闲时间。限制仅影响之后开始的上传。”
- 统计区标注“统计为当前时刻快照”。
- 配置不可编辑时继续显示原有只读原因，不因统计接口可读而变化。

## 六、风险与限制

- 共享存储统计需要递归遍历共享目录；目录很大时首次读取会有延迟。保持按需读取，不做定时轮询。
- 统计是瞬时值，刷新之间可能变化；界面明确标注快照属性。
- 暂存占用来自内存预留计数，与磁盘上暂存目录的实际字节数可能因删除失败等极端情况短暂不一致；以资源管理器的预算为准，不额外扫描磁盘。
- 访客能看到聚合占用数字，但看不到文件名和传输明细；这与现有资源页的只读可见性一致。

## 七、验收清单

1. 打开设置 → 资源页即可看到共享文件、上传任务、暂存空间、下载任务四项占用统计。
2. 上传进行中时上传数与暂存占用增加，完成后回落；下载进行中时下载数增加。
3. 修改并发数或暂存空间上限并保存后，统计中的上限立即更新。
4. 局域网访客能看到统计，但输入框只读、保存不可用。
5. 统计读取失败时显示错误，上传限制输入与保存仍可用。
6. 360–1280px 宽度下统计区与配置区无横向溢出。
