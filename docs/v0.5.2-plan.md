# Lan Copy v0.5.2 计划

制定日期：2026-10-26。基于当前 v0.5.1 工作区、上游官方文档及包元数据检查。本轮仅制定方案，不安装新依赖、不修改实现或版本号；开始实施后创建 `docs/v0.5.2-progress.md` 记录实际进展。

## 2026-10-26 追加：导航与 SPA 优化

本次实施范围为用户追加的三项前端优化，原依赖与脚本迁移阶段继续保留，分别记录进度。

1. 顶栏操作统一为分享、设置、局域网在线，状态放在最右侧，并检查桌面、平板、手机宽度。
2. 共享空间和文本快传使用同一个 Vue 应用，通过 History API 切换；保留 `/`、文件夹 hash、直接访问、刷新与浏览器前进/后退。切换保留文本草稿和最近文件夹地址，公共顶栏不重新挂载。文本快传正式地址为 `/transfer-text`，旧 `/transfer.html` 以 HTTP 308 重定向并保留查询参数，开发服务同步支持。独立预览页保持现有入口。
3. 按实际重复抽取公共顶栏、页脚、文件预览弹窗及浮层交互。业务页面卸载时释放请求、SSE、定时器及右键菜单提供者，避免遗留闭包或重复事件。现有 HTTP API、Go 入口与嵌入式资源布局保持兼容。

**验收：** 类型检查、前端与资源同步测试、产物一致性、Go 测试/vet/build；真实 Go 服务下三浏览器验证无整页导航、草稿/文件夹地址保留、历史导航、窄屏状态位置，以及文件/文本/预览和升级资源恢复。进度见 [v0.5.2-progress.md](v0.5.2-progress.md)。本次不以导航优化完成代表依赖与脚本迁移已完成，也不提前修改版本元数据。

## 背景与目标

v0.5.1 通过手工 vendor 清单与 Python 脚本检查预览依赖。项目已有 Node/npm/Vite 工具链，可将第三方库的版本、获取和完整性交给 npm，以 JavaScript 实现资源生成与一致性检查，减少重复清单和语言切换。

本版目标：四个预览库均由 package.json 与 lockfile 管理；保留同源、离线预览与单 Go 二进制；移除自建的 tarball 下载/摘要维护流程；优先把现有脚本迁入 Node.js，迁移发布编排时明确处理跨平台锁和进程语义。

## 依赖与资源方案

### 依赖声明

- 在现有 `frontend/package.json` 的 dependencies 中增加上述四个库，继续使用同一个 lockfile，不新增根目录 package.json 或第二套依赖树。
- 保持现有版本，先完成管理方式迁移，不混入库升级。JSZip 同时是项目脚本直接使用的库，明确列为直接依赖，核对 docx-preview 实际解析到的 JSZip 与复制的版本一致。
- 保留 Node 24.18.0 / npm 11.16.0。依赖更新使用明确版本和官方来源；不对所有安装脚本或 optional dependencies 一刀切禁用，以免破坏 Vite/esbuild。
- PDF.js 声明了 Node Canvas 可选依赖，评估安装体积与各平台安装行为；浏览器资源只选取所需文件，不将 Node Canvas、node_modules 或开发测试库复制进二进制。
- SheetJS 官方 tarball 获取发生在开发/CI 安装时，运行时无需访问 CDN。全新安装仍需联网或可用的 npm 缓存；不把 lockfile 解释为离线安装包。

### 由 JS 从安装包生成预览资源

本版采用“npm 管理来源 + JS 生成现有静态资源布局”的路径，保留当前 `/vendor/...` URL 与已验证的加载方式，降低同时更换模块加载器的风险。npm 管理不要求每个库都直接打入页面 JS。

- 新增小型 JS 资源准备模块，由 Vite 构建和开发服务共同使用。通过明确的包解析定位安装目录，不依赖 npm 缓存布局、开发机绝对路径或未经声明的传递依赖。
- 从 pdfjs-dist 选取 legacy 浏览器库、匹配的 Worker、CMaps、standard_fonts、WASM 及现有必要许可证；主库与 Worker 来自同一安装版本。保留按需加载，不把 PDF 或办公预览库纳入首页首屏 chunk。
- 从 docx-preview 和 JSZip 复制现有浏览器构建；从 xlsx 官方包复制浏览器完整构建。保持 DOCX、表格大小限制、禁用能力和 Worker 解析行为。
- 将项目维护的表格 Worker 和说明从生成目录迁回前端源工程，由资源准备模块一同输出；不把项目适配器误当作第三方原文件。
- 构建输出在 `tmp/frontend-dist/vendor/`，由同步脚本写入 `web/vendor/`；HTML 仍写入 `web/*.html`，普通 Vite 资源仍写入 `web/_frontend/`。dev 服务直接提供同一份生成资源，避免代理到可能过期的 Go vendor 文件。
- 扩展现有同步事务：HTML、`_frontend` 与 `vendor` 一起预检、暂存、替换和失败恢复；新增/修改/删除全部纳入 check-assets。暂存不进入内嵌目录，源目录不被清空。
- 生成一份精简的第三方来源/许可说明，版本与来源从安装包及 lockfile 派生，不手工重复维护逐文件 SHA。只复制选定资源及许可证，不公开整个安装包。

### 收敛现有校验

- 用 npm ci 的包完整性校验管理下载结果，用完整产物重建比较检查被提交的 JS、Worker、字体、WASM 和许可证是否一致。二者职责不同，均保留。[npm lockfile 说明](https://docs.npmjs.com/cli/v11/configuring-npm/package-lock-json/)
- 删除 `scripts/vendor_assets.py`、对应 Python 测试和手工 `frontend/vendor-manifest.json`，替换为上述生成逻辑及 node:test 用例。更新 check-vendor 入口为 JS 资源检查或合并到 check-assets，保持日常命令易理解。
- npm audit 与上游安全公告检查继续保留，但不承诺 audit 对 URL tarball 和所有漏洞覆盖完整，也不把 lockfile 当作无漏洞证明。
- 浏览器测试从 npm 包导入 JSZip，不再 require 生成目录中的 min.js；包更新以修改依赖并重建完整产物为入口，不另保留自建 tarball 更新命令。

## Python 脚本迁移方案

新建工具脚本放在现有根目录 `scripts/`，使用 `.mjs`；依赖需要从 `frontend/package.json` 明确安装和解析。只按实际共用需求提取版本/进程/锁模块，不创建通用脚本框架。

| 当前脚本 | 计划变更 | 必须保留的行为 |
| --- | --- | --- |
| `vendor_assets.py` | 删除，由前端资源生成及产物检查替代 | 完整资源、许可、来源与篡改/遗漏检测 |
| `ci_release_version.py` | 迁为无需第三方依赖的 `.mjs` | 读取已提交 VERSION；tag 必须严格等于 `v<VERSION>`；不递增版本 |
| `package_zip.py` | 迁为 `.mjs`，使用安装的 JSZip | UTF-8 中文路径、POSIX ZIP 内路径、排序与压缩、目录根名和更新包布局；以现有解包器及发布包测试确认兼容，不要求不同压缩器输出逐字节相同 |
| `build_release.py` | 在专门的锁/进程验证通过后迁为 `.mjs` | 当前版本或显式版本、失败不写 VERSION、全部制品存在后同目录原子替换版本文件、并发互斥、make -n/-q/-t 无写入 |
| `publish_release.py` | 复用已验证的 JS 版本/锁边界后迁为 `.mjs` | main/干净工作区、原有交互确认、前后 HEAD 验证、仅提交 VERSION、明确 refs 的原子推送；失败保留本地提交/tag，输出可重试命令，不擅自递增重试 |
| 三组发布/版本 Python 测试 | 逐项映射到 node:test 后删除 | 临时仓库与本地 bare remote；包括拒绝推送、取消、并发改动和失败路径；不访问真实远端 |

### 发布编排的专项限制

当前 Python 构建使用 Unix flock / Windows msvcrt 锁，并把 Make jobserver 文件描述符传给子进程。Node.js 标准库没有可直接替换这两类 OS 锁的统一 API，默认 stdio 配置也不能假定会继承额外描述符。[Node 文件系统 API](https://nodejs.org/docs/latest-v24.x/api/fs.html)、[Node 子进程 API](https://nodejs.org/api/child_process.html)

迁移时采用以下明确边界：

- JS 文件系统排他锁可实现构建/发布互斥，但不能宣称与原 OS 锁在崩溃释放上完全相同。本版优先采用排他创建锁目录和拥有者信息的保守策略，正常退出/可处理信号释放；不因超时自动抢占仍在执行的发布。
- 未能证明拥有者已退出时拒绝构建并报告锁路径。崩溃遗留锁的恢复必须有明确诊断与文档，避免自动删锁导致双重发布；这属于相对原 OS 自动释放机制的运维差异，实施时在 progress 明确记录。
- 专项验证必须先覆盖并发、正常释放、强制终止、遗留锁和 PID 复用/信息不完整的拒绝行为。若用户要求逐项保持原 OS 自动释放语义，则该纯标准库方案不满足要求，需保留原锁实现或另选并验证平台锁能力，不能用降低安全性完成迁移。
- MAKEFLAGS 的预览模式在任何写操作前识别；make -j 的 jobserver FD/FIFO 按实际形式处理并验证，不通过简单丢弃 MAKEFLAGS 隐藏问题。Node 子进程使用参数数组，覆盖空格/中文路径、退出码、信号及 Windows npm.cmd 调用。
- build/publish 先使用无需 npm 依赖的 Node 标准库，避免还没安装依赖就需要第三方锁库的启动循环。ZIP 依赖在 frontend-release 的 npm ci 成功后才使用。
- 只有行为测试通过后删除相应 Python 入口。若专项验证未通过，保留旧入口并标记该阶段未完成；不把“能用 JS 写出来”记作等价迁移已验收。

## 构建、CI 与兼容约束

- 保留单 Go module、单进程、单二进制；普通 `go run .`、`go build .` 和 Docker 直接构建使用已提交资源，无 Node/npm/Python 运行依赖。
- 重建前端及 release 开发流程需要固定 Node/npm。迁移完成后删除这些路径对 Python 的依赖，但仍保留 Go、Git、Make/tar 和 Windows 原生签名工具各自职责。
- 更新 Makefile、Windows 发布脚本、CI、开发和发布文档。CI metadata 阶段在执行 JS 版本检查前安装固定 Node；测试入口切换为 node:test。Go-only 检查仍可单独执行。
- `make test`、`make build`、`make publish` 的外部入口保留；工具依赖的首次安装步骤在文档中明确，不能因根脚本解析不到 frontend/node_modules 而只在某个 cwd 可用。
- 公共页面 URL、API、预览安全头、文件/文本持久化、更新清单与签名身份不变；保留 v0.5.1 hash、重验证和旧 chunk 恢复方案。
- 本轮制定计划不修改 VERSION、lockfile 或已生成的 web；正式实现完成时统一更新版本元数据。

## 实施阶段与退出条件

### 一：npm 接管依赖与资源来源

在隔离环境精确安装四个库，确认浏览器构建及附属资源/许可的路径，锁定依赖并实现 JS 资源准备。

**验收：** 固定工具链下干净安装通过；三平台安装行为及 PDF.js 可选依赖影响有记录；复制内容与现有版本逐项比对；不需要 Python 下载/解包脚本。SheetJS 包由官方 URL 安装并记录 integrity。

### 二：整合构建、开发与产物检查

把 vendor 生成纳入 Vite 与同步事务，迁移项目 Worker/说明源，更新测试的 JSZip 导入，再移除旧清单/下载器。

**验收：** dev 和真实 Go 内嵌服务均可同源加载预览；完整重建可复现，资源增删及生成失败/同步失败回滚有测试；离线启动、PDF Worker/CMaps/字体/WASM、DOCX、XLS/XLSX 全部保持可用，无许可证遗漏或首屏加载回退。

### 三：迁移低耦合 Python 工具

迁移 CI 版本检查、ZIP 打包及相应行为测试；更新调用方安装顺序和依赖解析。

**验收：** node:test 覆盖版本校验、中文路径、包内布局与打包错误；生成的 ZIP 通过现有 Go 解包及更新验签；在 Windows/Linux/macOS 验证工具入口，不依赖 Python。

### 四：迁移构建与发布编排

先完成锁、Make jobserver 与异常退出的隔离验证，再迁移 build/publish 和余下测试。保留原发布确认与恢复行为；接受的锁恢复差异有明确记录。

**验收：** 并行/崩溃/预览/构建失败不破坏版本和制品；临时 Git 仓库验证精确提交、原子推送及失败重试。只访问测试 remote，不执行真实发布。未通过的部分保留原实现，不标为完成。

### 五：完整回归与文档收尾

更新 CI 和所有调用入口，重新生成并提交资源；核对活动构建/测试流程中的 Python 引用，历史版本文档保留当时记录。

**验收：** 类型检查、JS 测试、产物一致性、Go test/vet/race、三浏览器真实服务、A/B 升级恢复、Docker 与测试签名包校验通过。平台运行与编译分别记录，既有未验证矩阵不自动关闭。未解决的 Python 依赖及其原因列入 progress。

## 本版完成标准

- 预览库版本与完整性由 npm/lockfile 管理，第三方静态资源自动生成，删除自建 vendor 下载和逐文件摘要维护流程。
- JS 成为本版新增及迁移脚本的默认语言；已替代的 Python 实现与测试删除，调用方和工具链要求一致。
- 发布锁恢复策略及已知差异被明确验证和记录；若该阶段不能满足约定边界，诚实保留未完成状态，不能据此宣称已彻底移除 Python。
- 原有 API、离线单二进制运行、预览行为和更新校验保持；开发依赖不进入公开静态目录或运行环境。

## 无法直接满足的要求

1. **所有库均从公共 npm registry 安装且保持现有版本：不成立。** SheetJS registry 没有 0.20.3；官方 tarball 仍能作为 npm 依赖管理。
2. **npm 接管后完全不需要资源处理脚本：不成立。** Worker、WASM、CMaps、字体、许可和 Go 内嵌目录仍需生成与验证。
3. **纯 Node 标准库无差别替代 OS advisory 锁、原生签名或 Go 编译：不能这样承诺。** 可用 JS 编排这些流程；锁恢复需明确设计与专项验证，签名与编译继续调用相应工具。
4. **仅 npm audit/lockfile 即可保证所有依赖安全、全新离线安装或所有平台正确：不成立。** 保留上游公告、完整产物与实际运行验证；安装网络与平台工具条件仍需满足。
