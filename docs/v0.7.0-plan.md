# Lan Copy v0.7.0 发票 OCR 与本地服务管理计划

制定日期：2026-11-17。状态：**待确认，尚未修改源代码**。

## 背景与目标

Lan Copy 的共享空间已经保存用户的发票文件（PDF、JPG、PNG），但只能浏览、预览、下载和打印，不能理解发票内容。

本版目标是打通“共享文件”和“发票识别”，并把 OCR 做成独立、可替换的本地容器服务：

- OCR 服务构建为独立轻量镜像，不内置到 Go 单二进制。
- Lan Copy 新增受控的本地服务管理能力，通过 Docker 拉起 OCR 镜像。
- 提供界面和接口上传插件服务镜像、启动/停止/查看状态和日志。
- Go 主服务通过 HTTP 调用 OCR 服务。
- 发票文件仍在共享空间，文件是事实来源，识别结果是派生数据。
- Docker、OCR 镜像或模型不可用时，Lan Copy 现有文件共享、碎片快传、打印、更新功能不受影响。

## 当前状态与新增面

当前 `lan-copy` 没有 Docker、容器、镜像或插件服务管理实现，也没有数据库和通用任务队列。因此本版需要新增：

1. `internal/containers`：Docker/Podman CLI 适配层。
2. `internal/servicehost`：受控的本地服务生命周期、清单、状态和健康检查。
3. `ocr-worker`：独立 OCR 镜像。
4. `internal/invoice`、`internal/ocrclient`、`internal/invoicestore`：发票业务。
5. 服务管理和发票页面。

这是一次明确的架构扩展，不是对现有文件共享逻辑的重构。

### 核心边界

1. **文件是主数据。** 共享目录仍由 `filestore` 独占管理。
2. **发票记录是派生数据。** 存在应用私有数据目录，不写入共享目录。
3. **容器服务是独立进程。** Lan Copy 不把 Python 运行时打进 Go 二进制。
4. **服务管理器只管理本机容器。** 不是通用编排平台，不接 Kubernetes、不接远程 Docker。
5. **HTTP 是唯一调用方式。** OCR 容器不挂载共享目录，不直接读用户文件。
6. **业务集成是显式的。** 通用服务管理只负责运行容器；只有 OCR 有发票业务协议，其他镜像不会自动“变成”发票能力。

## 本地服务管理设计

### 范围

服务管理器负责：

- 检测本机 Docker 是否可用。
- 从镜像引用拉取，或从上传的 `docker save` tar 加载镜像。
- 读取镜像内嵌的服务清单。
- 创建、启动、停止、重启、删除容器。
- 分配本机回环端口，检查健康状态，读取有限日志。
- 保存期望状态，应用重启后恢复/接管容器。

不负责：

- 远程 Docker、Kubernetes、Swarm。
- 任意 `docker run` 参数透传。
- 宿主机目录挂载、host 网络、privileged、设备直通。
- 任意脚本执行、镜像内代码审计。
- 在局域网暴露服务管理接口。

### 运行时适配

新增 `internal/containers`，优先使用 Docker CLI：

```go
type Runtime interface {
    Available(ctx context.Context) (RuntimeInfo, error)
    LoadImage(ctx context.Context, tarPath string) (ImageInfo, error)
    PullImage(ctx context.Context, reference string) (ImageInfo, error)
    InspectImage(ctx context.Context, reference string) (ImageInfo, error)
    Create(ctx context.Context, spec ContainerSpec) (ContainerInfo, error)
    Start(ctx context.Context, id string) error
    Stop(ctx context.Context, id string) error
    Remove(ctx context.Context, id string, removeImage bool) error
    Inspect(ctx context.Context, id string) (ContainerInfo, error)
    Logs(ctx context.Context, id string, tail int) (string, error)
    ListManaged(ctx context.Context, label string) ([]ContainerInfo, error)
}
```

实现要点：

- 通过 `exec.CommandContext` 调用 `docker`，设置超时和取消。
- 解析 `docker inspect` JSON，不解析人类可读输出。
- Windows/macOS 使用 Docker Desktop 的 `docker` CLI；Linux 使用 Docker Engine。
- Podman 只作为兼容候选，不在首期承诺。
- Docker 不可用时返回明确状态，不自动安装 Docker。

### 服务清单

镜像通过 label 携带服务清单，避免另外上传一份可被篡改的 manifest：

```text
io.lan-copy.service = {"schemaVersion":1,"id":"ocr",...}
```

示例：

```json
{
  "schemaVersion": 1,
  "id": "ocr",
  "name": "发票 OCR",
  "version": "0.1.0",
  "containerPort": 8765,
  "healthPath": "/health",
  "startupTimeoutSeconds": 90,
  "memoryMB": 1024,
  "cpus": 1.0,
  "env": {
    "OCR_MODEL_DIR": "/app/models"
  }
}
```

校验规则：

- `id`：小写字母、数字、连字符，1–32 字符，全局唯一。
- `version`：非空，建议 semver。
- `containerPort`：1024–65535。
- `healthPath`：以 `/` 开头，不允许 `..`、查询串和片段。
- `memoryMB`：128–4096。
- `cpus`：0.1–4.0。
- `env`：键名 `[A-Z][A-Z0-9_]{0,63}`，值不超过 1024 字符，不允许换行。
- 不接受 `command`、`entrypoint`、`volumes`、`networkMode`、`privileged`、`devices`、`ports` 等任意 Docker 参数。
- 镜像必须定义非 root `USER`，否则拒绝安装。
- 清单缺失或非法时拒绝安装，不猜测。

### 容器创建参数

服务管理器固定构造安全参数，不允许调用方透传：

```text
docker run -d
  --name lan-copy-svc-<id>
  --label io.lan-copy.managed=true
  --label io.lan-copy.service.id=<id>
  --label io.lan-copy.service.version=<version>
  --publish 127.0.0.1::<containerPort>
  --memory <memoryMB>m
  --cpus <cpus>
  --pids-limit 256
  --read-only
  --tmpfs /tmp:rw,noexec,nosuid,size=256m
  --security-opt no-new-privileges
  --cap-drop ALL
  --init
  --log-driver json-file
  --log-opt max-size=10m
  --log-opt max-file=2
  <image>
```

约束：

- 只绑定 `127.0.0.1`，不绑定 `0.0.0.0`。
- 不挂载宿主机目录；插件只能通过 HTTP 接收数据。
- 不使用 host 网络、privileged、额外 capabilities。
- 只读根文件系统，临时写入走 tmpfs。
- 容器名和标签由服务管理器生成，不使用用户输入作为路径。
- 端口由 Docker 随机分配，启动后通过 `docker inspect` 读取实际宿主端口。

### 生命周期与状态

服务状态：

```text
not_installed → installing → installed → starting → running
                                      ↘ unhealthy
                                      ↘ failed
running → stopping → stopped
```

- 期望状态保存在应用私有数据目录的 `services.json`。
- 容器真实状态以 `docker inspect` 为准；启动时按标签接管已存在容器。
- 应用启动后异步恢复服务，不阻塞 HTTP 服务启动。
- 默认：应用退出时停止由其管理的容器；进程崩溃时容器可能残留，下次启动接管。
- 健康检查：HTTP GET 容器回环端口 + `healthPath`，带启动超时。
- 日志：`docker logs --tail N`，仅本机接口可读，限制返回大小。
- 镜像更新：先加载新镜像，再停止/删除旧容器，创建新容器；失败时保留旧记录和日志。

### 镜像安装

支持两种方式：

1. **镜像引用**：`POST /api/services/pull` `{ "image": "registry/..." }`，异步 `docker pull`。
2. **上传 tar**：`POST /api/services/images`，multipart 字段 `image`，限制大小，流式写入私有临时文件，计算 SHA256，异步 `docker load`。

上传流程：

```text
浏览器上传 tar
  → 写入 <dataDir>/services/images/<random>.tar
  → 校验大小/SHA256
  → docker load
  → docker image inspect
  → 读取 io.lan-copy.service 清单
  → 返回预览：名称、版本、端口、健康路径、镜像大小、架构
  → 用户确认安装
  → 创建容器
```

不在上传完成后自动运行镜像。必须经过“预览清单 + 显式确认”。

限制：

- 单镜像 tar 默认上限 2 GiB，可配置。
- 上传与 `docker load` 都使用异步任务，返回 job ID。
- 临时文件任务结束清理；失败也清理。
- 校验镜像架构与宿主机 Docker 架构一致，不一致拒绝。
- 记录镜像引用、digest、大小、架构、上传时间，不记录用户原始文件名作为路径。

### 服务管理界面

新增“服务”设置页签或独立页面，建议放在设置中，避免改变主导航：

- Docker 状态：未安装、不可用、版本、平台。
- 服务列表：OCR 服务卡片，显示镜像、版本、状态、端口、内存/CPU 限制。
- 操作：安装、启动、停止、重启、删除、查看日志。
- 镜像安装：上传 tar 或填写镜像引用；上传后先展示清单预览，再确认。
- 安全提示：明确说明“镜像会在本机以容器方式运行，仅安装可信镜像；服务管理仅本机可用”。
- 资源与端口：显示实际宿主端口和健康地址，不显示宿主机绝对路径。

发票页只展示 OCR 服务状态和“启动服务”快捷操作，不重复完整服务管理界面。

## OCR 镜像

### 镜像内容

```text
ocr-worker/
  pyproject.toml
  uv.lock
  Dockerfile
  .dockerignore
  app/
    main.py
    config.py
    schemas.py
    engine.py
    pdf.py
    image.py
    preprocess.py
    document.py
  scripts/download_models.py
  models/            # 构建时下载，不提交权重
  tests/
```

### Dockerfile 原则

- 多阶段构建：构建阶段用 `uv sync --frozen --no-dev`，运行阶段只复制虚拟环境和应用。
- 基础镜像使用 `python:3.12-slim`，CPU-only ONNX Runtime，不引入 PaddlePaddle、CUDA、Torch。
- 运行阶段不安装 `pip` 依赖，不保留构建缓存。
- 模型在构建阶段下载并校验 SHA256；镜像内包含 v5 模型，离线可用。
- 删除 RapidOCR wheel 自带的 PP-OCRv6 默认模型和方向分类模型，避免无谓体积和误加载。
- 非 root 用户运行，`PYTHONDONTWRITEBYTECODE=1`，只写 `/tmp`。
- `EXPOSE 8765`，`CMD` 使用 `uvicorn --host 0.0.0.0 --port 8765 --workers 1`。容器内监听 `0.0.0.0` 是必要的，宿主只发布到 `127.0.0.1`。
- 镜像 label 写入服务清单。
- 提供 `HEALTHCHECK`，但 Lan Copy 仍以自己的 HTTP 健康检查为准。

### 模型

- `PP-OCRv5_mobile_det.onnx`：4,819,576 字节
- `PP-OCRv5_mobile_rec.onnx`：16,631,306 字节
- 合计 21,450,882 字节（20.46 MiB / 21.45 MB）
- 来源：ModelScope `RapidAI/RapidOCR` `v3.10.0`
- SHA256：
  - det `4d97c44a20d30a81aad087d6a396b08f786c4635742afc391f6621f5c6ae78ae`
  - rec `5825fc7ebf84ae7a412be049820b4d86d77620f204a041697b0494669b1742c5`
- 显式配置 PP-OCRv5 + Mobile + ONNX Runtime。
- 不默认加载方向分类模型；旋转首期通过 EXIF 和 PDF `/Rotate` 处理。
- 模型总大小超过 20MB 目标，保留 v5，不静默替换 v4、不裁剪。

### 镜像体积口径

“轻量”指相对完整 PaddleOCR/CUDA 方案，不承诺镜像只有几十 MB。

- 模型权重：21.45 MB。
- Python 依赖：当前最新组合实测约 441 MB；镜像中固定版本、删除 wheel 自带 v6 模型、去掉测试和缓存后重新统计。
- 最终镜像：构建后如实记录压缩/未压缩大小，不用依赖体积冒充镜像体积。
- 多架构：提供 `linux/amd64` 和 `linux/arm64` 构建脚本；上传前校验架构。

### OCR API

与之前设计一致，容器内提供：

- `POST /internal/ocr/v1/recognize`
- `GET /health`
- `GET /version`

返回页、文字块、坐标、置信度和来源。原生文字置信度为 `null`，不伪造。

PDF 策略：

1. PyMuPDF 提取原生文字层和坐标。
2. 逐页判断文字层可用性：有效字符、乱码比例、关键区域、是否几乎只有图片、坐标异常。
3. 可用返回 `native_text`；不可用按 200 DPI 渲染后 OCR。
4. 支持多页、`page`、`force_ocr`。
5. 限制文件大小、页数、渲染像素、块数、输出大小。
6. 加密/损坏/非白名单格式返回明确错误。

## 发票领域

### 文件与记录关联

```go
type SourceRef struct {
    Kind    string    // shared_file | upload
    Path    string    // 共享目录内相对路径
    Name    string
    MIME    string
    Size    int64
    ModTime time.Time
    SHA256  string
    Snapshot bool
}
```

- 识别前从 `filestore` 取稳定快照，复制到私有临时目录。
- Worker 只接收快照字节，不接触共享目录。
- 文件修改 → `stale`；文件删除 → `source_missing`；不静默错配。
- 删除发票记录不删除共享文件；删除共享文件不自动删除记录。
- 首期不自动跟随移动/重命名，后续可增加“重新关联”。

### 发票模型

保留任务要求的字段，增加字段级元数据：

- `invoice_type`
- `invoice_code`（可为 null）
- `invoice_number`
- `invoice_date`
- `buyer` / `seller`（name、tax_number）
- `amount_without_tax` / `tax_amount` / `total_amount`
- `amount_in_words`
- `remarks`
- `items`
- `validation`
- `fields`：状态、方法、OCR 置信度、Parser 置信度、block IDs、原始文字
- `raw_ocr`、`original`、`current`、`status`、`revision`

字段状态：`recognized`、`unrecognized`、`empty`、`not_applicable`、`invalid`、`ambiguous`、`manual`。

金额：

- `Money` 内部为 `int64` 分，JSON 输出字符串。
- 禁止 float 参与计算。
- 校验不含税金额 + 税额 ≈ 价税合计，默认容差 1 分。
- 发票代码、号码、税号使用字符串，保留前导零。

### 持久化

```text
<dataDir>/invoices/
  index.json
  index.backup
  records/<id>.json
  raw/<id>.json
  files/<id>.<ext>      # 仅直接上传
  tmp/                  # 快照，启动/任务结束清理
```

- JSON + 临时文件 + fsync + rename + 备份。
- 启动恢复索引，损坏时从 records 重建。
- 目录 0700，文件 0600。
- 限制单条 raw、总记录数、总字节数；超限明确报错，不静默淘汰。
- 无数据库、无 Redis。

### 任务队列

- Go 内存有界队列，默认 1 并发、16 排队、120 秒超时。
- 同一文件指纹 + 参数复用已有任务。
- 队列满返回 429。
- 应用关停时停止接收、取消运行、清理临时快照。
- OCR 服务未运行时，按配置尝试启动并等待健康；超时则任务失败，UI 提示。

## 文件与发票打通

### 文件浏览器

- PDF、JPG、JPEG、PNG 增加“识别发票/查看发票”右键动作。
- 支持多选批量识别。
- 文件行显示状态徽标：识别中、已识别、需复核、失败、源文件已变更/不存在。
- 点击徽标打开发票详情。
- 仅本机请求返回发票状态；局域网请求看不到识别结果。
- 不自动识别，必须用户显式触发。

### 发票页

- 顶栏打印图标旁增加“发票识别”图标，不改变现有文字导航。
- 列表：源文件、类型、号码、日期、销售方、价税合计、校验状态。
- 详情：原始文件预览、字段编辑、字段来源与置信度、原始 OCR、校验提示。
- 操作：保存、重新解析、删除、重新识别。
- OCR 服务状态卡：未安装/未启动/启动中/就绪/失败，提供启动和安装入口。
- 识别中轮询任务；列表通过 SSE `invoices` 事件刷新。

### 文件列表摘要

- `/api/files`、`/api/filesystem` 对本机请求附加可选 `invoice` 摘要。
- 非本机不返回，避免泄露结构化发票信息。
- 新增 SSE `invoices` 标记，向后兼容。

| GET | `/api/invoices/jobs/{id}` | 任务状态 |
| GET | `/api/ocr/health` | OCR 服务状态 |

## 安全与隐私

1. 服务管理 API 和发票 API 默认仅本机。
2. 服务管理默认关闭，需本机用户在设置中显式启用并确认风险。
3. Docker socket 等价于较高系统权限；Lan Copy 不把它暴露给局域网。
4. 上传镜像 = 运行本机代码；必须显式确认，仅接受可信镜像。
5. 固定容器参数：无 privileged、无 host 网络、无宿主机挂载、只读根文件系统、非 root、资源限制、回环端口。
6. 镜像清单只允许受控字段，不允许透传任意 Docker 参数。
7. Worker 容器不挂载共享目录；Go 只通过 HTTP 发送快照。
8. 发票记录在私有数据目录；不写入共享目录。
9. 日志不记录发票正文、名称、税号、金额；服务日志限制条数和大小。
10. 上传 tar 使用随机临时名、大小限制、SHA256、任务结束清理。
11. 现有文件共享、预览、下载的局域网行为保持不变。

## 失败与降级

| 场景 | 行为 |
| --- | --- |
| Docker 未安装/不可用 | 服务页显示安装提示；发票功能禁用；文件共享正常 |
| 服务管理未启用 | 发票页提示启用；不自动操作 Docker |
| 镜像未安装 | 提示上传/拉取镜像 |
| 镜像清单缺失/非法 | 拒绝安装，显示原因 |
| 容器启动失败 | 状态 failed，保留日志；可重试 |
| 健康检查失败 | 状态 unhealthy；识别任务失败 |
| OCR 超时 | 任务失败，清理快照 |
| 队列已满 | 429 |
| 源文件不存在/变更 | 404 或 stale 提示 |
| 服务崩溃 | 状态 failed；可重启；已保存记录不受影响 |
| 应用重启 | 接管已存在容器；未完成任务丢失；记录保留 |
| 应用退出 | 默认停止托管容器；崩溃残留下次接管 |
| 架构不匹配 | 拒绝安装镜像 |
| 端口分配失败 | 创建失败，显示 Docker 错误 |

## 完成标准

- 现有 API、存储格式、恢复语义和单二进制发布保持兼容。
