# Lan Copy v0.5.18 计划：移除过期兼容入口

制定日期：2026-11-17。状态：**待确认，尚未修改源代码**。

## 背景与目标

v0.5.17 把“文本快传”改造成“碎片快传”，为了不破坏旧链接和旧调用方，保留了若干兼容入口和重复字段。功能已经稳定，当前前端和脚本都不再使用这些入口，实际只剩测试在覆盖。继续保留会让 API 面同时存在两套写法，增加后续修改和文档维护成本。

本版目标是删除这些无调用方的兼容入口，收缩协议面；不改存储格式、不改恢复语义、不改当前正式 URL 和前端行为。

## 审计结论

逐个检查了路由、handler、前端、脚本和文档中的引用：

| 入口 | 当前位置 | 仓库内调用方 | 结论 |
| --- | --- | --- | --- |
| `POST /api/texts/images` | `routes.go`、`text.go`、`textstore.CreateImage` | 仅 `fragment_test.go` 的 `imageUploadRequest` | 删除 |
| `GET /api/texts/{id}/image` | `routes.go`、`text.go` 的 `serveFragmentImage` | 仅 `fragment_test.go` | 删除 |
| `GET /api/texts` 响应中的 `fragments` 字段 | `text.go` 的 `listTexts` | 无；前端只读 `texts` | 删除 |
| `GET /filesystem.html` 重定向 | `routes.go` | 仅 `filesystem_test.go` | 删除 |
| `GET /transfer.html` 308 重定向 | `routes.go`、`vite.config.ts` 插件、两组测试 | 仅测试 | 删除重定向（见下） |
| `POST /api/texts` JSON 纯文字 | `routes.go`、`text.go` | `FragmentTransfer.vue` 正在使用 | 保留 |
| `GET /api/texts/{id}/images/{index}` | `routes.go`、`text.go` | `FragmentTransfer.vue` 正在使用 | 保留 |
| `POST /api/texts/fragments` | `routes.go`、`text.go` | `FragmentTransfer.vue` 正在使用 | 保留 |
| 旧数据迁移（`textstore.FileName`、`BackupFileName`、应用数据目录迁移） | `app/storage.go`、`textstore` | 启动恢复路径 | 保留，属于升级能力而非入口 |

`textstore.Store.CreateImage` 只被 `uploadFragmentImage` 使用（单元测试也有调用），因此随端点一并删除；`CreateFragment` 的图片处理、`OpenImageAt`、`fragmentImage*` 等继续保留。

## 删除清单

### 1. `POST /api/texts/images`

- 删除 `internal/httpserver/routes.go` 中的路由。
- 删除 `internal/httpserver/text.go` 的 `uploadFragmentImage`。
- 删除 `internal/textstore/store.go` 的 `CreateImage`。
- 当前 UI 通过 `POST /api/texts/fragments` 的 `images` 字段一次提交图片，不受影响。
- 图片校验、数量上限、存储上限仍由 `CreateFragment` 覆盖。

### 2. `GET /api/texts/{id}/image`

- 删除路由和 `text.go` 中只读第一张图片的 `serveFragmentImage` 包装。
- 保留 `serveFragmentImageAt` 与 `GET /api/texts/{id}/images/{index}`，后者是当前 UI 使用的正式入口。
- 测试改用 `/images/0` 验证同样的 Content-Type、CSP 和安全头。

### 3. `GET /api/texts` 的 `fragments` 重复字段

- `listTexts` 只返回 `{"texts": ...}`，删除同值的 `fragments` 键。
- 前端 `FragmentTransfer.vue` 只解构 `texts`，无需改动。

### 4. `GET /filesystem.html` 重定向

- 删除 `routes.go` 中的 307 跳转 handler。
- 删除 `filesystem_test.go` 的对应断言。
- 从 `frontend/vite.config.ts` 的开发代理前缀列表移除 `/filesystem.html`。
- 删除后该路径由静态文件服务器处理并返回 404；这是有意废弃旧书签入口。

### 5. `GET /transfer.html` 的 308 重定向

这里需要区分“跳转逻辑”和“页面骨架文件”：

- `web/transfer.html` 仍然是 `/transfer-text` 的服务端 HTML 骨架（Go 路由把 `/transfer-text` 内部映射到该文件），文件本身不能删，否则 `/transfer-text` 丢失首屏骨架。
- 因此删除的是重定向行为，而不是文件。

**采用方案 A（推荐）**：删除 Go 的 308 handler 和 Vite 插件的跳转分支。删除后 `/transfer.html` 由静态文件服务器直接返回同一页面（200），不再跳转。仓库内不再有 HTTP 跳转逻辑。

注意：`App.vue` 当前按 `location.pathname` 决定渲染哪个页面，只识别 `/transfer-text`。若不同步把 `/transfer.html` 识别为碎片快传页，直接访问该文件路径时 Vue 挂载后会显示内网空间。因此实施时在 `currentPage()` 中把 `/transfer.html` 计入 transfer，并补一条 `App.test.ts` 用例；这是路径到页面的映射，不是兼容跳转。

相关同步改动：

- `frontend/vite.config.ts` 的 `text-transfer-route` 插件删除 `/transfer.html` 分支，保留 `/transfer-text` 和 `/print-queue` 的内部重写。
- `internal/httpserver/filesystem_test.go` 删除 308/307 断言，保留页面可访问与初始骨架断言。
- `frontend/scripts/routes.test.mjs` 改为断言 `/transfer.html` 返回 200 的页面内容，或删除旧链接用例。
- `frontend/scripts/browser-test.mjs` 删除 `redirect: 'manual'` 的 308 断言，保留从 `/transfer.html` 进入后能看到碎片快传页面的回归。

7. 检查 `README.md`、`README.en.md` 是否有旧入口描述，有则同步。

## 风险与回滚

- 外部若有第三方脚本仍调用被删端点，会开始收到 404。仓库内没有此类调用方；如确实存在外部依赖，需在本版发布说明中标注。
- 旧 `/filesystem.html` 书签将 404，属于本次明确要求。
- 回滚只需还原本次提交的 Go 路由、handler 和测试；不涉及数据格式，已保存的文件和碎片不受影响。

## 不包含

- 不把 `/api/texts` 重命名为 `/api/fragments`。这是整个 API 命名迁移，涉及前端、测试和文档，需单独版本处理。
- 不删除 `textstore` 的旧数据迁移逻辑。
- 不删除 `/transfer-text`、`/print-queue` 等当前正式 URL。
- 不处理 `web/logo/` 中未被 HTML 引用的备用品牌资源。
- 不触碰当前未跟踪的 `docs/v0.7.0-*.md` 计划文档。
