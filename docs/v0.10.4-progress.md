# Lan Copy v0.10.4 进度

## 已完成

| 模块 | 结果 |
| --- | --- |
| 版本模型 | 统一接受 `x.y.z` 与 `x.y.z-build{c}`；无后缀按 `build0` 比较；构建号从 1 开始，基础版本升级后重置为 `-build1` |
| `build_release.py` | `make build` 成功后构建号 `+1`；显式基础版本升级归零；显式完整版本原样使用；降低版本报错；失败和预览不落盘 |
| `publish_release.py` | 默认在同一基础版本上递增构建号；支持新基础版本与显式完整版本；发布版本必须严格递增；标签使用完整版本 |
| CI | `ci_release_version.py` 接受完整版本，标签必须严格等于 `v` + 已提交 `VERSION`，分支和标签构建都不递增 |
| Node 入口 | `release-local.mjs`、`deploy-target.mjs` 接受并透传 `x.y.z-build{c}` |
| 在线更新 | `CompareVersions` 先比较基础版本再比较构建号；历史无后缀标签仍有效；带构建号的正式 Release 可被识别 |
| 文档 | README、README.en、UPDATING、GITHUB-ACTIONS、DEVELOPING 同步新格式与递增规则 |
| 测试 | Python、Node、Go 更新逻辑与 HTTP 更新检查覆盖构建号解析、递增、归零、比较和标签匹配 |

## 待人工验收

- 在真实发布环境执行一次 `make build`，确认 `VERSION` 从 `0.8.1` 变为 `0.8.1-build1`，再次执行变为 `-build2`。
- 执行 `make build VERSION=<更高基础版本>`，确认首次构建为 `-build1`。
- 执行 `make publish`，确认确认提示、版本提交、标签和远端推送均使用完整版本。
- 旧版本客户端检查更新时能看到更高的构建号，并能完成在线安装与重启。
