# Lan Copy v0.5.7 计划

制定日期：2026-10-29。

## 目标与方案

在项目根目录通过 Air 启动时，默认页面 `/` 显示「请通过 make frontend-dev 启动前端调试项目」，引导访问 Vite 输出的地址。普通 `go run .`、`go build .`、Docker 和发布制品继续提供内嵌前端。

新增仓库 `.air.toml`，通过运行参数 `-air-dev` 显式启用开发提示，由应用组装层传给 HTTP 配置。参数默认关闭，不依据可执行文件名、父进程或版本字符串猜测运行方式。仅替换开发模式的根页面，保留其他页面、静态资源和 API，尤其是 Vite 代理的 vendor/logo；保留单进程、单二进制、嵌入式前端和根目录入口。不修改 VERSION、前端版本或发布配置。

## npm 预览依赖与资源迁移

本节是 v0.5.7 合并后的第二项工作。当前 `VERSION` 为 0.5.6；保持版本元数据不变。四个预览库保持现有版本，由现有 `frontend/package.json` 与 lockfile 管理：`pdfjs-dist@6.4.299`、`docx-preview@0.4.1`、`jszip@3.10.2`，以及 SheetJS 官方 `xlsx-0.20.3` tarball。实施时核对包布局、许可证及 docx-preview 使用的 JSZip。

新增 Node 标准库资源生成器，从 npm 安装包生成现有 `web/vendor/` 文件树，保留 `/vendor/` URL、PDF legacy 主库和匹配 Worker、CMaps、字体、WASM、许可证、项目 README 与 SheetJS Worker。生成到临时目录并复用已有资源同步事务；删除 Python vendor 脚本、相邻测试和手工清单。预览库不进入首页 chunk，不增加根目录 npm 项目。

Vite 开发与正式构建从已安装依赖准备 vendor；开发服务直接提供 `/vendor/`，保留其他 Go API 代理。扩展资源同步和只读检查以覆盖 vendor；更新 Makefile、CI、Windows 签名脚本、浏览器样本与开发说明。普通 Go 构建继续使用已提交嵌入资源，不调用 npm 或联网。其余 Python 构建/发布脚本另行规划。

验收包括 npm ci、前端类型/测试/构建、资源一致性和损坏检测、真实 Go 服务下 Chromium/Firefox/WebKit 预览回归、Vite vendor 与 API 代理、Go 测试/构建及 Windows 交叉编译。发布打包可能修改版本元数据，应在隔离副本执行；不修改 VERSION/tag。无 Windows 签名证书时记录签名未验收。
