# Lan Copy v0.9.0 插件生命周期事件计划

更新日期：2026-11-18。状态：**已批准并完成实现（含局域网开放），自动化验证通过，待人工验收**。

## 背景与目标

v0.8 已经具备 Docker 插件镜像导入、安装、启停、健康检查、日志和统一 HTTP Client，但插件只能被动响应 Lan Copy 主动调用，无法感知共享文件夹、文本和用户操作。插件作者要实现“上传后自动识别”“删除后清理索引”“新建文件夹后触发同步”等场景，只能轮询目录或另建监听。

本版本增加一套**由 Lan Copy 主动推送的插件生命周期事件**：

1. 文件、文件夹、文本操作成功后产生结构化事件。
2. 已订阅事件的插件通过固定的 `POST /events` 接口接收，带 HMAC 签名、事件 ID 和重试。
3. `/plugins` 页面新增“生命周期”菜单，完整展示事件目录、订阅方式、签名校验、示例代码、交付状态和测试入口。
4. 保持现有 API、镜像格式和插件协议 1.x 兼容：不声明事件的插件行为完全不变。

## 非目标

- 不做事件持久化、离线补发、跨重启重放或全局事件总线。
- 不做插件之间的直接通信、注册中心或事件订阅管理后台（订阅来自镜像 Manifest）。
- 不推送插件自身的启停事件，避免启动顺序歧义和关停期阻塞；后续如需要，单独设计 `system.*` 与关停前队列排空。
- 不改变共享目录、上传事务、恢复与回滚语义。

## 事件目录（首期）

所有事件在对应操作**成功提交后**产生，失败、取消和回滚不产生事件。

| 事件 | 触发点 | 关键数据 |
| --- | --- | --- |
| `file.uploaded` | 上传事务提交成功（单文件、多文件、文件夹上传统一） | `destination`、`files[{path,size}]`、`directories[]`、`counts`，列表最多 100 项，超出用 `truncated` 标记 |
| `file.deleted` | 删除单个文件成功 | `path`、`name`、`size` |
| `file.renamed` | 文件原地重命名 | `path`、`name`、`previousPath`、`previousName` |
| `file.moved` | 文件移动到其他目录 | `path`、`name`、`previousPath`、`previousName` |
| `folder.created` | 新建文件夹 | `path`、`name`、`parent` |
| `folder.deleted` | 删除文件夹成功（支持递归删除） | `path`、`name`、`recursive` |
| `folder.renamed` | 文件夹原地重命名 | `path`、`name`、`previousPath`、`previousName` |
| `folder.moved` | 文件夹移动 | `path`、`name`、`previousPath`、`previousName` |
| `text.created` | 新建文本或图文碎片 | `text.id`、`text.kind`、`text.title`、`text.size`、`text.expiresAt` |
| `text.saved` | 碎片转存为共享文件 | `text.id`、`files[{path,name}]` |
| `text.deleted` | 删除碎片 | `text.id`、`text.kind`、`text.title` |
| `system.ping` | 仅由“发送测试事件”接口触发 | `requestedBy`、`at` |

`path` 一律是共享根目录内的相对路径，使用 `/` 分隔；不包含宿主机绝对路径、应用数据目录或插件挂载路径。

## 事件信封与传输

### 请求

```http
POST /events
Content-Type: application/json
X-Lan-Copy-Event: file.uploaded
X-Lan-Copy-Event-Id: evt-01J...
X-Lan-Copy-Timestamp: 1763435045
X-Lan-Copy-Signature: v1=<hex(hmac-sha256(timestamp + "." + body))>
```

```json
{
  "schemaVersion": 1,
  "id": "evt-01J...",
  "type": "file.uploaded",
  "occurredAt": "2026-11-18T03:04:05Z",
  "data": {
    "destination": "docs",
    "files": [{ "path": "docs/a.pdf", "size": 182344 }],
    "directories": [],
    "counts": { "files": 1, "directories": 0 },
    "truncated": false
  }
}
```

### 订阅声明

Manifest 新增两个**可选**字段，旧镜像不受影响：

```json
{
  "endpoints": {
    "health": "/health",
    "manifest": "/manifest",
    "version": "/version",
    "capabilities": "/capabilities",
    "events": "/events"
  },
  "events": ["file.uploaded", "folder.*", "text.*"]
}
```

- `events` 最多 32 项，每项为精确类型（`file.uploaded`）、域通配（`file.*`、`folder.*`、`text.*`）或全局通配 `*`。
- 未声明 `events` 或为空数组表示不订阅，不产生任何推送。
- `endpoints.events` 缺省为 `/events`，校验规则与现有端点一致。
- `capabilities` 继续只描述业务能力，事件订阅单独声明，避免语义混用。
- 插件仍需在 `/manifest` 中返回相同订阅，作为启动时的身份复核。

### 投递语义

- **尽力而为、至多一次尝试 + 有限重试**：默认 5 秒超时，最多 3 次尝试（1s、2s 退避）；网络错误、超时、`5xx`、`429` 重试，其余 `4xx` 立即丢弃。插件必须按 `id` 幂等。
- 每个插件一个 FIFO 队列（容量 128），保证同一插件的事件顺序；队列满时丢弃最旧事件并累加 `dropped`。
- 只有实例状态为 `running` 且健康为 `healthy` 时才投递；停止、启动中、不健康时直接丢弃并计入指标，不阻塞文件操作。
- 连续 5 次失败后熔断 60 秒，期间只记录不投递；恢复后自动继续。
- 事件发布在 HTTP 响应前完成“入队”，实际投递完全异步，不增加文件操作延迟。
- 关闭时停止接收新事件，已入队事件最多等待 2 秒，不延长现有退出期限。

### 鉴权

- 事件密钥由现有 `SecretBox` 的密钥和实例 ID 通过 HMAC-SHA256 派生，不写入 `state.json`；同一实例和密钥下保持稳定，实例重装或密钥更换时轮换。
- 密钥通过保留环境变量 `LAN_COPY_EVENT_TOKEN` 注入容器；不允许用户在配置中覆盖。
- 签名覆盖 `timestamp + "." + 原始请求体`，时间戳允许 ±5 分钟偏移，插件应使用常量时间比较。
- 事件接口只存在于插件专用网络或 `127.0.0.1` 随机端口，不暴露给局域网。

## 后端实现

| 文件 | 变更 |
| --- | --- |
| `internal/plugin/types.go` | `MaskInstance`；`Manifest.Events`、`ManifestEndpoints.Events` 与事件类型定义在 manifest/events 文件中 |
| `internal/plugin/manifest.go` | 订阅类型、去重、数量、通配符和端点校验；归一化默认 `/events` |
| `internal/plugin/events.go` | 事件信封、HMAC、订阅匹配、每插件队列、重试/退避、熔断、投递记录与统计、`Publish` 非阻塞入口 |
| `internal/plugin/lifecycle.go` | 安装时生成密钥、注入 `LAN_COPY_EVENT_TOKEN`、启动后按订阅投递、重装轮换密钥 |
| `internal/plugin/manager.go` | 事件调度器初始化/关闭、实例健康与订阅查询、投递记录读取、测试事件 |
| `internal/plugin/store.go`、`secrets.go` | 从 `SecretBox` 密钥派生每实例事件令牌，不改变插件状态格式 |
| `internal/filestore/directory.go` | `MutateDirectory` 返回 `MutationResult`（路径、名称、目标、是否目录、是否递归），保持错误语义和锁范围不变 |
| `internal/httpserver/filesystem.go` | 目录操作成功后映射并发布对应事件 |
| `internal/httpserver/upload_tree.go` | 提交成功后发布一条 `file.uploaded` 批量事件 |
| `internal/httpserver/text.go` | 新建、保存、删除碎片后发布 `text.*` |
| `internal/httpserver/plugins.go`、`routes.go` | `GET /api/plugins/{id}/events`、`POST /api/plugins/{id}/events/test`、`GET /api/plugins/event-catalog` |
| `internal/app/runtime.go` | 关停时按现有顺序停止事件接收，不改变现有 10 秒关停预算 |

新增 API：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/plugins/event-catalog` | 事件目录（类型、说明、示例数据），供页面和文档复用 |
| GET | `/api/plugins/{id}/events` | 订阅列表、事件端点、统计、最近 50 条投递记录（仅内存） |
| POST | `/api/plugins/{id}/events/test` | 入队一条 `system.ping`，返回 `202` 与事件 ID；要求本机、动作头 `plugins` |

错误约定：未安装、未运行、未订阅分别返回可区分的 404/409；测试事件在插件未运行时直接返回 409 并说明原因。

## 插件服务菜单

`/plugins` 频道新增第三个菜单“生命周期”（`plugins | images | events`）：

1. **事件目录**：按文件、文件夹、文本分组，展示事件名、触发时机、数据字段和示例 JSON。
2. **对接步骤**：声明 Manifest `events` 与 `endpoints.events`、实现 `POST /events`、校验签名、按 `id` 幂等、返回 2xx、处理重试和熔断。
3. **签名示例**：提供 Go（标准库）最小校验片段，包含 `LAN_COPY_EVENT_TOKEN`、原始请求体读取和常量时间比较。
4. **交付状态**：按已安装插件展示订阅、事件端点、已投递/失败/丢弃计数、最近投递记录和最后错误；运行中且已订阅的插件提供“发送测试事件”按钮。
5. **复制对接说明**：扩展 `buildAgentPrompt`，把事件目录、订阅字段、签名校验、幂等和测试步骤一并写入可复制的 Agent Prompt。
6. **空状态与降级**：Docker 不可用、未安装插件、未订阅事件时均有明确说明，不显示无意义操作按钮。

页面文案与 `docs/PLUGIN-PROTOCOL.md` 的事件章节保持同一事件名和字段，测试覆盖关键文案。

## 兼容性、安全与边界

- Manifest 新字段可选；`state.json` 格式不变，可向前加载旧状态，也不阻塞回滚到旧版本。
- 事件只包含共享目录相对路径和文本元数据，不包含文件内容、宿主机绝对路径、secret 或配置。
- 单个事件体上限 64 KiB；超限截断列表并设置 `truncated`，不发送半个 JSON。
- 投递失败不回滚业务操作，不影响 HTTP 状态码；只记录日志、指标和投递记录。
- 事件队列与投递记录只驻留内存，重启后清空；文档明确“不保证重启后补发”。
- 不改变现有 `/api/events` 浏览器 SSE 协议；插件事件与浏览器变更事件是两条独立通道。

## 验收标准

- 上传、新建文件夹、重命名、移动、删除、文本新建/转存/删除都产生正确事件，失败和回滚不产生。
- 声明订阅的插件能收到按顺序、带有效签名的事件；未声明订阅的插件完全不受影响。
- 插件宕机、超时、返回 5xx 时文件操作仍成功，重试、丢弃和熔断行为可观测。
- `/plugins` 的“生命周期”菜单能说明全部事件与对接方式，并可直接发送测试事件看到投递结果。
- 旧镜像、旧 `state.json`、现有 API 与浏览器 SSE 均保持兼容。
- 自动化测试、跨平台构建和前端检查全部通过，验收记录留档。

## 追加需求：插件管理开放到局域网（2026-11-18，已批准并完成）

### 目标

`/api/plugins*` 与 `/plugins` 不再限制为运行 Lan Copy 的本机可访问，局域网内能访问服务的设备都可以读取插件状态并执行管理操作。写操作继续保留动作头和同源校验。

### 变更

| 范围 | 变更 |
| --- | --- |
| `internal/httpserver/http_helpers.go` | 新增不带本机判断的 `validActionRequest`；`validLocalActionRequest` 继续用于其他仅本机设置 |
| `internal/httpserver/plugins.go` | `requirePlugins` 移除 `isLocalRequest`；写操作改用 `validActionRequest`，保留 `X-Lan-Copy-Action`、`Sec-Fetch-Site` 和 `Origin` 校验 |
| 前端 | 移除“仅限本机”的 403 降级和文案；页面说明改为“局域网内可管理”；增加“仅安装可信镜像”的安全提示 |
| 文档 | README、DEVELOPING、PLUGIN-PROTOCOL、v0.9.0 进度与验收同步说明访问范围与风险 |
| 测试 | 原先的“远程 403”改为“远程读取/写操作可通过”；补充远程写缺少动作头、跨源仍返回 403，以及带动作头且同源可通过访问门禁 |

### 安全边界

- Lan Copy 没有账号体系。开放后，任何能访问服务的局域网设备都可以安装、启动、停止、卸载插件、上传镜像、读取脱敏配置和日志、删除插件数据；动作头只是 CSRF 防护，不是身份认证。
- 容器仍以非 root、只读根、cap-drop ALL、资源限制和专用网络运行，不接受任意 Docker 参数。
- 页面和协议文档明确提示只安装可信镜像；需要更强隔离时应让 Lan Copy 仅监听本机地址（例如 `-listen 127.0.0.1:8080`）、使用防火墙或反向代理认证。
- 卸载时删除数据仍要求显式确认；配置、健康记录和日志的脱敏逻辑不变。

### 验收

- 局域网来源可以访问 `/plugins`、插件列表、详情、状态、日志、配置、镜像、任务和事件状态。
- 局域网写操作缺少动作头或跨源时仍返回 403；带动作头且同源时可以进入业务校验。
- 本机行为保持不变，其他仅本机设置（自启动、上传资源、碎片设置等）不受影响。
