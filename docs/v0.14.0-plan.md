# Lan Copy v0.14.0 智能表格列顺序与列隐藏计划

更新日期：2026-11-24。状态：**已批准并完成实现，自动化验证通过，待人工验收**。

## 背景与目标

智能表格内联视图目前始终按 CSV 物理列顺序展示全部列。列较多的台账需要反复横向滚动，也无法暂时隐藏内部字段。本版为智能表格增加两项纯展示偏好：

1. 调整列的显示顺序。
2. 隐藏/显示指定列。

偏好保存在 CSV 同目录的 `${origin-table-name}.hidden.metadata.json` 中，例如 `data/orders.csv` 对应 `data/orders.csv.hidden.metadata.json`。该文件属于 Lan Copy 内部元数据，不写入 CSV、不改变表格版本、不影响插件 API。

同时，Lan Copy 的文件列表、搜索、下载、预览、缩略图和文件操作都不再暴露这类元数据文件，避免用户误删或误打开。

## 已确认的决策

- **只改展示，不改 CSV**：列顺序与隐藏只作用于内联表格视图；CSV 物理列顺序、内容、版本号和插件查询/更新结果保持不变。
- **同目录侧车文件**：偏好写在表格同目录的 `<完整表格文件名>.hidden.metadata.json`，随共享目录一起复制/备份。
- **文件内不记录表格路径**：元数据只保存顺序和隐藏列，目录整体移动、重命名后不需要改 JSON；单文件重命名时同步移动侧车文件。
- **列定义以 CSV 为准**：新增列自动追加到末尾；已删除的列从偏好中忽略；表头大小写变化按不区分大小写匹配并保留顺序。
- **元数据文件默认隐藏**：文件名以 `.hidden.metadata.json` 结尾（不区分大小写）即视为内部元数据，不参与列表、搜索、下载、预览、缩略图、删除/移动等用户操作。
- **容忍损坏的元数据**：读取失败、JSON 无效、版本不认识时按“无偏好”处理，不阻塞表格打开；用户再次保存时覆盖为合法内容。
- **不再提供主键列选择**：页面内部优先使用名为 `id` 的列作为记录标识，没有 `id` 时使用第一列；不影响插件 API。
- **任意列都可隐藏**，包括记录标识列；新增行时临时显示记录标识列，确保可以填写主键。
- **搜索只保留全文搜索**：移除列筛选下拉与筛选值；输入后 300ms 防抖自动查询，结果单元格高亮匹配文字。
- **最小字号 12px**：项目界面文字不小于 12px（打印纸张缩略图内部装饰文字除外）。
- **并发语义**：列偏好是本地展示配置，不做版本冲突校验，最后保存者生效；不触发文件变更事件。

## 非目标

- 不重写 CSV 的物理列顺序，不新增“重排列并保存 CSV”的能力。
- 不改变智能表格 API、插件 API、版本校验、主键规则、写入语义。
- 不改变 CSV/TSV 只读预览页；列偏好只作用于“标记为智能表格”的内联视图。
- 不支持按列设置宽度、冻结列、列公式、列类型或单元格格式。
- 不把偏好保存到应用数据目录或 `table-marks.json`；本版明确要求放在共享目录。
- 不加密、不签名侧车文件；任何能访问共享目录的设备都可以修改它。
- 不做多端实时同步；另一个页面刷新或重新打开表格后看到最新偏好。

## 元数据格式

对于 `data/orders.csv`，侧车路径为：

```text
data/orders.csv.hidden.metadata.json
```

内容：

```json
{
  "version": 1,
  "order": ["id", "status", "customer", "amount"],
  "hidden": ["internal_note"]
}
```

| 字段 | 规则 |
| --- | --- |
| `version` | 固定为 `1`；无法识别时按无偏好处理 |
| `order` | 全部列的展示顺序，可包含隐藏列；CSV 中不存在的列读取时忽略 |
| `hidden` | 不展示的列名；必须存在于 CSV 表头；可以包含记录标识列 |
| 文件大小 | 最多 256 KiB；超过时按无偏好处理，保存时重写 |
| 编码 | UTF-8 JSON，末尾换行 |
| 路径长度 | 侧车路径与现有共享路径规则一致，最长不超过文件名限制 |

归一化顺序：

1. 按 `order` 中仍存在于 CSV 表头的列依次排列，重名只保留第一次。
2. 其余 CSV 列按物理顺序追加到末尾。
3. 新列自动可见；`hidden` 中不存在于 CSV 的列被丢弃。
4. `hidden` 按保存内容保留，记录标识列也可以隐藏；新增行界面会临时显示该列。
5. 返回归一化后的 `order` 与 `hidden` 给前端。

## 后端实现

### 1. `internal/tablestore/layout.go`（新增）

```go
const (
    LayoutSuffix   = ".hidden.metadata.json"
    MaxLayoutBytes = 256 << 10
)

type Layout struct {
    Version int      `json:"version"`
    Order   []string `json:"order"`
    Hidden  []string `json:"hidden"`
}

func LayoutPath(table string) string
func (s *Store) ReadLayout(name string) (Layout, error)
func (s *Store) NormalizeLayout(layout Layout, columns []string) Layout
func (s *Store) SaveLayout(ctx context.Context, name string, layout Layout) (Layout, error)
```

实现要点：

- `LayoutPath` 只在合法 CSV 路径后追加后缀，不做字符串替换。
- `ReadLayout` 通过 `filestore.SnapshotFile` 读取；文件不存在返回空偏好；任何解析/版本/大小问题都降级为空偏好，不返回错误。
- `SaveLayout` 先读取表格确认存在并取得表头，再归一化，使用原子写入保存 JSON。
- 不把偏好写入 CSV；不改变 `Table.Version`。

### 2. `internal/filestore` 增加通用原子写入与内部文件识别

`filesnapshot.go` 增加：

```go
// WriteFile 原子创建或替换共享目录内的普通文件。
func (s *Store) WriteFile(name string, data []byte) (FileSnapshot, error)
```

- 与 `CreateFile`/`UpdateFile` 使用同一把文件锁、临时文件、`fsync` 和目录同步。
- 允许目标不存在或已存在，统一走临时文件 + `os.Rename`，避免两次调用之间的竞态。
- 继续拒绝 `..`、反斜杠、符号链接、超长路径和非法组件。

新增 `internal/filestore/metadata.go`（或放入 `store.go`）：

```go
const MetadataSuffix = ".hidden.metadata.json"
func IsHiddenMetadata(name string) bool
```

- 按完整路径后缀、不区分大小写判断。
- 该判断用于所有用户可见的文件入口，不改变 `ValidateComponent`，以免影响内部读写。

### 3. 文件可见性

以下入口过滤或拒绝内部元数据：

| 入口 | 行为 |
| --- | --- |
| `filestore.ListDirectory` / `GET /api/filesystem` | 不返回以 `.hidden.metadata.json` 结尾的文件，搜索同样过滤 |
| `filestore.ListFiles` / `GET /api/files` / 存储用量 | 不返回，也不计入用户文件数和容量 |
| `GET /files/{name}`、`GET /preview-files/{name}` | 返回 404，避免直接 URL 下载/预览 |
| `GET /thumbnails/{name}` | 返回 404 |
| `POST /api/filesystem/{action}` | 对元数据路径返回无效/不存在，不能删除、移动或重命名 |
| `DELETE /api/files/{name}` | 返回 404 |
| 本机“打开/打开所在文件夹” | 拒绝 |
| 上传目录清单与单文件保存 | 拒绝保留后缀，避免用户把内部文件上传成不可见文件 |

`GET /api/filesystem` 返回的条目仍按现有规则排序，过滤发生在构建结果时。

### 4. 表格重命名、移动与删除

- `tablestore` 增加：

```go
func (s *Store) RelocateLayout(previous, current string) error
func (s *Store) RemoveLayout(name string) error
```

- `RelocateLayout`：仅针对单文件；读取旧侧车原始字节，写入新侧车，再删除旧侧车。目标已存在时覆盖，避免遗留旧偏好；任一步失败只记录日志，不影响文件操作结果。
- 目录整体移动/重命名时，侧车随目录自动移动，无需改动 JSON。
- 删除单个表格时删除侧车；删除目录时侧车随目录一起删除。
- `internal/httpserver/filesystem.go` 现有 `syncTableMarks` 扩展为同时同步表格偏好；`DELETE /api/files/{name}` 成功删除文件后也尝试删除侧车。

### 5. HTTP API

浏览器表格查询响应增加可选 `layout` 字段：

```json
{
  "path": "data/orders.csv",
  "version": "sha256:...",
  "columns": ["id", "status", "customer", "amount"],
  "rows": [],
  "total": 0,
  "offset": 0,
  "limit": 50,
  "modified": "2026-11-24T00:00:00Z",
  "layout": {
    "version": 1,
    "order": ["id", "status", "customer", "amount"],
    "hidden": ["internal_note"]
  }
}
```

- 只有浏览器入口 `POST /api/tables/query` 附带 `layout`；插件入口 `POST /api/plugin-api/tables/query` 保持原响应不变。
- 元数据读取失败时返回空偏好，查询仍然成功。

新增写接口：

```http
POST /api/tables/layout
Content-Type: application/json
X-Lan-Copy-Action: tables

{"path":"data/orders.csv","version":1,"order":["id","status"],"hidden":["internal_note"]}
```

- 要求 `X-Lan-Copy-Action: tables`，与表格写入使用同一来源校验。
- 任意列（包括记录标识列）都可以出现在 `hidden` 中，服务端不强制取消隐藏。
- 响应返回归一化后的 `{"path","layout"}`。
- 表格不存在返回 404，路径非法返回 400，写入失败返回 500。
- 不调用 `notifyFilesChanged()`，因为用户可见文件列表没有变化；也不发布生命周期事件。

路由增加：

```go
mux.HandleFunc("POST /api/tables/layout", s.saveTableLayout)
```

### 6. 错误与限制

- 读取从不因侧车内容报错；保存复用现有表格错误类型，不新增哨兵错误。
- `order`/`hidden` 超过 `MaxColumns` 时截断，空列名或超过单元格上限的列名被忽略。
- 保存前重新读取 CSV 表头，避免向已删除的表格写侧车。

const layoutOrder = ref<string[]>([])

列计算：

- `allColumns`：`result.columns`，始终代表 CSV 物理列。

## 风险与后续

- 侧车文件位于共享目录，任何设备都能看到或修改；本版按“可信局域网共享”处理，不加密、不校验签名。
- 如果用户通过外部程序删除/重命名 CSV 而不经过 Lan Copy，侧车可能成为孤儿文件；它会继续被 Lan Copy 隐藏，重新上传同名表格时偏好会被复用。后续可增加后台清理。
- 列偏好在多端不实时同步；需要刷新才能看到其他设备的修改。若后续需要实时同步，可复用现有文件变更事件，但本版不做。
- 不支持拖拽排序，先提供上移/下移按钮；列很多时可通过面板内滚动操作。
