# Lan Copy v0.10.6 资源详情与运行占用计划

更新日期：2026-11-20。状态：**待批准**。

## 背景与目标

v0.10.5 已让设置 → 资源页显示共享空间、上传、暂存和下载的占用，但信息仍集中在四个数字上：

- 看不到空间被哪些文件类型占用，无法判断大头是视频、图片还是压缩包。
- 看不到 Lan Copy 自身的 CPU/内存占用。
- 看不到运行中插件的 CPU/内存占用。
- 统计数字与上传限制编辑混在同一区域，职责不清。

本版在同一个“资源”设置面板内拆成上下两部分：

1. **资源详情**：共享空间合计、文件类型堆叠条形图、上传/暂存/下载占用、Lan Copy 与插件的实时 CPU/内存。
2. **资源配置**：现有的并发上传数、暂存空间、读取空闲超时及保存操作。

实时运行数据每 2 秒自动刷新；文件类型统计只在打开面板、切换回资源页或点击刷新时重新扫描。

## 已确认的边界

- 保留设置左侧一个“资源”入口，不新增设置菜单项；面板内部按上下两部分拆分。
- 文件类型按固定分类聚合：图片、视频、音频、文档、压缩包、代码/文本、其他。
- 堆叠条形图只展示字节占比，不提供点击筛选、钻取或按目录拆分。
- Lan Copy 自身内存使用 Go 运行时的 `MemStats.Sys`（从操作系统取得的内存），不读取系统活动监视器的 RSS；界面注明“运行时内存”。
- Lan Copy CPU 使用进程累计 CPU 时间差分计算，按单核百分比显示，可超过 100%；首次采样显示“采样中…”。
- 插件只统计运行中的容器；启动中、停止、失败和未安装插件不进入合计。单个插件采样失败记为不可用，不影响其他插件和 Lan Copy 自身数据。
- 实时数据只在资源详情可见、设置弹窗打开且页面处于前台时轮询；关闭弹窗、切到其他设置页或页面隐藏时停止。
- 不修改共享文件、上传限制、插件生命周期、容器资源限制或权限模型。
- 不把统计结果持久化，不提供历史趋势、导出或告警。

## 非目标

- 不显示系统总内存、整机 CPU、磁盘剩余空间或宿主机负载。
- 不统计插件镜像、容器日志、数据卷占用的磁盘空间。
- 不按扩展名逐个展示，也不合并“其他”以外的细分类。
- 不实现图表交互、动画过渡或第三方图表库。
- 不为插件统计新增后台常驻采集器；使用现有 2 秒 stats 缓存和按需查询。

## 一、文件类型聚合

### 1.1 `internal/filestore/usage.go`

扩展 `Usage`：

```go
type TypeUsage struct {
    Kind  string `json:"kind"`
    Bytes int64  `json:"bytes"`
    Files int    `json:"files"`
}

type Usage struct {
    Bytes int64       `json:"bytes"`
    Files int       `json:"files"`
    Types []TypeUsage `json:"types"`
}
```

- `ListFiles` 的结果按扩展名（小写）归类，大小写不敏感；无扩展名归入 `other`。
- 分类键与扩展名：
  - `image`：jpg/jpeg/png/gif/webp/avif/bmp/ico/svg/heic/heif/tif/tiff
  - `video`：mp4/m4v/webm/ogv/mov/mkv/avi/wmv/flv
  - `audio`：mp3/m4a/wav/flac/ogg/oga/aac/opus
  - `document`：pdf/doc/docx/xls/xlsx/ppt/pptx/csv/tsv/txt/md/rtf/odt/ods/odp/epub
  - `archive`：zip/tar/gz/tgz/bz2/xz/7z/rar/zst
  - `code`：go/js/mjs/cjs/ts/tsx/jsx/vue/html/htm/css/scss/less/json/xml/yaml/yml/toml/ini/sh/bash/zsh/ps1/py/rb/php/rs/java/kt/c/h/cpp/hpp/cs/sql
  - `other`：其余
- `Types` 只返回非零分类，按字节数降序；字节相同按固定分类顺序，保证图表颜色和顺序稳定。
- 合计仍使用全部可见普通文件，与现有 `/api/storage` 的 `bytes`/`files` 完全一致。
- `/api/storage` 响应增加 `types` 字段；现有客户端只读 `bytes`/`files`，保持兼容。

## 二、Lan Copy 进程采样

### 2.1 新增 `internal/processstats`

```go
type Sample struct {
    CPUPercent  float64   `json:"cpuPercent"`
    MemoryBytes int64     `json:"memoryBytes"`
    CPUReady    bool      `json:"cpuReady"`
    SampledAt   time.Time `json:"sampledAt"`
}

func New() *Sampler
func (s *Sampler) Sample() Sample
```

- 采样器只在内存保存上一次累计 CPU 时间和时间戳，不加后台 goroutine。
- 首次调用只建立基线，`CPUReady=false`，CPU 显示“采样中…”。
- 两次采样间隔小于 500ms 时返回上次 CPU 百分比，避免手动刷新产生噪声；内存仍读取最新值。
- CPU 百分比 = `(累计 CPU 时间差 / 墙钟时间差) × 100`，保留一位小数。
- 内存使用 `runtime.ReadMemStats` 的 `Sys`。

### 2.2 CPU 跨平台实现

- `cpu_unix.go`（`//go:build unix`）：`syscall.Getrusage(RUSAGE_SELF)`，累加 `Utime` 与 `Stime`。
- `cpu_windows.go`（`//go:build windows`）：`syscall.GetProcessTimes(GetCurrentProcess())`，累加内核态与用户态时间。
- `cpu_other.go`（`//go:build !unix && !windows`）：返回不支持错误，界面显示“不可用”；不影响其他平台构建。
- 内存实现共用，不引入 `gopsutil` 等新依赖。

## 三、插件占用聚合

### 3.1 `internal/plugin`

新增：

```go
type UsageItem struct {
    PluginID         string  `json:"pluginId"`
    Name             string  `json:"name"`
    CPUPercent       float64 `json:"cpuPercent"`
    MemoryBytes      int64   `json:"memoryBytes"`
    MemoryLimitBytes int64   `json:"memoryLimitBytes"`
    PIDs             int64   `json:"pids"`
    Available        bool    `json:"available"`
    Error            string  `json:"error,omitempty"`
}

type Usage struct {
    Running          int         `json:"running"`
    Unavailable      int         `json:"unavailable"`
    CPUPercent       float64     `json:"cpuPercent"`
    MemoryBytes      int64       `json:"memoryBytes"`
    MemoryLimitBytes int64       `json:"memoryLimitBytes"`
    PIDs             int64       `json:"pids"`
    Items            []UsageItem `json:"items"`
    SampledAt        time.Time   `json:"sampledAt"`
}
```

`func (m *Manager) Usage(ctx context.Context) Usage`：

- 在管理锁内收集运行中且 `RuntimeInstanceID` 非空的实例及插件名称，然后释放锁。
- 并发调用现有 `m.stats` 读取每个插件，复用 2 秒缓存；单个失败只标记该项 `Available=false`，不返回整体错误。
- 合计只累加可用项；`Running` 为运行中实例数，`Unavailable` 为采样失败数。
- 结果按插件名称、ID 排序，保证界面顺序稳定。
- 使用调用方传入的 context；HTTP 层给插件聚合设置 3 秒超时，避免单个运行时拖住整页。

- 保持 `no-store`、GET、访客可读。
- 文件扫描失败仍返回 500，不返回部分分类。

### 4.2 `GET /api/system-usage`

```json
{

    "cpuPercent": 1.2,
    "memoryBytes": 48234496,
    "cpuReady": true,
    "sampledAt": "2026-11-20T12:00:00Z"

  "plugins": {
    "running": 1,
    "unavailable": 0,
    "cpuPercent": 3.4,
    "memoryBytes": 104857600,

    "items": [
      {
        "pluginId": "demo",
        "name": "示例插件",
        "cpuPercent": 3.4,
        "memoryBytes": 104857600,
        "memoryLimitBytes": 536870912,
        "pids": 12,
        "available": true
      }
    ],
    "sampledAt": "2026-11-20T12:00:00Z"

```

- 只注册 GET，`Cache-Control: no-store`。
- 无插件管理器时返回运行数 0、空列表和零值。
- 插件聚合使用 3 秒超时；超时项计入 `unavailable`。
- 不含环境变量、挂载、镜像、日志等插件明细。

## 五、资源页布局

设置左侧仍为“关于、通用、资源、更新、部署、插件”。资源页从上到下：

### 5.1 资源详情

1. 标题行：“资源详情” + “刷新”按钮 + “实时数据每 2 秒自动刷新”。
2. 四张占用卡片：共享文件、上传任务、暂存空间、下载任务，沿用 v0.10.5 样式。
3. 文件类型堆叠条形图：
   - 顶部显示“合计 700 MiB · 42 个文件”。
   - 条形图按分类字节占比分段，颜色与图例一致。
   - 图例列出分类、大小、文件数和百分比；零字节分类不显示。
   - 无文件时显示“共享空间中还没有文件”。
   - 使用 CSS flex 和百分比宽度实现，不引入图表库；容器 `role="img"` 提供完整中文 `aria-label`。
4. 运行占用：
   - Lan Copy 卡片：CPU、运行时内存；CPU 未就绪时显示“采样中…”。
   - 插件合计卡片：CPU、内存 / 上限、运行插件数、PID 合计。
   - 运行中插件表：名称、CPU、内存、PID；采样失败显示“暂时不可用”和原因摘要。无运行插件时显示空状态。
5. 统计错误只影响详情区，资源配置保持可用。

### 5.2 资源配置

- 与详情区用分隔线和“资源配置”标题隔开。
- 保留并发上传数、暂存空间（GiB）、读取空闲超时和保存按钮。
- 保留现有范围校验、本机可写/访客只读、`X-Lan-Copy-Action: upload-resources` 和保存后立即更新统计上限的行为。
- 文案明确“仅影响之后开始的上传”。

### 5.3 刷新策略

- 打开设置、切回资源页、点击刷新：重新读取 `/api/resource-usage` 和 `/api/system-usage`。
- 自动刷新只请求 `/api/system-usage`，每 2 秒一次；上一次未结束时跳过本轮，避免请求堆积。
- 弹窗关闭、切换到其他设置页、页面隐藏时停止计时器；组件卸载时清理。
- 文件类型统计不参与自动轮询，避免大目录反复扫描。

### 5.4 响应式

- 统计卡片和运行占用卡片使用自适应网格，宽屏两列或四列，窄屏单列。
- 堆叠条形图和图例在 360px 下可换行，不出现横向滚动。
- 插件表在窄屏下只保留名称、CPU、内存，PID 放入同一行次要信息或隐藏列。

## 九、风险与限制

- 文件类型统计需要递归遍历共享目录，大目录首次读取较慢；只在按需刷新时执行。
- Lan Copy 内存是 Go 运行时从系统取得的内存，不等同于活动监视器的 RSS；界面会明确标注。
- CPU 百分比按单核计算，多核繁重任务可能超过 100%；首次打开需要一次采样基线。
- 插件统计依赖容器运行时，每秒轮询会调用 Docker/Podman stats；现有 2 秒缓存和 3 秒超时用于限制开销，插件多时仍可能变慢。
- 插件采样失败时只显示部分数据，不弹出全局错误，避免影响资源配置。
- 堆叠图分类是固定启发式规则，未知扩展名统一归入“其他”；不保证与操作系统文件类型识别完全一致。
