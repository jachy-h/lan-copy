# Lan Copy v0.16.0 计划：macOS 下 `lancopy` 直接后台启动

更新日期：2026-11-24。状态：**待批准**。

## 背景

Homebrew 安装后命令名为 `lancopy`（发布包内二进制仍叫 `lan-copy`）。当前直接执行：

```bash
lancopy
```

会在前台阻塞终端，并输出插件运行时探测等内容；要后台常驻必须改用 `brew services start lancopy`。目标是让**直接执行 `lancopy`** 就能启动、打印启动日志、自动转入后台并交还终端，同时不改变发布包内 `lan-copy`、`go run .`、`make build` 产物与 `brew services` 的现有语义。

## 目标

1. 在 macOS 终端执行 `lancopy`（无参数）后：
   - 服务在后台运行，终端提示符立即恢复；
   - 打印启动日志：存储目录、本机地址、局域网地址、浏览器提示、日志文件路径；
   - 不打印插件运行时探测等插件相关内容（仍写入日志文件，便于排查）；
   - 启动失败（端口被占用、目录不可写等）时打印实际错误并以非零码退出，不留下半启动进程。
2. 再执行一次 `lancopy` 时，若已有实例在监听，打印“已在运行”和访问地址后退出，不启动第二份服务。
3. 其它入口行为不变。

## 已确认的决策

- **只在 macOS 且命令名为 `lancopy` 时自动后台**：判定条件为 `runtime.GOOS == "darwin"`、`filepath.Base(os.Args[0]) == "lancopy"`、无参数、`stdout` 是真实 TTY。这样：
  - Homebrew 的 `lancopy` 得到后台体验；
  - 发布包里的 `lan-copy`、`make build` 产物、`go run .`（临时二进制名 `lan-copy`）保持前台，开发调试与现有文档命令不受影响；
  - `brew services`（带 `-dir` 参数）与 `-autostart`、`-listen`、`-dir` 等显式参数仍是前台，交给 launchd 或用户自己管理。
- **单二进制自我重启，不写脚本、不改 Formula**：父进程用 `--internal-background` 重新执行自身，子进程 `Setsid` 进入新会话，stdin 指向 `/dev/null`，stdout/stderr 追加到日志文件。Homebrew Formula 无需改动即可生效。
- **启动日志通过额外管道回传**：父进程用 `ExtraFiles` 把管道写端作为 fd 3 交给子进程（`LAN_COPY_READY_FD=3`）。子进程只把启动摘要行同时写入日志和该管道，写完后关闭；父进程读到 EOF 后打印摘要并退出。插件日志只进日志文件，因此终端天然没有插件内容，不需要按文案过滤。
- **就绪即返回，不等待子进程退出**：父进程读到启动摘要（或超时/子进程退出）就结束；成功启动后不为子进程调用 `Wait`，由系统在父进程退出后托管。超时 15 秒；超时会打印日志尾部并终止本次启动的子进程。
- **日志文件固定位置**：默认 `~/Library/Logs/lancopy/lancopy.log`，可用环境变量 `LAN_COPY_LOG_FILE` 覆盖（测试与特殊部署使用）。启动前若日志超过 8 MiB，轮转为 `lancopy.log.1`（覆盖旧文件），避免后台日志无限增长。
- **不新增停止命令**：停止仍走页面右上角“关闭软件”（`/api/shutdown`）。`brew services start/stop lancopy` 仍是 launchd 场景的官方方式，两者不混用。
- **重复启动探测只做一次**：父进程在派生前后用 `probeRunningInstance` 对 `-listen` 地址做一次约 300ms 的探测；命中本服务则打印“已在运行”。未命中立即派生，不引入 2 秒等待。

## 行为矩阵

| 入口 | 行为 |
| --- | --- |
| macOS 终端 `lancopy` | 后台启动，打印启动摘要后恢复提示符 |
| `lancopy` 第二次执行（已有实例） | 打印“已在运行”与地址，退出 0 |
| `lancopy -dir ~/x` / 其它参数 | 前台，行为不变 |
| 发布包 `./lan-copy` | 前台，行为不变 |
| `go run .`、`make build` 产物 | 前台，行为不变 |
| `brew services start lancopy` | launchd 前台托管，行为不变 |
| Windows / Linux | 行为不变（`lan-copy` 与 `lancopy` 都不自动后台） |

## 代码改动

### 新增 `internal/desktop/background_darwin.go`

- `ShouldStartBackground() bool`：判断命令名、无参数、TTY（`golang.org/x/sys/unix.IoctlGetTermios`，仅 darwin 引用）。
- `StartBackground() error`：轮转日志、打开日志文件、创建就绪管道、`exec.Command(exe, "--internal-background")` 并使用 `SysProcAttr{Setsid: true}`、`ExtraFiles` + `LAN_COPY_READY_FD=3`；读取 fd 3 直到 EOF/超时；打印子进程回传的启动行与日志路径；失败时返回包含日志尾部的错误。
- `ReadyWriter() io.WriteCloser`：子进程侧读取 fd 3；未设置环境变量时返回 nil，普通前台运行无额外行为。
- `BackgroundLogPath() (string, error)`、`rotateLog(path, maxBytes)`、`tailLines(path, n)` 等辅助函数，均为可测试的小函数。
- 测试用可注入参数：`startBackground(exe, logPath string, timeout time.Duration)` 返回子进程与回传行，便于用临时 shell 脚本覆盖成功、失败、无回传三种情况。

### 新增 `internal/desktop/background_other.go`

非 darwin 的桩实现：`ShouldStartBackground() false`、`StartBackground()` 返回错误、`ReadyWriter()` 返回 nil，保证跨平台编译。

### 修改 `internal/app/runtime.go`

- `flag.Parse()` 之前识别并剥离 `--internal-background`（与现有 `--internal-autostart`、`--internal-updater` 同一层处理）。
- `flag.Parse()` 之后、创建 listener 之前：
  - 若当前是父进程且 `desktop.ShouldStartBackground()`：
    - 一次性探测 `-listen` 地址，已运行则打印地址并返回；
    - 否则调用 `desktop.StartBackground()`，成功或失败后直接返回/退出，不再继续前台流程。
- 启动摘要行改为经统一 helper 输出：始终写入 `log`；子进程模式下同时写入 `desktop.ReadyWriter()`，全部写完后关闭。启动摘要包含现有 5 行（已启动目录、本机地址、局域网地址、浏览器提示），不包含插件日志。
- 其余流程（listener、组件、插件、HTTP、信号处理）不变。

### 测试

- `internal/desktop/background_darwin_test.go`（darwin 构建标签）：
  - 条件表：`lancopy`/`lan-copy`、有/无参数、是否 TTY、是否子进程环境下 `ShouldStartBackground` 的取值；
  - 日志路径默认值与 `LAN_COPY_LOG_FILE` 覆盖；
  - 8 MiB 轮转（用很小的阈值注入测试）；
  - 父/子握手：临时脚本向 fd 3 写两行后驻留，断言父进程拿到这两行且子进程仍存活；脚本只写 stderr 并退出，断言返回错误且错误含日志尾部；脚本不写 fd 3，断言超时路径终止子进程。
- `internal/app/startup_test.go`：启动摘要 helper 输出包含存储目录、本机地址、每个局域网地址、浏览器提示，且不包含任何“插件”文案。
- `go.mod` / `go.sum`：`golang.org/x/sys` 从间接依赖提升为直接依赖（模块已在图中，无新下载）。

人工验收（macOS 终端，非脚本、stdout 为 TTY）：

1. `go build -o /tmp/lancopy-bin/lancopy .` 后执行 `/tmp/lancopy-bin/lancopy`：
   - 输出启动摘要且不出现“插件运行时”等插件行；
   - 立即回到提示符；
   - `curl -fsS http://localhost:8080/healthz` 返回 `ok`；
   - `~/Library/Logs/lancopy/lancopy.log` 中有完整日志（含插件行）；
   - 再次执行同一命令，打印“已在运行”并退出 0；
   - 页面右上角“关闭软件”能停止进程。
2. `go run .` 与 `./lan-copy`：仍为前台，Ctrl-C 可停止。
3. `lancopy -dir /tmp/x`：仍为前台。
4. 端口被其它程序占用时执行 `lancopy`：打印绑定错误与日志路径，非零退出，且没有残留进程。
5. 把日志文件写到超过 8 MiB 后再次启动：生成 `lancopy.log.1`，新日志重新开始。

## 不做的部分

- 不新增 `lancopy --stop`、pid 文件或 launchd 注册；停止走页面与 `brew services stop`。
- 不改变 Windows 控制台行为、发布归档布局、更新包格式、插件协议与 HTTP API。
- 不修改 Homebrew Tap 的 Formula（本仓库发布后，Tap 的 caveats/README 文案可另行同步，但不属于本仓库改动）。
- 不让 `lan-copy`、Linux/Windows 或带参数的启动自动后台。

## 风险与后续

- **TTY 判定**：使用 darwin 上的 termios ioctl，重定向到 `/dev/null` 或管道时不会误判为交互终端。
- **父进程在 15 秒等待期内被 Ctrl-C**：子进程在新会话中可能继续启动；这符合“后台启动”的预期，但用户会失去本次父进程的输出。超时路径会终止子进程，避免无提示的悬挂启动。
- **`brew services` 与手工 `lancopy` 混用**：先启动的一方占用端口，后启动方会得到“已在运行”或绑定错误，不会出现两份服务。
- **日志增长**：按 8 MiB 轮转并只保留一份旧日志，最多约 16 MiB。
