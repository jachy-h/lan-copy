# Lan Copy v0.5.6 计划

制定日期：2026-10-27。用户已选择 A：PDF、JPG/JPEG、PNG，并要求考虑打印预览。在 v0.5.5 工作区上增量实现，保留已有未提交工作，不修改 VERSION 或发布配置。

## 目标与范围

- 打印页选择本地单个文件，或从共享空间文件的「⋯」菜单选择「打印」进入预览；支持 PDF、JPG/JPEG、PNG；打印前显示纸张版面预览，PDF 可逐页预览，预览支持放大/缩小，缩放不改变打印尺寸。
- Windows 主机复用已安装驱动。纸张及方向跟随设备默认设置，等比缩放并居中到可打印区域；首版固定一份、单面，一页文档对应一张纸。
- 保留测试页功能，文件与测试页任务共用互斥和最近 50 条内存记录；区分已提交与实际出纸。Office、其他图片格式、页码范围、手动纸张/方向/份数、完整系统队列管理后续完善。

## 选定方案与边界

1. 复用内嵌 PDF.js，在浏览器完成 PDF 及图片解码，按 Windows 返回的真实纸张/可打印区域生成 200 DPI 的 PNG 页面。预览与打印使用相同布局和渲染逻辑；图片透明区域铺白底，方向使用浏览器解码结果。
2. 不增加外部打印程序、PDF 原生库、进程或 DLL 资产。代价是浏览器需要准备全部页面并把 PNG 页面发送给主机；限制原文件 50 MiB、最多 50 页，单页 PNG 12 MiB/1600 万像素，合计 128 MiB，逐页渲染释放画布。
3. 后端只接收声明格式为 PDF/JPG/JPEG/PNG 的文档元数据及有序 PNG 页面；原文件不写入共享空间。这是浏览器渲染后的文件打印协议，不声称后端独立解析 PDF。`printing` 组件拥有暂存、校验、提交/回滚和清理，不允许客户端指定磁盘路径。
4. Windows 用 GDI 查询纸张、可打印区域与偏移；用 DEVMODE 固定一份/单面，`StretchDIBits` 输出已准备页面。提交前核对版面标识，纸张/方向/分辨率变动时失败并要求刷新预览，不静默改变版面。
5. 临时页放在应用私有数据目录，上传/验证失败、任务完成或失败均清理；启动清理上次遗留的自有暂存目录，绝不重放任务。原生打印失败不自动重试，已部分出纸的任务不能保证撤回。
6. HTTP 层处理 multipart、请求大小、同源动作校验和状态码；组件处理格式/页数/像素/总量限制、设备校验与互斥。完整文件接收校验完成前不调用原生打印。

## 共享空间入口补充（2026-10-27）

- 只在单个 PDF、JPG/JPEG、PNG 文件的「⋯」扩展菜单中增加「打印」；不改变点击文件名、双击行和文件预览的原有行为。文件夹、不支持格式、多选菜单不提供打印。
- 通过 SPA 进入 `/print-queue?file=...&from=...`，自动读取共享文件并显示来源及预览；进入、刷新和前进后退均不自动提交打印。共享空间导航保留原文件夹，返回地址只允许共享空间自身路径。
- 使用已有 `/preview-files/{name}`，由 filestore 继续完成路径和普通文件校验，不增加磁盘路径接口。浏览器先读取一份有 50 MiB 上限的快照，预览及确认打印均使用此快照，避免源文件变化导致输出内容与预览不一致。
- 读取失败、已移动/删除、超限或非法路径均禁用打印；切换文件、选择本地文件、关闭页面和关停时取消过期请求，不把旧文件覆盖到新选择上。改选本地文件时清除 URL 中的共享来源。

## 验证要求

运行前端类型检查与测试、构建并同步嵌入资源；Go 测试、vet、相关 race 检查及 Windows/Linux/macOS 构建。真实浏览器测试模拟设备和原生提交，不能代替 Windows 实际出纸验收；明确记录无法验证项。
