# Lan Copy v0.4.0 计划

## 背景与目标

当前文件系统页面以共享空间卡片列表呈现，支持目录导航、递归搜索、上传文件夹、拖放上传/移动、新建文件夹、移动、重命名、删除及文件预览。主要操作可用，但工具入口和行内按钮偏网页式；文件列表缺少 Windows 文件资源管理器中熟悉的导航层级、详细信息列、键盘操作和选择反馈。

v0.4.0 聚焦文件系统前端交互与视觉改造，让常见操作更接近 Windows 资源管理器的操作习惯，同时保留 Lan Copy 的网页共享场景、单页嵌入部署和现有服务端行为。目标是熟悉、可预期、可键盘操作，而不是在浏览器里模拟完整桌面窗口或 Windows 外观。

## 现状与边界

- `web/index.html` 提供共享空间、搜索、上传文件夹、新建文件夹、路径导航、条目列表和上传状态区域。
- `web/filesystem.js` 管理目录读取、递归搜索、拖放、目录上传、移动、重命名和删除；文件列表变化由 SSE 通知刷新。
- `web/file-ui.js` 管理名称预览、图片缩略图、搜索词高亮和复制文本。
- `web/style.css` 使用卡片和无列行布局；文件/文件夹操作按钮常驻显示，当前没有条目选择模型、上下文菜单或键盘快捷操作。
- `GET /api/filesystem`、文件预览/下载和现有变更 API 已足以承载本次交互；除非实施中发现明确缺口，不改变 API、访问控制、文件名校验、上传提交/回滚和删除确认语义。
- 文件内容只保存在运行 Lan Copy 的电脑上。网页不能无提示地获得本机任意目录访问权；本机打开文件夹仍通过既有桌面接口，远端设备仍以下载和网页预览为主。

## 设计原则

1. **沿用 Windows 的操作模型，不照搬 Windows 视觉皮肤。** 使用紧凑工具栏、可读路径、详细信息列表、单击选择、双击打开文件夹、右键菜单和清晰的焦点/选中状态；维持 Lan Copy 现有色彩与品牌。
2. **常用命令显式，低频命令收纳。** 导航、搜索、新建文件夹和上传保持可见；移动、重命名、删除、复制路径等放入上下文菜单或选择后的命令栏，避免每行按钮挤占文件名空间。
3. **交互反馈一致。** 单击只选择；双击文件夹进入目录、双击文件按当前预览能力打开；键盘 Enter 与双击行为一致。所有破坏性操作继续明确确认并报告结果。
4. **渐进增强。** 桌面端提供完整键盘和右键操作；触屏端提供可见菜单入口和足够大的触控区域，不依赖 hover 或右键。
5. **渐进改造。** 保留单页结构和嵌入资源方式，按交互、结构、样式分阶段实施，不借此重写文件服务或迁移数据。

## 目标体验方案

### 1. 导航工具栏与位置栏

- 在文件列表上方增加紧凑导航行：返回上一级、回到全部文件、当前位置路径和刷新。根目录时禁用“上一级”。刷新只重新读取当前目录及当前搜索条件。
- 路径采用可点击的分段面包屑，各段之间用轻量分隔符；窄屏时允许横向滚动或收纳前段，避免长路径挤掉主要操作。继续支持拖放到路径段以移动条目。
- 双击文件夹行进入目录；提供可见的文件夹图标/名称点击入口，确保触屏设备不需要双击。
- 浏览器前进/后退应恢复之前的目录路径；目录导航和刷新不能意外清空用户正在输入的搜索词，搜索框提供清除按钮。
- 页面标题或位置区展示当前目录名；条目总数、文件夹数和搜索命中数放在列表状态栏，避免与路径争夺空间。

### 2. 详细信息列表

- 桌面端默认使用 Windows 常见的“详细信息”视图，列为：名称、修改日期、类型、大小。文件夹优先，名称按不区分大小写排序；同类条目按名称排序。保持排序稳定，刷新后不跳动。
- 名称列显示缩略图或类型图标、文件/文件夹名称；日期使用本地化格式，类型展示友好的文件类型或“文件夹”，文件夹大小显示短横线。
- 点击列标题切换升序/降序，显示排序方向并向辅助技术暴露 `aria-sort`。小屏改用紧凑的两行列表，保留名称、日期和核心操作，不强行显示全部列。
- hover 展示轻微背景；焦点行有可见轮廓；选中行使用稳定的浅蓝底色和边框。选择与 hover 必须有明显区别。
- 空目录、无搜索结果、读取中和读取失败均使用独立状态，不把错误伪装成空目录。长名称省略显示但可通过标题/辅助标签读取完整名称。

### 3. 选择、打开与键盘操作

- 单击条目选择一项；Ctrl/Command+单击切换多选；Shift+单击选择连续范围；空白处单击清除选择。多选状态显示选择数量及适用操作。
- 双击文件夹进入；双击可预览文件打开预览页；不支持预览的文件沿用下载行为或提示可下载。保留当前明确的下载和本机打开所在文件夹能力。
- 键盘焦点进入列表后支持 Up/Down 移动焦点、Enter 打开、Space 选择、Ctrl/Command+A 全选当前可见结果、Escape 清除选择/关闭菜单。快捷键不得拦截输入框、对话框和浏览器/操作系统保留的组合键。
- `F2` 重命名选中单项；`Delete` 调用现有删除确认；`Ctrl/Command+C` 在浏览器权限允许时复制所选条目的相对路径，并以轻提示说明复制结果。若剪贴板不可用，保留现有降级实现。
- 焦点移动、选择变化和操作完成使用合适的 ARIA 语义及 `aria-live` 状态播报；不依赖颜色作为唯一状态提示。

### 4. 命令栏与上下文菜单

- 工具栏保留搜索、新建文件夹、上传文件夹；“上传文件”可沿用页面现有拖放/选择能力，如果实现独立按钮则复用现有上传流程，不另造提交路径。
- 选择条目后显示上下文命令：打开/预览、下载或打开所在文件夹、移动、重命名、删除、复制路径。只显示适用于当前选择的命令；多选只启用已有后端语义可支持的操作，避免假装支持批量操作。
- 条目右键打开自绘上下文菜单，菜单支持 Escape 关闭、方向键移动、Enter 执行、点击外部关闭，并将焦点返回触发条目。浏览器原生右键菜单在文件列表内由自绘菜单替代；列表外保持浏览器默认行为。
- 触屏端通过溢出按钮打开同一菜单；关键操作不能只在 hover 或右键中出现。
- 移动、重命名、删除继续使用现有 API 与确认机制。删除非空文件夹仍先提示，再根据服务端确认要求询问递归删除；替换同名上传继续逐项明确确认。

### 5. 视图状态与响应式布局

- 初期只提供“详细信息”列表视图，避免同时承担图标/平铺/内容视图的布局和状态维护；若用户反馈强烈，再单独评估图标视图。
- 目录排序方式可在当前页面交互中切换；视图偏好是否跨会话保存，优先用本地 `localStorage`，仅存排序/列宽等无敏感信息的展示偏好，不写入服务端。
- 桌面宽度下列表占满共享区域，工具栏和路径栏保持一行优先；窄屏下折行，操作收进触控菜单，列信息转为次级文本。
- 尊重 `prefers-reduced-motion`；使用系统字体栈和中性表面色，避免仿 Windows 标志、窗口边框或系统控件造成平台错觉。

### 6. 拖放与操作反馈

- 拖动共享条目到文件夹或面包屑仍表示移动，悬停目标提供明确高亮；拖动本地文件/文件夹到页面表示上传，保留当前拖入覆盖层和目录结构上传行为。
- 两类拖放使用不同提示与图标，避免把本机文件拖放和共享空间内移动混淆。搜索结果中拖放目标路径仍指向真实目录，不把搜索结果位置误当成当前目录。
- 移动、重命名、删除后保持当前目录；被删除/移动的当前目录失效时按既有逻辑回到根目录。刷新期间保留选择时，若条目已消失则清理失效选择。
- 操作成功用轻量 toast 和列表更新表达；失败保留表单/菜单上下文并显示可理解的错误。上传进度继续显示已读取/已上传状态。

## 实施阶段

### 阶段一：交互模型与语义

梳理 `filesystem.js` 的目录、筛选、排序、选择、焦点与命令状态；建立稳定的条目 DOM 标识和事件委托，定义键盘/鼠标/触屏统一的操作入口。确保导航历史、刷新和 SSE 更新不会丢失错误状态或留下失效选择。

**验收：** 鼠标单击/双击、键盘导航、搜索、目录切换、SSE 刷新、拖放移动/上传之间状态一致；操作仅调用既有 API。

### 阶段二：资源管理器式列表与命令入口

调整 `index.html` 的文件页结构，加入导航工具栏、位置栏、列标题、详细信息行、命令栏和上下文菜单容器。调整 `style.css` 实现紧凑列表、选择/焦点/排序反馈、桌面与触屏响应式布局；保留原来的上传进度、空状态和对话框。

**验收：** 桌面端能看清列信息，操作不挤占名称；触屏端不依赖悬浮/右键；缩放、长路径、长名称和窄视口下没有横向溢出或不可达控件。

### 阶段三：键盘辅助功能与边界收尾

实现并核对快捷键、菜单焦点管理、ARIA 状态、剪贴板回退和无动画偏好。检查输入框、对话框和预览导航中的快捷键冲突，确保菜单可以只用键盘关闭和操作。

**验收：** 完成核心文件操作无需鼠标；焦点始终可见且关闭菜单后返回原位置；屏幕阅读器可识别列表、列标题、选择数量、排序方向和操作结果。

### 阶段四：兼容性验证与文档

检查 Chromium、Firefox、Safari 的基本交互，Windows、macOS、Linux 桌面浏览器及 iOS/Android 触屏布局。验证服务端不可达、空目录、递归搜索、外部文件变更、网络错误、非空目录删除、同名上传冲突和并发刷新。

**验收：** `go run .` / `go build .` 的嵌入前端仍正确；现有文件 API、上传和恢复语义不变；更新开发说明并记录浏览器能力差异。测试范围由实现阶段按受影响路径确定。

## 主要改动位置

- `web/index.html`：文件页的导航、工具栏、列表表头、命令区域与菜单容器。
- `web/filesystem.js`：导航历史、稳定排序、选择/焦点模型、快捷键、上下文菜单及命令分发；保留当前上传、移动和实时刷新流程。
- `web/file-ui.js`：必要时提取共享的列表渲染辅助函数；只在存在真实复用时扩展，不把状态管理放入展示工具模块。
- `web/style.css`：资源管理器式详细信息布局、选中/焦点/排序状态、窄屏行为和减少动画偏好。
- `web/` 下现有前端脚本测试：随实际实现补充交互行为回归覆盖，不为纯样式规则写脆弱的快照测试。

## 兼容性与不做事项

- 不更改 Go 文件存储组件边界和既有文件系统 HTTP API，不更改上传暂存、提交、回滚和启动恢复语义。
- 不提供浏览器无法可靠实现的本机任意目录浏览、复制文件内容到系统资源管理器、剪切后跨应用移动或原生 Windows 文件对话框。
- 不把删除、覆盖上传改为静默操作；不移除远程访问与本机访问之间现有的能力差异。
- 不在本版本顺带重做文件预览、更新器、文本共享或整体站点视觉。
- 不引入前端框架或第三方 UI 组件库；在当前嵌入式静态前端中渐进实现。

## 完成标准

- 用户可以通过熟悉的路径导航和详细信息列表定位文件，并用鼠标、键盘或触屏完成核心操作。
- 文件/文件夹选择、排序、打开、移动、重命名、删除、预览/下载、拖放和上传提示一致且有清楚反馈。
- 搜索、SSE 刷新、目录历史、错误及空状态行为稳定；无效选择及时清理。
- 页面在主流桌面和移动浏览器可用，兼顾键盘焦点、屏幕阅读器提示、缩放和减少动画偏好。
- 单进程、单二进制、嵌入式前端、现有 API、存储格式及崩溃恢复行为保持兼容。
