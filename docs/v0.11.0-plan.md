# Lan Copy v0.11.0 插件 Web 界面子路径代理计划

更新日期：2026-11-20。状态：**已批准并完成实现，自动化验证通过，待人工验收**。

## 背景与目标

插件容器目前只监听容器内端口：`loopback` 模式发布到 `127.0.0.1:<随机端口>`，`container` 模式使用 `http://<容器名>:<端口>`，两种方式都只有 Lan Copy 进程自己可达。插件如果自带 Web 界面（配置页、看板、导入向导等），局域网里的手机、平板和其他电脑无法直接打开。

本版增加插件 Web 界面子路径代理：

1. 插件的 `manifest` 可以声明自己带有 Web 界面，声明后 Lan Copy 自动提供入口。
2. 入口固定为 `http://<lan-copy>/plugin-app/<插件ID>/`，把请求反向代理到运行中实例的容器端口。
3. 代理按请求实时解析实例地址，插件重启后宿主端口变化不需要重新配置。
4. 支持普通 HTTP、流式响应（SSE）、文件上传下载和 WebSocket 升级。
5. 插件页与详情页显示“打开界面”，停止、不健康、未声明界面的插件不显示可用入口。

## 已确认的决策

- 目标形态：Lan Copy 容器插件（`loopback` 与 `container` 两种网络模式都支持）。
- 插件可以改造为子路径感知：读取 `X-Forwarded-Prefix`，按前缀生成资源地址、前端路由和 Cookie 路径。
- 插件界面对局域网**默认开放**，与现有插件管理页的信任模型一致。
- 入口采用带插件 ID 的子路径，而不是固定单数 `/plugin-route`：固定路径无法同时挂多个插件，且容易与插件管理页 `/plugins` 混淆。

## 非目标

- 不支持任意 URL 代理，也不支持登记宿主机上的外部进程端口；代理目标只能是 Lan Copy 管理的插件实例。
- 不做插件界面的账号认证、登录态共享或单点登录；沿用现有局域网无登录模型。
- 不做 HTML/JS 内容改写、自动注入 `<base>` 或猜测绝对路径；子路径兼容由插件按协议自行实现。
- 不做插件界面专属域名、TLS 证书或独立端口监听。
- 不改变现有插件调用 API、生命周期事件、表格插件 API 的路径、超时与令牌语义。
- 不做代理层的响应缓存、压缩转码或请求重试。

## 路由与对外行为

| 方法与路径 | 行为 |
| --- | --- |
| `GET /plugin-app/{id}` | `308` 跳转到 `/plugin-app/{id}/` |
| 任意方法 `/plugin-app/{id}/{rest...}` | 反向代理到实例的 `ui.path` + `rest` |

- 路由注册在主 mux 上，使用独立前缀 `/plugin-app/`，与 `/plugins` 管理页、`/api/plugins` 管理接口、`/api/plugin-api` 插件调用接口互不重叠。
- 路径中的 `{id}` 必须符合现有插件 ID 规则；不存在、未安装或未声明 `ui` 返回 `404`。
- 实例未运行、启动中、停止或健康状态不是 `healthy` 时返回 `503`，响应体是简短 HTML 提示页，并在 `Retry-After` 中给出建议重试秒数。
- 上游连接失败、超时或协议错误返回 `502`，不向浏览器暴露容器地址和内部错误细节；原始错误写入服务日志。
- 不做整体请求超时，允许大文件上传下载和长连接；只设置上游响应头超时（60 秒）与空闲连接超时。
- `FlushInterval = -1`，保证 SSE 和分块响应即时下发。
- 请求体不设额外上限，由插件自行限制；响应体不缓冲。

## Manifest 扩展

`Manifest` 增加可选字段：

```json
{
  "ui": {
    "path": "/"
  }
}
```

- `ui` 省略或为 `null` 表示插件没有 Web 界面，不注册代理入口。
- `ui.path` 可选，默认 `/`，表示界面在容器内的挂载路径；必须是 `/` 开头的绝对路径，不含 `..`、查询串和片段，长度 ≤ 256。
- 界面标题使用 Manifest 的 `name`，不新增重复字段。
- 代理入口路径由 Lan Copy 决定，固定为 `/plugin-app/{id}/`，插件不能自定义对外路径。
- 校验规则与现有 `endpoints` 一致；未知字段仍然拒绝。

兼容性：Manifest 解析使用 `DisallowUnknownFields`，带 `ui` 的镜像在旧版 Lan Copy 上会在导入阶段被拒绝。文档需写明最低版本；旧镜像在新版本上不受影响。不采用额外 OCI 标签，避免同一份协议信息出现两个事实来源。

## 插件侧协议

插件必须按子路径部署，不能假设自己挂在站点根路径：

1. 读取请求头 `X-Forwarded-Prefix`（值为 `/plugin-app/{id}`），用它拼接 HTML 中的资源地址、`<base href>`、前端路由 base 和 `fetch` 地址。
2. 资源引用优先使用相对路径；根绝对路径 `/assets/app.js` 会被浏览器解析到 Lan Copy 根路径，导致 404。
3. `Set-Cookie` 的 `Path` 使用 `X-Forwarded-Prefix`，避免与 Lan Copy 根路径或其他插件冲突。
4. 重定向可以使用根绝对路径，Lan Copy 会把 `Location` 改写为带前缀的地址；但插件内部生成的链接仍应带前缀。
5. 需要长连接时正常使用 SSE 或 WebSocket，代理不缓冲、不降级。
6. 插件只能假定自己运行在代理前缀下，不要生成指向 `/api`、`/files` 等 Lan Copy 路径的链接。

Lan Copy 转发时附带：

```http
X-Forwarded-For: <客户端地址>
X-Forwarded-Host: <浏览器访问的 Host>
X-Forwarded-Proto: http
X-Forwarded-Prefix: /plugin-app/<id>
```

## 后端实现

### 1. `internal/plugin/manifest.go`

- `Manifest` 增加 `UI *ManifestUI`，`ManifestUI` 含 `Path string`。
- `ValidateManifest` 校验 `ui.path`；`NormalizeManifest` 把空路径归一为 `/`。
- 补充 Manifest 单元测试：默认值、非法路径、未知字段、旧 Manifest 不受影响。

### 2. `internal/plugin/manager.go`

新增只读目标解析，状态锁只在读取期间持有：

```go
type ProxyTarget struct {
    BaseURL string // http://127.0.0.1:<port> 或 http://<容器名>:<port>
    UIPath  string // Manifest ui.path，已归一化
}

func (m *Manager) ProxyTarget(pluginID string) (ProxyTarget, error)
```

错误分类：

- 插件或实例不存在：`ErrPluginNotInstalled`。
- 实例未运行/已停止/启动中：`ErrPluginNotRunning`。
- 健康状态不是 `healthy`：`ErrPluginUnhealthy`。
- Manifest 未声明 `ui`：新增 `ErrPluginNoUI`。

不返回完整 `Instance`，避免把配置和内部状态带到 HTTP 层；地址来自实例记录的 `InternalAddress`，与现有调用路径一致。

### 3. `internal/httpserver/plugin_proxy.go`

新增文件，职责：

- 解析 `{id}` 与剩余路径，调用 `ProxyTarget`。
- 使用共享 `http.Transport` 的 `httputil.ReverseProxy`，按请求创建轻量代理对象。
- `Director`：设置上游 scheme/host，拼接 `ui.path` 与剩余路径，保留原始查询串；设置 `X-Forwarded-*`；`Host` 使用上游地址，原始 Host 放进 `X-Forwarded-Host`。
- `ModifyResponse`：把上游根绝对路径的 `Location`、`Content-Location` 改写为带代理前缀的地址；其他来源不改写。
- `ErrorHandler`：记录日志并返回 `502`。
- 进入代理前删除 `SecurityHeaders` 写入的 `Content-Security-Policy` 与 `X-Frame-Options`，保留 `X-Content-Type-Options: nosniff`；上游自带的安全头正常透传。
- 上游错误页与 Lan Copy 错误页区分：代理失败返回代理错误页，不伪装成 Lan Copy 业务错误。

### 4. `internal/httpserver/routes.go`

```go
// 子树路由，由处理器内部解析 ID 与剩余路径，避免通配符边界差异。
mux.Handle("/plugin-app/", http.HandlerFunc(s.pluginUIProxy))
```

不套用 `X-Lan-Copy-Action` 或同源校验：代理页面是插件自己的同源应用，写请求由插件自行防护。

### 5. 传输配置

- `ResponseHeaderTimeout: 60s`，`IdleConnTimeout: 90s`，`MaxIdleConnsPerHost` 使用合理默认值。
- 不跟随上游重定向，交给浏览器。
- 保持 `FlushInterval = -1`。
- 连接复用限制在插件实例维度，插件停止后连接自然关闭。

## 前端

- `frontend/src/api/plugins.ts`：`PluginManifest` 增加 `ui?: { path?: string }`。
- 插件卡片：当 Manifest 声明 `ui` 且实例 `running` 且 `healthy` 时显示“打开界面”按钮，`target="_blank"`、`rel="noopener"`，地址为 `/plugin-app/{id}/`；否则按钮禁用并说明原因（未运行/不健康/无界面）。
- 详情弹窗：显示对外地址，提供“打开”和“复制地址”操作，并提示“局域网设备使用同一地址访问”。
- “对接”页新增“插件 Web 界面”卡片：展示 Manifest `ui` 声明示例、入口格式、`X-Forwarded-Prefix` 约定和运行/健康限制；“复制对接说明”生成的 Agent Prompt 同步包含该章节。
- 不把插件界面嵌入 iframe：避免两套滚动与键盘焦点冲突，也让插件页拥有独立历史记录。
- 测试覆盖：按钮出现条件、停止状态、无 `ui` 的插件、地址拼接。

## 安全边界

| 项 | 方案 |
| --- | --- |
| 代理目标 | 只允许 Lan Copy 管理的运行中实例，不接受任意 URL |
| 路径校验 | 插件 ID 走现有正则；剩余路径不允许绕过前缀和 `..` |
| 上游地址暴露 | 错误页与响应不返回容器名、宿主端口或内部错误 |
| 响应头 | 代理路由移除 Lan Copy 的 CSP/X-Frame-Options，交由插件页面自行声明 |
| 认证 | 沿用局域网无登录模型，默认开放，文档明确提示只安装可信镜像 |
| 同源风险 | 插件页面与 Lan Copy 同源，页面脚本可携带动作头调用管理 API；必须在协议文档和插件页提示，后续可评估独立端口隔离 |
| 生命周期 | 停止、不健康时立即拒绝代理，避免把请求打到旧端口 |

同源风险是本版最需要明确的取舍：子路径代理让插件界面获得 Lan Copy 的 Origin。安装插件本身已经意味着信任该镜像，但“镜像只能通过受限令牌访问表格”与“其页面可以在浏览器里调用完整管理 API”不是同一级别的信任。本版按已确认决策默认开放，并在文档中写清；如果后续需要更强隔离，再设计独立监听端口方案。

- 前端 `npm run typecheck`、`npm test`、`npm run sync-assets`、`npm run check-assets`

新增测试：

2. Manager：未安装、未运行、不健康、无 `ui`、正常返回目标地址。

- 插件停止后返回 503，重启恢复后可继续访问。
- 深链接刷新、静态资源、上传、SSE/WebSocket 正常。
- 插件管理页原有的安装、启动、停止、事件、表格功能无回归。

## 风险与待确认

- 子路径兼容完全依赖插件配合；不读取 `X-Forwarded-Prefix` 的旧插件只能在根路径工作，无法通过本入口正常使用。
- Manifest 新增字段导致新镜像无法导入旧版 Lan Copy，发布说明需标注最低版本。
- 同源风险见安全边界；如果默认开放后收到安全反馈，再评估独立端口。
- Lan Copy 自身被外部反向代理挂到子路径时，`/plugin-app/...` 的绝对地址需要外部代理同步改写；本版不处理这种部署。
