# Lan Copy v0.10.0 智能表格计划

更新日期：2026-11-19。状态：**已批准并完成实现，自动化验证通过，待人工验收**。

## 背景与目标

共享目录里的 CSV 目前只能作为普通文件下载或预览，缺少结构化查询、并发安全的更新入口，插件也无法在不直接挂载共享目录的前提下读写表格。

v0.10.0 增加“智能表格”：

1. 共享目录中的 `.csv` 文件直接成为表格，不需要额外元数据或导入步骤。
2. 新增 `/tables` 页面，可浏览、搜索、筛选、排序、分页，并进行基础行编辑。
3. 新增插件专用 API：查询表格，以及一次请求内完成加锁、版本校验、更新、写回和解锁的 `lock_and_update` 原子接口。
4. 安装插件时注入 `LAN_COPY_API_URL` 和每实例 API 令牌，插件无需挂载共享目录即可安全访问表格。
5. CSV 文件仍是唯一事实来源，写入使用同目录临时文件与原子替换；外部编辑、上传和插件更新共享同一版本号。

## 已确认的边界

- 主要入口：页面 + 插件 API。
- 更新接口：原子 `lock_and_update`，不暴露长事务锁。
- 表格识别：共享目录内 `.csv` 直接识别；第一行是列名。
- 插件访问：注入 API 地址与令牌，通过 HTTP 调用。

## 非目标

- 不做 SQL 引擎、关联查询、聚合、事务隔离级别或服务端索引。
- 不做多用户账号权限；沿用当前局域网无登录模型。
- 不做表格公式计算、单元格格式、图表或多人协同光标。
- 不把插件直接挂载到共享目录。
- 首期不推送 `table.updated` 生命周期事件，避免插件更新触发自身循环；后续可单独设计。
- 不改变现有普通文件上传、删除和文本存储语义。

## CSV 模型与限制

| 项 | 规则 |
| --- | --- |
| 文件类型 | 仅共享根目录内扩展名为 `.csv` 的普通文件；拒绝符号链接、越界路径和保留名 |
| 编码 | UTF-8；允许并保留 UTF-8 BOM |
| 分隔符 | 逗号；支持 RFC 4180 引号、字段内逗号和换行 |
| 换行 | 识别并保留原文件主要换行符（LF/CRLF） |
| 表头 | 第一行必须是列名；空列名或重复列名返回 400，并指出列号 |
| 空文件 | 页面新建时允许提供列名并生成只有表头的 CSV |
| 行宽 | 数据行列数与表头不一致时返回 400，并指出行号，避免静默丢列 |
| 大小 | 单文件 ≤ 8 MiB，≤ 50,000 数据行，≤ 200 列，单元格 ≤ 64 KiB |
| 版本 | 文件字节的 SHA-256，读取和更新都返回；更新必须提交 `expectedVersion` |
| 写入 | 同目录临时文件、fsync、原子 rename；失败不改变原文件 |

CSV 写入会规范化引号和换行，但不改变字段内容和列顺序。页面展示与 API 返回的都是字符串；比较和排序在需要时自动识别数字。

## 表格存储边界

新增 `internal/tablestore`，负责 CSV 解析、查询、行操作、序列化和版本校验；路径校验、文件锁和原子写入仍由 `internal/filestore` 负责。

`filestore` 新增窄接口：

```go
type FileSnapshot struct {
    Data    []byte
    Version string
}

// SnapshotFile 在文件锁内读取普通文件并计算版本。
func (s *Store) SnapshotFile(name string, maxBytes int64) (FileSnapshot, error)

// UpdateFile 在文件锁内读取、调用 fn、原子写回；fn 返回错误时不写文件。
func (s *Store) UpdateFile(name string, maxBytes int64, fn func([]byte) ([]byte, error)) (FileSnapshot, error)

// CreateFile 以 O_EXCL 创建普通文件，已存在时返回 fs.ErrExist。
func (s *Store) CreateFile(name string, data []byte) (FileSnapshot, error)
```

- 复用现有 `Path`、`ValidateComponent`、锁和 `notifyFilesChanged` 语义。
- 表格更新期间持有现有文件锁，保证与上传、删除、重命名互斥；不新增第二套文件锁。
- 更新成功后由 HTTP 层通知文件变更，表格页面和文件列表刷新。

## 查询模型

`POST /api/tables/query`：

```json
{
  "path": "data/orders.csv",
  "q": "pending",
  "filters": [{ "column": "status", "op": "eq", "value": "pending" }],
  "sort": { "column": "updatedAt", "order": "desc" },
  "limit": 100,
  "offset": 0
}
```

响应：

```json
{
  "path": "data/orders.csv",
  "version": "sha256:...",
  "columns": ["id", "status", "updatedAt"],
  "rows": [
    { "_row": 2, "values": { "id": "A-1", "status": "pending", "updatedAt": "2026-11-19" } }
  ],
  "total": 1,
  "offset": 0,
  "limit": 100
}
```

- `q` 在全部列中做不区分大小写的包含匹配。
- `filters` 支持 `eq`、`neq`、`contains`、`prefix`、`gt`、`gte`、`lt`、`lte`、`empty`、`not_empty`。
- 单列排序；数值列按数值排序，否则按字符串排序。
- `limit` 默认 100，最大 500；`offset` 最大 1,000,000。
- `_row` 是 CSV 中的数据行号（表头后的第 1 行是 1），用于页面定位，不作为并发更新的唯一标识。

## lock_and_update

`POST /api/tables/lock-and-update`（插件侧为 `POST /api/plugin-api/tables/lock-and-update`）：

```json
{
  "path": "data/orders.csv",
  "expectedVersion": "sha256:...",
  "keyColumn": "id",
  "operations": [
    { "kind": "insert", "values": { "id": "A-2", "status": "new" } },
    { "kind": "update", "key": "A-1", "changes": { "status": "done" } },
    { "kind": "delete", "key": "A-3" }
  ]
}
```

语义：

- 一次请求内加锁、读取、校验 `expectedVersion`、校验全部操作、写回、释放；任何一步失败都不写文件。
- `update` 和 `delete` 必须使用唯一 `keyColumn`；`keyColumn` 必须存在且值唯一，否则返回 409 并说明原因。
- `insert` 可省略列，省略的列写空字符串；未知列返回 400。
- 单次最多 1,000 个操作；更新后的文件仍受大小限制。
- 返回：

```json
{
  "path": "data/orders.csv",
  "version": "sha256:...",
  "applied": { "inserted": 1, "updated": 1, "deleted": 1 }
}
```

- 版本冲突返回 409，响应包含当前 `version`，客户端应重新查询后重试。
- 页面编辑复用同一接口，由浏览器提交 `X-Lan-Copy-Action: tables`。

## 页面

新增 `/tables` 页面和顶栏入口：

1. 左侧列出共享目录中的 CSV（路径、大小、修改时间），支持搜索。
2. 主区域展示列头、行号、分页和总行数；“查询”支持全文搜索、列筛选、排序。
3. 基础编辑：单元格编辑、整行新增/删除；保存时提交当前版本，冲突后提示“文件已被其他设备或插件修改”，可重新加载。
4. 新建表格：输入文件名和列名，创建只有表头的 CSV；文件名走共享目录校验。
5. “插件 API”帮助卡：展示 `LAN_COPY_API_URL`、`LAN_COPY_API_TOKEN`、查询与 `lock_and_update` 示例和错误码。
6. 空状态、加载失败、只读/无权限和超大文件提示清晰；不显示无法执行的按钮。

## 插件 API 接入

### 环境变量

安装/重建容器时注入：

```text
LAN_COPY_API_URL=http://host.docker.internal:8080
LAN_COPY_API_TOKEN=<每实例派生令牌>
```

- 令牌由 `SecretBox` 密钥和实例 ID 派生，不写入 `state.json`，不复用事件签名密钥。
- `LAN_COPY_API_TOKEN` 加入保留变量名，用户配置不能覆盖。
- 插件令牌只能访问 `/api/plugin-api/tables*`，不能访问插件管理、文件、更新或关停接口。
- 令牌校验使用常量时间比较；停止的实例令牌不生效。
- API 地址由启动参数 `-plugin-api-url` 覆盖；未设置时：
  - `loopback`：`http://host.docker.internal:<监听端口>`；
  - `container`：`http://lan-copy:<监听端口>`，与现有文档中的容器名约定一致。

### 容器访问

- `loopback` 模式为插件容器增加固定 `host.docker.internal:host-gateway` 的 `ExtraHosts`，让 Linux Docker 也能访问宿主机；Docker Desktop 自带该解析。
- 只允许这一个固定映射，仍禁止用户提供任意 `ExtraHosts`、DNS、Host 网络或 Docker Socket。
- 若 Lan Copy 只监听 `127.0.0.1`，Linux 上插件可能无法访问；文档要求使用可被容器访问的监听地址，或用 `-plugin-api-url` 指向可达地址。

### 鉴权

```http
Authorization: Bearer <LAN_COPY_API_TOKEN>
```

- 401：缺少或无效令牌。
- 403：令牌有效但插件未运行/健康异常（如需要）或访问了非表格 API。
- 插件 ID 记入日志和更新结果，便于排查。

## HTTP API

| 方法 | 路径 | 访问 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/tables` | 局域网 | CSV 列表 |
| POST | `/api/tables/query` | 局域网 | 查询、筛选、排序、分页 |
| POST | `/api/tables/lock-and-update` | 局域网 + `X-Lan-Copy-Action: tables` | 原子加锁更新 |
| POST | `/api/tables/create` | 局域网 + `X-Lan-Copy-Action: tables` | 新建空表 |
| GET | `/api/plugin-api/tables` | 插件令牌 | 插件侧 CSV 列表 |
| POST | `/api/plugin-api/tables/query` | 插件令牌 | 插件侧查询 |
| POST | `/api/plugin-api/tables/lock-and-update` | 插件令牌 | 插件侧原子更新 |

- 页面接口沿用当前局域网无账号模型；写操作要求动作头和同源校验（`validActionRequest`）。
- 插件接口使用 Bearer 令牌，不要求动作头或同源。
- 请求体上限 2 MiB；错误统一返回 `{error, code?, version?}`。
- 路径无效、非 CSV、文件不存在、文件过大、表头无效分别返回明确的 4xx。

## 安全与兼容性

- CSV 仍是共享目录普通文件；页面与插件都只能访问共享根目录内 `.csv`，不访问应用数据目录或插件挂载目录。
- 插件令牌仅授权表格 API；令牌不进入视图、日志或任务结果，实例重装后轮换。
- 所有写入在文件锁内完成并原子替换；版本冲突不会覆盖他人修改。
- 不执行 CSV 内容、公式或宏；页面使用文本渲染。打开外部 CSV 时的公式风险由用户自担，文档提示。
- 不改变 `state.json` 格式；新增环境变量为运行时注入。
- 现有 `/api/plugins`、`/api/files`、文本和生命周期事件行为保持兼容。

## 验收标准

- 共享目录内任意合法 CSV 能在 `/tables` 浏览、搜索、筛选、排序和分页，表头与行号正确。
- 页面可新增/编辑/删除行；并发修改时返回 409 并要求重新加载，不丢数据。
- `lock_and_update` 在版本正确时原子应用全部操作；任一操作失败时文件完全不变。
- 插件通过注入的地址和令牌能查询、更新表格；无令牌、错误令牌、停止实例和非表格 API 被拒绝。
- CSV 引号、字段内换行、BOM、CRLF 和大文件限制均有测试覆盖。
- 三平台构建、Go 全量测试、前端测试和资源同步通过。
