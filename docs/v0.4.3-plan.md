# Lan Copy v0.4.3 计划

## 目标

将文件列表现有的行级右键菜单扩展为全局一致的上下文菜单：用户在共享文件、共享文本和页面空白区域按右键时，能获得与当前位置匹配的操作；菜单不覆盖浏览器在输入、文本选择和链接上的原生能力。菜单复用现有业务操作，不新增服务端 API 或文件操作语义。

## 现状与范围

- `web/filesystem.js` 已为文件/文件夹行提供右键菜单和“⋯”按钮，支持打开/预览/下载、移动、重命名、删除、复制路径；菜单只绑定在文件行。
- `web/app.js` 的共享文本条目有复制、删除按钮，但没有右键菜单。
- 页面级可复用的菜单容器目前只有 `web/index.html` 中的 `#fileMenu`。
- 本版扩展为共享空间与文本快传页面共用的全局上下文菜单能力。设置弹窗、原生文件选择器、预览内容及浏览器自身 UI 不属于自定义菜单目标。

## 1. 统一菜单触发与上下文

- 建立一个全局上下文菜单控制器，监听页面 `contextmenu`，根据最近的语义目标构造菜单；文件行“⋯”按钮继续保留，作为触屏和无右键设备的等价入口。
- 菜单由统一的菜单渲染、定位、键盘导航和关闭逻辑管理；各页面只提供上下文与可用动作，不复制一套菜单 DOM/交互。
- 上下文分为：文件/文件夹、共享文本条目、可操作页面空白区。点击右键的具体条目优先；文件行按现有规则更新选择，再按所选集合生成菜单。已多选时右键未选中的条目只选择该条目，避免误把旧选择作用于新目标。
- 菜单动作执行前按稳定 ID/path 重新获取最新条目；条目已被外部移动或删除时提示并刷新，不对陈旧 DOM 或过期选择执行写操作。
- 页面空白处菜单仅展示当前页面有意义的少量操作，不提供通用浏览器命令：共享空间提供刷新列表、复制当前页面地址、回到全部文件（仅在子目录）；文本快传提供刷新共享文本、聚焦文本输入框、复制当前页面地址。无效或不可用动作禁用或不显示。
- 页面导航、搜索、目录变化和数据刷新时，清除失效上下文；右键菜单不改变文件列表当前的排序、滚动位置或页面 URL。

## 2. 文件与文件夹菜单

- 单个文件沿用已有能力：预览或下载、打开所在文件夹（按当前 localhost/LAN 访问策略）、移动、重命名、删除、复制路径。
- 单个文件夹提供：打开、移动、重命名、删除、复制路径。
- 多选只显示当前已有语义支持的批量动作：复制所选路径、下载所选文件（仅文件且按浏览器逐项下载策略可行时）、删除所选项（需明确逐项/批量确认语义后实施）。首版不将单项重命名或移动伪装成批量操作；若现有后端无安全原子批量能力，菜单只提供复制路径，不新增批量写接口。
- 空目录或空白处右键只提供页面级操作，不凭空显示文件操作。搜索结果使用已有条目路径执行动作，打开/移动目标不因搜索而错误地变为搜索结果父目录。
- “打开”“预览”“下载”等操作继续走现有 `openEntry`、预览器和 `/files/` 下载路径；移动、重命名、删除继续复用既有确认和 API 处理。

## 3. 共享文本菜单

- 共享文本条目右键菜单提供“复制文本”和“删除文本”；删除继续复用现有确认弹窗及文本删除 API。
- 点击某条文本的右键或操作按钮时，将上下文绑定到文本 ID，而不是列表序号或可变 DOM 顺序；ID不存在时关闭菜单并刷新列表。
- 文本内容可被鼠标选中复制。若用户在文本选区上右键，优先保留浏览器原生“复制”等选区菜单；当没有选区且命中条目时才显示 Lan Copy 菜单。
- 文本输入区、搜索框、设置表单及所有可编辑控件保留浏览器原生右键菜单，保证剪切、复制、粘贴、输入法和拼写检查可用。

## 4. 原生行为与自定义菜单边界

- 不在 `input`、`textarea`、`select`、`[contenteditable]`、链接、按钮、预览内容、对话框或浏览器原生控件上拦截原生菜单；已有专属“⋯”按钮可显式打开 Lan Copy 菜单。
- 页面文字有非折叠选区时保留原生选择菜单；用户在可复制正文或文本条目上选择内容后不弹出自定义菜单。
- 在文件列表表头、面包屑按钮、导航链接、分享/状态按钮和操作控件上保留其浏览器及控件预期行为，不通过全局 `preventDefault()` 抢占。
- 仅当全局处理器确认上下文属于空白页面区域或可识别的文件/文本项目，并且没有上述原生行为优先条件时，才阻止默认菜单。
- 右键菜单不拦截拖放、触控长按滚动、系统手势或浏览器快捷键；移动设备依靠现有可见操作按钮访问相同功能。

## 5. 菜单交互、可访问性与视觉

- 使用 `role="menu"` / `role="menuitem"`，菜单仅含可执行项及必要分隔组；不可用项使用原生 `disabled`。
- 打开后聚焦第一项；支持上/下方向键、Home、End、Enter/Space、Escape。关闭后焦点回到触发按钮或对应文件行；页面空白右键关闭后不强行移动焦点。
- 点击菜单外、执行动作、页面滚动、窗口失焦、目录导航或弹窗打开时关闭菜单；Escape 关闭后不清除选择。
- 菜单按视口边缘翻转和限位，支持窄屏与浏览器缩放，不遮住指针对应项目的主要名称；菜单内长文案可读、不横向溢出。
- 视觉沿用当前文件菜单的颜色、圆角、阴影、危险操作标识和焦点样式；共享文本菜单与页面空白菜单使用同一组件样式。

## 6. 实施位置与步骤

1. 在 `web/index.html`、`web/transfer.html` 中接入唯一全局菜单容器及必要脚本；或将共享菜单能力放入现有适合的前端模块，避免创建只包一两个函数的空泛抽象。
2. 在 `web/filesystem.js` 中把当前文件菜单的上下文构造与动作分发接入统一菜单控制器，保留文件行“⋯”入口与现有动作实现。
3. 在 `web/app.js` 中为共享文本条目注册上下文提供器，按 ID 提供复制和删除动作，并保留文本选中与原生菜单。
4. 在 `web/style.css` 统一菜单样式、视口定位、窄屏约束与焦点表现；移除重复或冲突的旧菜单规则。
5. 对照权限、确认弹窗、访问来源限制和页面事件生命周期检查所有右键路径，不改服务端 API、数据格式或文件系统行为。

## 验收

- 在文件/文件夹上右键，菜单动作、单选/多选语义与现有“⋯”菜单一致；移动、重命名、删除及预览仍调用原流程。
- 在共享文本条目上右键可复制/删除；选中文本后浏览器原生复制菜单可用。
- 在两页面空白处右键只显示各自合适的页面操作；无选择时不出现文件操作。
- 输入框、文本域、链接、表头、导航、预览内容和设置控件仍能使用原生上下文菜单。
- 菜单在屏幕四边、窄屏、放大显示和滚动时位置正确；鼠标、键盘和触屏等价入口均可完成操作，焦点返回合理。
- 数据被 SSE 更新、删除或移动后，旧菜单上下文不会执行错误操作；外部更新和搜索状态下动作目标正确。
- 不新增 API 或第三方前端库；保持单进程、单二进制与嵌入式前端兼容。
