# Lan Copy v0.2 实施进度

按 `docs/v0.2-plan.md` 的建议顺序跟踪。状态反映当前工作区代码；尚未完成的计划项不会视为已验收。

## 已完成

### 1. 名称冲突处理的错误返回与重试上限

- `availableName` 在候选名不存在时返回名称；遇到权限等文件系统错误时直接返回错误。
- 冲突编号从 `(2)` 到 `(10000)`，超过上限返回 `fs.ErrExist`，避免无界循环。
- 添加错误传播与冲突上限回归测试。
- 名称查询出错时上传会清理事务暂存内容并返回错误。

### 5. 文本存储容量与替换保护（基础实现）

- 新增最多 1,000 条文本及 JSON 文件最多 16 MiB 的限制；单条仍限制为 64 KiB。
- 写入临时文件后同步并关闭；替换过程保留旧库备份，并同步目录项。新库落位或目录同步失败时尝试恢复旧库。
- 启动时恢复旧库备份、清理过期备份，并识别和清理中断留下的文本临时文件；相关异常写入标准应用日志。
- 增加写入、文件同步、改名、目录同步失败注入测试，验证旧库仍可读取；增加启动恢复和临时文件清理测试。
- Windows 通过文件同步保证内容写入；`os` 不提供可移植的 Windows 目录句柄同步，因此目录项断电持久性仍受平台限制。

### 9. 测试入口与 CI 对话框覆盖（部分）

- `make test` 统一调用 Python、现有 Node 前端脚本和 Go 测试。
- CI 增加 `scripts/test-dialog.cjs`。
- 调整对话框和设置测试以适配当前设置面板的更新检查时机及关闭按钮依赖。
- 前端仍有基于源码片段执行的脆弱测试，模块化和真实 DOM 覆盖尚未完成。

### 2. 上传统一与提交恢复

- 普通文件和目录上传统一走 `/api/upload-tree`；旧版 `/api/upload` 路由及逐文件直接提交实现已移除。当前前端原本就统一使用树上传协议。
- 所有请求内容先写入隐藏事务目录。普通文件遇到同名目标会沿用编号命名；目录替换仍需用户确认。
- 替换备份与提交清单放在暂存目录旁。提交中进程退出时，启动恢复按暂存、目标和备份的实际状态回滚；完成标记已落位的事务则只清理备份；没有提交记录的未完成接收目录会清理。
- 回滚自身失败时保留事务目录和备份，交由下次启动恢复；增加中断恢复及旧端点移除测试。
- 运行约束：恢复以应用锁内操作和同一文件系统的原子改名为边界；本机其他进程直接并发修改共享目录不受此事务保证。

### 3. 关停、更新与在途请求

- 建立应用级 context；SSE 同时监听请求取消和应用关停。
- 网页关停仅接受 loopback 来源且 Host 为 localhost/loopback 的请求，不验证操作系统管理员身份；新增关停状态接口。
- 上传和文件/预览下载纳入在途计数。关停确认与计数在同一互斥区内原子执行，确认后停止新传输，避免状态查询与关停之间的竞态。
- 提交关停时回传操作者确认过的上传/下载数量；若数量与服务端实时计数不符，服务端拒绝本次确认并要求界面展示新数量后再确认。
- 有在途传输时先显示上传/下载数量和中断风险，再要求操作者输入“强制关闭”；没有在途请求时进行普通确认。若首次无传输确认后出现新请求，服务端返回最新计数并要求补充确认。
- 网页、更新和系统信号共享关停流程。系统信号/更新会记录在途数量并等待最多 5 秒，超时后记录强制关闭时的剩余数量。
- 增加传输计数、确认口令、localhost 限制和对话框输入测试。

## 尚未完成（按建议顺序）

### 1. 共享锁范围

- 文件操作使用 `fileMu`，文本存储使用 `textMu`，文本请求不会再等待文件操作锁。
- 文件列表和目录列表不再持有文件操作锁进行磁盘遍历；排序及 HTTP 响应写出也在锁外完成。列表是尽力读取，若应用内变更在遍历期间移除条目则跳过该条目，客户端可刷新获取新状态。
- 递归目录搜索监听请求 context，并在遍历超过 10,000 项时返回明确的范围错误；普通目录浏览仍只列出当前层级。
- 文件变更仍由文件锁串行提交；列表不承诺与并发变更构成原子快照。外部进程直接改动共享目录仍不在支持保证内。
- 增加列表不依赖文件锁、搜索预算和取消请求的回归测试。

### 4. 路径策略与内部数据隔离（路径规则部分完成）

- 上传清单、路径解析、目录创建/移动/改名和所有基于 `sharedPath` 的读取/删除入口共用组件校验规则。
- 保留前缀统一按大小写不敏感方式屏蔽；拒绝 Windows 保留设备名、非法路径字符及尾点，避免跨平台路径含义不同。
- 增加路径解析与名称校验测试，覆盖保留名前缀大小写变体及 Windows 设备名。
- 文档明确：本机其他进程直接并发改动共享目录不受应用内路径预检保护；当前应用路径级文件操作无法消除预检后的外部替换竞态。
- 尚未迁移文本库、上传暂存和恢复记录到共享目录之外，也未实现基于目录句柄的安全操作。

### 5. 文本存储

- 容量限制、备份替换、目录同步、失败注入和启动清理已完成；文本过期保留策略仍由产品需求决定。
- 上传使用随机事务 ID 和接收阶段记录。启动发现没有提交记录的事务时，记录异常日志并清理暂存内容；残留代表上传未确认完成，不会作为有效共享文件公开。
- 上传暂存文件在提交前同步内容；事务接收和提交阶段的异常与恢复结果写入应用日志。事务 ID 不从目标路径派生，避免同路径并发上传冲突。

### 6. 上传全局资源预算

- 并发上传数、暂存空间预算、读取空闲超时和目录上传预检协议均未实施。

### 7. 内部模块边界

- HTTP、文件服务、存储、生命周期和事件职责仍主要集中在现有包与处理器中。

### 8. 变更通知与前端取消

- 尚未统一文件与文本事件格式，也未为目录切换、搜索和页面隐藏接入请求取消及刷新合并。

### 9. 测试维护性

- 已补齐统一 `make test` 命令和 CI 对话框测试；前端测试解耦、DOM 交互覆盖及文档入口更新仍待处理。
