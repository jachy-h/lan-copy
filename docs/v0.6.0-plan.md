# Lan Copy v0.6.0 计划

## 背景与目标

Lan Copy 已有 HTTP 服务、文件与文本共享 API、局域网访问地址面板和动态设置弹窗，但没有标准 MCP 接口。用户希望 AI 客户端能够通过 MCP 访问当前运行的 Lan Copy，也希望能从设置中快速看懂连接方式并复制所需配置。

v0.6.0 增加基于 HTTP 的 MCP 服务，并在设置导航中增加带 AI 图标的“AI”入口。用户可查看 MCP 的用途、当前服务地址、可用工具与访问边界，并复制端点或客户端连接配置。MCP 调用复用现有文件/文本组件和访问策略，不另建存储、不绕开共享目录边界。

## 现状与边界

- 设置弹窗由 `web/settings.js` 动态生成；当前页签为“关于、通用、上传、更新”。页签使用 ARIA tablist，支持方向键切换。
- `/api/access` 提供当前页面来源及局域网访问地址；设置中的 `/api/app` 提供版本和运行平台信息。
- HTTP 路由与安全头集中在 `internal/httpserver/routes.go`；文件和文本能力分别通过 `filestore`、`textstore` 等组件提供。
- 现有服务支持从 localhost 和局域网设备访问，未提供通用用户登录认证。新增 MCP 端点会继承服务当前的网络可达范围，不能把它描述成仅限本机的接口。
- 不改变当前文件/文本 API、存储格式、路径规则和恢复语义。MCP 只作为新协议入口调用已有能力。

## 设计原则

1. **采用标准 HTTP MCP 传输。** 使用 MCP Streamable HTTP，一个稳定的 `/mcp` 端点处理协议请求；协议与 JSON-RPC 细节交由成熟的 Go MCP SDK 处理，实施前评估 SDK 的维护状态、许可和依赖体积。不要新实现私有 JSON-RPC 变体。
2. **用户能直接连接当前服务。** 地址使用当前服务的 scheme、host、port 与 `/mcp` 路径，不硬编码 `localhost`、默认端口或某个网卡地址；展示并复制可访问的 LAN 地址。
3. **先提供范围清楚的工具。** 首版工具聚焦共享空间中的列表、搜索、元信息和读取，以及共享文本的查询。工具只访问 Lan Copy 管理的共享内容；不暴露任意本机路径、管理数据目录、上传暂存目录或进程控制能力。
4. **MCP 层做协议适配。** 参数 schema、协议错误和 MCP 工具注册归 MCP 适配层；业务规则和持久化继续由既有组件负责，HTTP 层负责 Origin/访问校验与 HTTP 响应。
5. **不给客户端制造假的“已连接”状态。** 设置页展示端点、当前服务状态和工具说明；复制配置只表示内容已复制，不以浏览器自身探测代替真实 MCP 客户端握手。

## MCP 服务能力

### 传输与端点

- 提供单一 `GET/POST /mcp` HTTP 端点，按 MCP Streamable HTTP 规范处理客户端请求；是否支持 SSE 响应由所选 SDK 和首版实际需要决定。
- 优先采用无会话的请求处理模式，除非所选 MCP SDK 或所需能力明确要求会话。避免把已有的文件 SSE 变更接口 `/api/events` 误作 MCP SSE 传输。
- 对不支持的方法返回正确的 HTTP 状态；按规范检查请求和响应的 `Content-Type`、`Accept`、协议版本及 JSON-RPC 消息结构。
- 工具列表顺序固定，工具名、参数和结果 schema 稳定；返回结果适合 AI 直接理解，并对文件路径、数量和文本大小设置与现有服务一致或更严格的边界。
- 第一版工具建议：
  - `list_files`：列出共享目录或指定相对目录的条目，支持受限分页/数量上限。
  - `search_files`：在共享空间中按名称搜索，沿用现有递归范围和路径约束。
  - `get_file_info`：返回文件/文件夹元信息，不泄露共享目录之外的绝对路径。
  - `read_text_file`：读取允许预览的文本内容，设置响应大小上限并返回截断提示；二进制文件只返回类型和大小等元信息。
  - `list_shared_texts`：读取用户主动保存的共享文本，结果遵守现有文本存储范围和容量限制。
- 每个工具提供清楚的描述、必填/可选参数、错误语义和只读标注。首版不提供上传、覆盖、移动、重命名、删除、关闭服务、设置修改或软件更新工具。
- MCP 工具通过既有组件执行，而不是从 HTTP handler 中复制路径校验和文件读取实现。若需要组件新方法，应按实际调用方定义最小接口。

### 安全与访问策略

- 所有请求验证 `Origin`：缺失时按 MCP 规范允许的客户端请求策略处理；存在但不属于合法服务来源时返回 403。覆盖 DNS rebinding 防护，并测试 HTTP 与 HTTPS、localhost、IPv4、IPv6 和 LAN hostname 情形。
- 绑定行为沿用 Lan Copy 当前监听设置和可访问范围。设置页明确提示：“允许访问此 Lan Copy 的设备，也可能连接 MCP 并读取共享内容”；不要让“AI”图标产生仅本机可用的错觉。
- 不新增匿名管理能力。首版仅暴露共享文件与共享文本的只读工具，且继续应用相同的路径校验、保留名称、符号链接防护、数据大小限制和文件访问边界。
- 不把 MCP 配置复制内容当作秘密令牌；复制片段不包含应用数据目录、主机本地绝对路径、密钥或隐式凭证。
- 考察跨源浏览器调用、私有网络访问/CORS 及 Host 校验边界。MCP 客户端可能不是浏览器，但服务端不能因“给 AI 用”而放宽现有安全头或跨站请求规则。
- 若后续需要写入或管理类工具，须单独设计授权、用户确认和审计策略，不随只读工具顺手开放。

## 设置中的“AI”页面

### 左侧入口与页面结构

- 在设置弹窗左侧导航增加“AI”项，配简洁的 AI/节点图标和可读文本；图标必须有文字名称与可访问标签，不能只靠图形辨认。
- 保持现有 tablist 的键盘导航与窄屏布局。AI 页作为独立 tabpanel，不新开设置弹窗或外部站点。
- 页面包含：MCP 状态说明、端点地址、服务可访问地址选择、工具能力列表、安全提示、复制动作及帮助链接。

### 地址展示与复制

- 默认显示当前浏览器正在访问的服务 origin 拼接 `/mcp`，即对当前设备最准确的连接地址。若当前来源为 `localhost`，同时列出 `/api/access` 返回的局域网地址供其他设备选择。
- 地址选择器根据 `/api/access` 的当前结果生成；IPv6 地址正确加方括号，使用正确的 scheme 和端口。无可用局域网地址、API 请求失败或页面离线时显示明确状态，不生成看似有效的虚构地址。
- 提供“复制 MCP 地址”按钮，复制所选端点；另外提供“复制通用 HTTP 配置”按钮，复制带有该端点的简洁 JSON 配置片段。界面标注这是一段可粘贴到兼容 MCP 客户端中的 HTTP server 配置，具体入口名称可能因客户端不同而异。
- 复制成功/失败均给出状态提示。使用 Clipboard API，并沿用现有的 `LanCopyFileUI.copyText` 降级路径。
- 以代码块展示一条直接使用端点地址的示例，并提供“复制”快捷按钮；避免把同一 MCP 服务伪装成需要启动子进程的 stdio 配置。
- 在页面直接列出工具名称、用途、只读状态和关键参数。MCP 客户端握手/工具发现属于客户端操作，设置页说明“复制地址后在客户端添加，再由客户端读取工具列表”。

### 连接状态和可解释性

- 服务启用时显示“HTTP MCP 可用”和端点；若 MCP 初始化/组装失败，应在服务启动日志和设置状态中可诊断，不能让主页或原 HTTP 服务因此不可启动。
- 如果首版不提供运行时开关，明确说明 MCP 随 Lan Copy HTTP 服务一起运行。若实现评估确认需要关闭开关，开关必须有明确默认值、持久化语义和关闭后的 404/405 行为，且地址仍不能误报可用。
- 设置页说明 MCP 可读取共享空间中的哪些内容，并提供直达项目文档/连接说明的链接。

## 结构与主要改动位置

- `internal/httpserver/routes.go`：挂载 `/mcp` 路由，并应用明确的 Origin/Host 校验策略。
- `internal/mcpserver/`（候选包名）：注册只读工具、JSON schema、MCP SDK transport 和到既有组件的调用。只有在真实实现开始时创建，不预建空包；依赖保持单向，业务组件不依赖 MCP 或 HTTP。
- `internal/app/`：创建并注入 MCP 适配器及其现有组件依赖；维持单进程、单 HTTP 服务和统一关停。
- `web/settings.js`：新增 AI tab、加载可达地址、展示工具信息、生成配置和复制反馈。
- `web/style.css`：AI tab 图标/布局、端点代码块、地址选择器、工具列表和窄屏样式。
- `docs/`：补充 MCP 客户端连接指南、安全范围、支持的工具及常见地址问题。

## 实施阶段

### 阶段一：协议与依赖选型

确认 MCP Streamable HTTP 稳定规范版本和兼容的 Go SDK。检查 SDK 对无会话模式、Origin 校验钩子、工具 schema、错误转换、取消和 SSE 的支持；评估依赖大小、许可证、维护状态与跨平台构建。

**验收：** 形成明确的 SDK/传输决策；使用官方 MCP Inspector 或兼容客户端完成本地握手和 `tools/list` 验证。规范以实现时官方稳定版为准，参考 [MCP Transports](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)。

### 阶段二：只读工具和 HTTP 挂载

实现 MCP 服务适配层和第一批只读工具。所有数据读取调用现有存储/文件组件；设置参数、资源限制、协议错误映射和请求取消；将端点挂入现有 HTTP 服务并保持普通页面/API 独立可用。

**验收：** MCP 客户端能发现工具并成功调用；非法参数、越界路径、缺失文件、过大文本、无效 Origin 和不支持的方法返回可诊断且不泄露本机绝对路径的错误。

### 阶段三：设置 AI 页面

增加左侧 AI 导航项、端点地址选择、工具说明、复制端点和通用配置片段。通过 `/api/access` 获取可达地址，不硬编码网卡；实现 Clipboard API 与降级复制，并覆盖加载失败、无 LAN 地址和移动端布局。

**验收：** 在 localhost 页面可复制本机端点和局域网端点；在 LAN 页面复制当前 host 的端点；粘贴的配置地址包含正确 scheme、IPv6 格式、端口与 `/mcp` 路径。

### 阶段四：安全、兼容和文档

验证不同来源的 MCP 客户端请求、DNS rebinding/Origin 拒绝、路径边界、服务关停、并发调用和跨平台构建；记录 MCP 客户端添加步骤和网络限制。

**验收：** MCP 请求不会绕过共享目录校验或上传/关停生命周期；原 Web UI 和 REST API 行为保持兼容；Windows、macOS、Linux 构建与对应受影响测试通过。

## 不做事项

- 不实现 stdio 子进程入口或需要用户单独安装的 MCP companion binary；服务由当前 Lan Copy HTTP 进程提供。
- 不将现有 `/api/events` 改造成 MCP 端点，也不以自定义 SSE 协议替代 Streamable HTTP。
- 不开放本机任意文件路径、应用数据目录、任意命令执行、关闭软件、软件更新或设置管理。
- 首版不提供改变共享文件/文本的 MCP 工具，不把模型发起的写操作变成无需用户确认的动作。
- 不引入账号系统、远程云服务或新的共享存储；如果未来需要互联网远程 MCP，应单独设计认证、TLS、授权和威胁模型。

## 完成标准

- MCP 兼容客户端可以通过当前 Lan Copy HTTP 服务端点完成协议初始化、工具发现和只读工具调用。
- 设置左侧有清楚可识别的 AI 入口；用户可了解工具能力及访问范围，并复制当前服务的 MCP 地址和通用 HTTP 配置。
- 地址来自当前页面 origin 和 `/api/access` 的实时结果，支持 IPv4、IPv6、HTTP/HTTPS、不同端口及无地址错误状态。
- MCP 只读取 Lan Copy 共享范围内的文件和文本，沿用现有组件边界与路径安全规则；无效 Origin 被拒绝。
- 设置页和文档清楚说明服务的局域网可达范围以及哪些设备能够读取共享内容。
- 保持单进程、单二进制、嵌入式前端、现有 HTTP API、数据格式及恢复语义兼容。
