# Lan Copy v0.5.0 计划：前端技术栈升级

## 目标与范围

将现有 HTML、原生 JavaScript 和全局脚本方案逐步替换为 **Vue 3 + TypeScript + Vite**，降低文件管理、设置、预览和实时状态的维护成本。升级以现有功能、视觉和交互等价为前提，不借迁移删减功能、改变权限或重做产品流程。

本文件替换此前 v0.5.0 的 MCP 服务与设置 AI 页面计划；MCP 不属于本版交付范围，后续另行规划。本文件是待实施计划，不代表前端迁移已完成，也不在本次文档修改中升级 VERSION。

必须继续保持：

- 单进程、单二进制、嵌入式前端，最终用户不安装 Node.js，不启动独立前端服务，不依赖 CDN 或互联网加载界面资源。
- 根目录 `go run .`、`go build .` 在干净检出且未安装 Node.js 时仍可使用；前端修改后的编译通过独立命令完成。
- HTTP API、页面地址、参数、文件与文本数据格式、上传事务、更新签名和恢复语义兼容。
- Windows、macOS、Linux 的运行与构建语义保持；Go 包边界继续遵守 AGENTS.md 与 v0.3 计划。

## 当前基础与迁移原则

当前 `web/` 包含三个页面入口：`index.html`、`transfer.html`、`preview.html`。页面依赖有顺序的普通脚本及 `window.LanCopy*` 全局对象。`filesystem.js` 同时管理目录、选择、键盘、上传、实时刷新和弹窗；`settings.js` 动态生成设置界面；`preview.js` 管理多种预览引擎及销毁。现有浏览器逻辑测试主要位于 `scripts/test-*.cjs`，使用 Node.js 和模拟 DOM。

1. **先记录基线，再切换实现。** 以实施开始时的实际工作区行为为基线，包含已落地的 v0.4.3/v0.4.4 功能；计划中的未实现能力不当作现有功能。先整理功能、截图、请求与测试对应关系。
2. **按功能边界迁移。** 先设置与公共组件，再共享空间，最后文本快传和预览；每阶段都有可运行结果和验收记录。
3. **界面与数据单向关联。** Vue 管理组件 DOM；请求、上传协议和预览引擎通过明确模块接入，避免新旧代码同时控制同一 DOM 或维护同一份状态。
4. **保留成熟实现。** 首轮保留二维码生成、目录收集、PDF/DOCX/表格解析及上传协议算法，转换为模块或适配器；不同时更换预览引擎或升级 vendor 版本。
5. **兼容是发布条件。** 不能仅凭新页面可打开或旧测试通过判定迁移完成；关键链路必须在真实浏览器和 Go 服务上验证。

## 技术方案

### 界面、类型与状态

- 使用 Vue 3 单文件组件和 Composition API，TypeScript 开启严格类型检查；API DTO 按现有服务端字段定义，保留可选字段、错误状态与 `requiresConfirmation` 等协议语义。
- Vite 采用多页面构建，保留三个 HTML 入口。首版不引入 Vue Router，不将现有地址改造成新的 SPA 路由。
- 每个页面维护自己的应用状态；用 composables 管理目录、选择、设置、实时刷新等内聚状态。暂不引入 Pinia 或额外请求状态框架；确有跨组件共享需求时再评估。
- API 模块统一编码路径、设置请求头和解析错误；组件决定展示与确认动作。写操作不自动重试，防止上传、删除、更新等操作重复执行。
- 保留原有 CSS 和品牌资源，逐步提取颜色、间距、字体等变量及局部组件样式。不同时引入大型 UI 库、Tailwind 或全新视觉体系。
- 文件名、路径、文本和错误消息按文本渲染；除受控的现有文档预览适配器外，不以 `v-html` 插入外部内容。Vue 使用预编译模板，运行时不依赖 `eval`。

### 目录与资源约定

以下为目标结构，随真实实现创建，不预建空目录：

```text
frontend/
  package.json、package-lock.json、tsconfig.json、vite.config.ts
  index.html、transfer.html、preview.html
  src/
    pages/          # 三个页面入口与页面组件
    components/     # 按实际复用提取弹窗、菜单、状态与分享面板
    composables/    # 功能状态、订阅和生命周期
    api/            # 现有 HTTP 协议与类型
    preview/        # 既有预览引擎适配与销毁
    styles/         # 公共样式和设计变量
  public/
    logo/、vendor/  # 原样复制的品牌与第三方资源
web/                # 已提交、可直接被 Go 嵌入的生产产物
assets.go           # 保留根目录嵌入入口
```

- 最终 `frontend/` 为人工维护的前端源文件，`web/` 为生成产物，禁止直接修改生成 JS/CSS。迁移期间未迁移页面仍可保留原实现，但每个路径必须有唯一来源。
- Vite 输出到临时目录，校验三个入口及依赖资源完整后再替换 `web/`；失败不删除已有可用资源。过渡期通过明确的复制清单合并旧页面和新产物，不能直接清空旧 `web/` 导致其他页面丢失。
- vendor、Worker、WASM、字体、CMap 等保持同源路径，完整复制嵌套目录，保留许可证、来源和完整性说明；源映射及开发文件不进入公开静态目录。
- Vue 模块仅加载一次；大体积预览引擎按需加载，不纳入共享空间和文本页的首屏依赖。
- 检查 `//go:embed web/*`、`fs.Sub`、静态 MIME、点目录默认嵌入规则与产物路径，不依赖未被嵌入的隐藏 manifest。优先让生成 HTML 直接引用产物，不新增 Go 模板渲染层。

### 构建与开发流程

**选择提交生产产物到仓库**，以保持 Go 原生入口兼容。仅增加 `go:generate` 或要求每次先运行 npm，不能满足无 Node.js 的干净检出要求。

- 固定 Node.js/npm 工具链和依赖锁文件；实施阶段记录实际选用版本，不使用浮动 latest。Node.js 仅用于前端开发、重建和一致性验证。
- 提供前端安装、开发、类型检查、测试、构建与产物一致性检查命令，并在 Makefile、Windows 构建脚本和开发文档中提供明确入口。
- Go 直接运行与构建使用已提交 `web/`；修改前端源码后必须重建并一起提交产物。开发文档明确这两种工作方式，避免误以为 Go 会自动编译 Vue。
- CI 在固定工具链下执行 `npm ci`、类型检查、测试和生产构建；校验重新生成的 `web/` 与提交内容一致，覆盖新增、修改和删除文件。构建不得写入时间戳或机器绝对路径等不稳定内容。
- 发布前强制执行产物一致性检查；前端检查成功后才进入签名和打包，防止旧 UI 随新 Go 代码发布。更新 Makefile 的构建输入、Python 发布脚本测试、`build.bat` 和 GitHub Actions。
- Docker 继续可使用提交的前端产物在 Go 阶段构建；CI 同时检查源码与产物一致，容器运行时不添加 Node.js。Dockerfile 的 COPY 输入与实际结构同步。
- 本地可以使用 Vite 开发服务，但 API、事件流和文件请求必须到同一 Go 实例。优先通过 Go 同源开发入口转发前端资源；若使用 Vite 代理，须实测 Origin/Host、localhost 权限、SSE、Range 和动作头，不放宽生产访问策略来迁就开发服务。开发代理只在显式开发模式启用。

### 预览专门验收

- 弹窗预览与独立页面共用预览适配器，保留标题、下载原文件、返回位置、加载/失败提示；未知类型维持下载降级。
- 图片及 SVG 的既有隔离策略、原始尺寸切换、滚动与键盘操作保持；音视频保持播放、音量、进度与编码错误提示。
- 文本保持前 256 KiB 范围读取、截断提示和 UTF-8、GB18030/GBK、UTF-16LE、UTF-16BE 切换。
- PDF 保留 PDF.js 6.4.299、分页、跳页、缩放、按需读取，以及 Worker、字体、CMap 和 WASM 路径。
- DOCX 保留 docx-preview 0.4.1 与 JSZip 3.10.2、32 MiB 上限、禁用 altChunk HTML/评论/修订；旧 `.doc` 继续只下载。
- XLS/XLSX 保留 SheetJS 0.20.3 的 Worker 解析、32 MiB 上限、最多 20 个工作表、每表最多 250 行/50 列、切表及截断提示；公式只显示缓存值，不执行宏。
- HTML 入口与预览资源各自的 CSP 保持；不添加 `unsafe-eval`、外部 CDN 或宽泛跨源许可。独立预览页已有的 WASM 执行例外不扩展为全站策略。
- 连续打开、切换文件、关闭、跳页离开和后退缓存恢复时，中止 fetch、终止 Worker、销毁 PDF 文档/渲染任务、停止媒体并释放 Object URL；异步旧结果不得写入新文件界面。

### 实时刷新与状态生命周期

- 沿用 `/api/events` 的 `change` 事件、`version`、`files`/`texts` 标记、事件合并及按需刷新；不改变服务端协议。
- 每页统一持有订阅，组件不各自重复创建 EventSource。保留断线后页面可见期间每分钟轮询恢复、连接恢复后停轮询的语义。
- 目录切换、搜索和文本读取使用取消与请求序号保护；页面隐藏、离开和关停时按现有规则停止相应请求及定时任务，恢复可见时刷新。
- 服务端结果与暂态分开维护；SSE 更新不能随意重置排序、多选、滚动、编辑输入、预览位置或正在上传的任务。不得因组件重挂载重复提交写操作。

## 实施阶段与退出条件

### 阶段一：建立基线与兼容测试

盘点实际功能及浏览器支持范围，整理桌面/窄屏截图、API 请求样例、关键文件样本与现有测试映射。优先补充当前模拟 DOM 难以覆盖的真实交互回归，不为纯搬迁编写镜像实现测试。

**验收：** 原前端通过基线用例；建立包含 localhost、本机通过 LAN 地址访问、远端 LAN 访客、IPv6（环境支持时）及非默认端口的验证记录。现有缺陷单独记录，不混入重构。

### 阶段二：工程基础与设置迁移

建立 Vue/TypeScript/Vite 多页面构建、提交产物和 CI 一致性校验；提取 API、Toast、确认弹窗及设置组件。保留未迁移页面的资源，用显式挂载边界接入设置组件。新旧确认服务可有短期适配，但每个弹窗只有一个实现负责打开、关闭和恢复焦点。

**验收：** 设置与更新/关停完整链路等价，旧页面仍可运行；无 Node.js 的干净检出仍能 Go 直接构建运行；资源被嵌入，开发与生产权限语义一致。

### 阶段三：共享空间迁移

迁移目录导航、搜索排序、选择与焦点、菜单、文件操作和上传。将上传、目录请求与 SSE 的生命周期交给明确的功能模块，移除对应全局脚本。

**验收：** 文件管理和上传清单逐项通过，包括连续搜索旧响应、列表刷新时多选、冲突取消、预检过期、网络中断、目标目录切换、非空目录删除及服务端错误。刷新、直达与前进/后退保持。

### 阶段四：文本快传与预览迁移

迁移文本页及分享/服务状态组件；将既有预览引擎封装为具有显式挂载和销毁契约的适配器，由 Vue 持有独占容器，避免 Vue 和第三方库同时更新内部节点。

**验收：** 所有格式在弹窗及独立页面均通过；反复开关预览无残留任务或旧内容覆盖；断网、隐藏/恢复、关闭服务及更新重连正确，复制在普通 LAN HTTP 下可用或给出原有失败反馈。

### 阶段五：清理与发布验证

删除已无调用的 `window.LanCopy*` 桥接与旧脚本，更新相邻测试、开发文档、README、构建输入及 CI。保留历史兼容 URL；仅在对应替代行为已验证后删除旧测试，不以新组件结构作为删除原行为断言的理由。

**验收：** 完成以下发布检查，所有必需项无未解释失败；测试平台不足时明确列为未完成，不能声称“全平台无影响”。

## 验证与发布门槛

- **前端：** 严格类型检查、生产构建、产物一致性检查；Vitest/Vue Test Utils 覆盖有业务意义的状态与组件行为，Playwright 在真实 Go 服务上覆盖主要用户链路。测试依赖不进入生产资源。
- **现有回归：** `make test`、`go vet ./...` 及受影响 HTTP/上传/预览/更新测试全部通过；将旧 Node.js 模拟 DOM 测试逐项映射为保留或等价替代，包含文件时间、删除确认、状态、目录收集、弹窗与设置更新。
- **浏览器：** 以记录的版本验证 Chromium/Edge、Firefox、Safari；自动化 WebKit 不代替实际 Safari。移动端实际验证 iOS Safari、Android Chrome 的窄屏、触摸、预览、复制和浏览器支持的上传方式，保留原有能力降级。
- **协议与安全：** 验证既有 GET/HEAD/Range、下载文件名、MIME、CSP、动作头、本机与访客差异，以及错误状态、超限、非法路径、未知资源 404。不得用放宽服务端策略解决前端兼容问题。
