# v0.15.1 计划：CI 不再使用 macOS runner

## 背景

`.github/workflows/release.yml` 的 `test` job 矩阵包含 `macos-latest`，而 `build` 依赖它。macOS runner 排队时间长，每次推送 `main` 都要等一台 macOS runner 才能进入构建。macOS 专属测试实际上只有 `internal/desktop/autostart_darwin_test.go`，而发布者本机就是 macOS，可以在发布前本地跑完。

## 方案

1. `release.yml` 的 `test` job 矩阵收敛为 `[ubuntu-latest, windows-latest]`；tag 发布时的 `homebrew` job 仍使用 `macos-latest`（`brew audit` 需要）。
2. `Makefile` 新增 `release-test` 目标：先确认平台是 `Darwin`，再执行 `go vet ./...`、Python 脚本测试与 `go test ./...`。本机为 macOS 时这组命令覆盖 CI 移出的 darwin 测试。
3. `make publish` 的构建命令改为 `$(MAKE) --no-print-directory release-test build`，测试在签名构建之前执行；测试失败则不递增版本、不提交、不打标签、不推送。`make -n publish` 预览行为不变。
4. 文档同步：`docs/GITHUB-ACTIONS.md` 更新矩阵与 `make publish` 步骤，`docs/DEVELOPING.md` 增加 `make release-test` 与 CI 范围的说明。
5. `VERSION` 递增构建号：`0.15.1-build2` → `0.15.1-build3`。

## 不做的部分

- 不删除 `build` job 的 `GOOS=darwin` 交叉编译：发布包构建仍需在 Linux 上产出 macOS 归档。
- 不改 `homebrew` job 的 runner，也不改前端 `browser` job。
- 不在 CI 里用 `continue-on-error` 保留 macOS 测试：runner 仍需排队，无法解决等待问题。
