# Lan Copy v0.5.5 计划

制定及扩展日期：2026-10-27。基于当前 v0.5.4 工作区，包含更新历史清理与打印队列首期功能；实际实施与验收见对应进度文档。

## 背景与目标

用户反馈多次更新后留下大量 update 文件。当前 `internal/updater/service.go` 在程序所在目录创建 `.lan-copy-update-*` 暂存目录，包含下载包、候选程序、更新辅助程序和更新计划。

代码检查确认：更新成功会删除 `previous`、下载包和计划等文件；非 Windows 平台还会删除整个暂存目录。Windows 因运行中的辅助程序无法删除自身，会留下 `updater.exe` 及目录，后续没有历史清理机制。更新中途失败也可能保留目录及恢复文件。上述为代码依据，本轮未复现用户设备上的实际残留。

本版目标：

1. 自动清理历史更新残留，只保留最近两个更新版本对应的历史目录，避免随更新次数持续增长。
2. 在分享按钮左侧增加打印入口，进入打印队列页面；支持选择 Windows 主机已安装的打印机、打印一张测试页，并展示本次启动后的测试任务。完整文件打印在后续版本完善。

## 保留规则与范围

- “最近两个版本”按最近两次成功更新记录计算；同一版本重复安装合并计数，以最新一次成功记录为准。当前安装路径中的主程序不计入历史目录配额。
- 保留的历史目录用于更新诊断，不新增历史版本切换功能，不为凑足两个版本重新保留已被现有流程删除的安装包或旧程序。非 Windows 平台继续及时删除可清理的暂存目录，历史目录数量可以少于两个。
- 只处理当前可执行程序所在目录下、能确认属于该程序的 `.lan-copy-update-*` 目录；不扫描共享文件目录，不清理用户自行下载的发布包、`release/` 或其他名称含 update 的文件。
- 进行中的更新、回滚尚未完成以及仍含唯一恢复副本的目录不进入历史淘汰集合。保护项可能使目录数暂时超过两个；日志明确说明原因，恢复完成后再收敛。
- 保持现有 API、更新包格式、签名及程序身份校验、启动参数、健康检查和自动回滚语义；不修改版本号或发布配置。

## 技术方案

### 更新记录与清理边界

在 `internal/updater/` 内实现记录、扫描和清理，按需要新增内聚文件，不把文件删除逻辑放入 HTTP 或应用组装层。

为后续更新目录增加小型状态记录，保存目标程序标识、更新 ID、版本、完成时间及结果。版本来自已验证的更新清单；如需扩展内部 `Plan`，新增字段允许缺省，兼容已有内部计划。状态记录采用临时文件替换方式提交，只有辅助进程通过现有健康检查、确认更新成功后才标记成功，不能把新服务刚启动视为更新完成。

成功记录按完成时间降序排列，使用更新 ID 打破相同时间的排序歧义；同版本取最新记录，保留前两个版本对应目录，其余已完成目录进入删除集合。失败但已完成恢复、且无恢复副本的暂存目录可直接清理，不挤占成功版本配额。

清理前核对目录归属与状态，跳过符号链接、异常路径和无法判定的内容；不能仅凭名称前缀递归删除。可变状态与更新互斥由 updater 统一管理，明确主进程和辅助进程之间的状态交接，避免扫描期间删除刚创建或尚未完成的事务。

### 清理时机与 Windows 文件占用

- 在普通应用启动和每次成功更新后执行历史清理；普通启动入口通过 updater 的明确方法接入，应用组装层只负责调用。
- Windows 保留正在运行的辅助程序，由后续启动或下一次更新清理超过配额的历史目录；不要求辅助程序强删自身，不引入常驻清理进程。
- 文件占用、权限不足或部分删除失败时记录路径和原因，下次清理重试。清理失败不将已成功的更新改判为失败，也不阻止服务正常启动。
- 保留现有单个 `lan-copy-update.log` 的用途；清理错误接入可用日志，避免新增无限增长的日志文件集合。

### 已有残留迁移

旧版成功更新在 Windows 上通常只留下 `updater.exe`，没有版本和完成时间记录。不能将这些目录直接当成可按语义版本排序的成功记录。

为旧目录提供明确的兼容识别：仅把内容严格符合旧版成功残留布局、辅助程序可确认属于 Lan Copy、且文件已不被占用的目录作为可回收历史项；有 `plan.json`、`previous`、候选程序或未知文件的目录先保护并记录原因。旧记录暂按目录修改时间排序，同时间按目录名稳定排序，最多保留两项；新记录优先，逐步挤出旧记录，历史集合总配额仍为两个。该时间仅用于无法恢复版本信息的旧残留排序，不冒充准确的版本信息。

## 实施阶段

### 一：实现保留策略与旧目录识别

在 updater 内实现状态记录、稳定排序、版本去重、两版本配额、路径和恢复文件保护，以及旧残留识别。

**退出条件：** 临时目录测试覆盖 0/1/2/多版本、重复版本、相同时间、混合新旧目录、异常记录、符号链接、未知文件及恢复副本保护；删除范围不越出目标程序目录。

### 二：接入更新生命周期与启动清理

将成功状态提交和清理接入 `RunHelper`，在正常应用启动时调用 updater 清理入口。保留失败回滚分支，处理清理失败及重试。

**退出条件：** 正在执行的更新不被清理；健康检查失败仍可恢复旧程序；清理失败不影响服务启动或更新结果；完成恢复后的无用暂存文件可以回收。

### 三：多轮更新与跨平台验收

扩展现有 `internal/httpserver/update_test.go` 的真实进程更新测试，验证连续至少四个版本更新后的目录数量、保留顺序，以及升级旧残留的首次清理。使用隔离的测试程序目录，不删除开发者真实安装文件。

**退出条件：** Windows 实机验证辅助程序退出后旧目录可删除，连续更新及重启后收敛到最多两个历史版本；Linux/macOS 验证及时清理行为和回滚不退化。文件占用、权限错误、唯一恢复副本场景验证保护与后续重试。

## 打印队列首期方案

### 页面与交互

- 顶栏分享图标左侧新增打印图标，使用可新标签打开的链接 `/print-queue`，当前页面显示选中状态；与共享空间、文本快传共用 SPA 顶栏。支持直接访问、刷新及浏览器前进后退，保留原有文件夹地址与文本草稿。
- 桌面使用左右两栏：左侧选择打印机、刷新列表、测试页示意及“打印测试页”；右侧展示任务记录。手机改为上下排列。
- 自动选择可用的系统默认打印机，否则选择列表第一台；刷新时保留仍有效的选择。只枚举服务主机当前用户已安装的打印机，过滤常见需交互的虚拟打印机和传真。
- 显示加载、无打印机、不支持平台、读取失败及服务关闭状态；发送动作前需成功读取打印机与任务状态。任务待提交或正在提交时禁用按钮。
- 明确本版只提供测试页，不提供普通文件上传打印、页码/纸张/份数设置、系统队列完整镜像和取消任务功能。

### 后端与平台边界

- 新增 `internal/printing`，组件拥有任务记录、序号、提交互斥及平台实现；由 `internal/app` 组装，通过参数传入 HTTP 服务。保持单进程、单二进制，不启动外部打印工具。
- Windows 使用 `EnumPrintersW`、`GetDefaultPrinterW` 读取设备，使用 GDI `CreateDCW`、`StartDocW`、`StartPage`、`TextOutW`、`EndPage`、`EndDoc` 绘制一张 Lan Copy 测试页，沿用设备默认设置；失败时尽力 `AbortDoc`，释放字体和 DC。GDI 操作固定在同一系统线程。
- 非 Windows 主机返回不支持原因，页面仍可访问；Windows 原生实现使用 `_windows.go`，其他平台用构建约束。
- `GET /api/printing` 返回能力与打印机列表；`GET /api/printing/jobs` 返回当前服务启动后的最近 50 条测试任务；`POST /api/printing/test` 仅接收打印机名称，不接收任意文件、命令或端口。读写返回 `no-store`。
- 测试请求使用自定义动作头并校验 Origin / Sec-Fetch-Site，允许同源局域网访客发起。应用关闭后拒绝新任务。异步提交在组件内再次核对打印机，任一时刻只允许一个测试任务进入原生提交阶段。
- 状态仅包括等待提交、正在提交、已提交、提交失败；记录系统任务 ID。“已提交”仅代表交给 Windows 队列，不声称已实际出纸；任务不会自动重试，错误提示用户先核对系统队列。任务记录重启后清空，不维护第二份系统持久队列。

### 四：实现打印入口与页面

实现共享顶栏入口、SPA 路由、打印页面及独立 HTML 加载骨架；更新 Vite 构建与嵌入资源同步清单。

**退出条件：** 直接访问与页内切换均可用，打印按钮位于分享左侧；桌面与窄屏无横向溢出；选择、刷新、禁用与错误状态有验证，文件夹地址与文本草稿不退化。

### 五：实现打印机发现与测试页提交

实现 printing 组件、Windows 枚举与 GDI 测试页、非 Windows 降级和 HTTP 接口。

**退出条件：** 测试覆盖重复提交互斥、设备重新校验、驱动失败不自动重试、最近 50 条记录、跨站动作拒绝及不支持平台；Windows 编译通过。Windows 实机能够枚举目标打印机并输出一张测试页后，才算平台验收完成。

### 六：打印页面与平台验收

执行前端类型检查、组件/路由/资源同步测试、生产资源构建与校验，以及真实浏览器下的入口、布局和模拟任务反馈验证；运行受影响 Go 检查与跨平台构建。

**退出条件：** 明确区分真实浏览器加模拟打印响应与 Windows 原生运行；Windows 实机验证无设备、默认设备、设备移除、正常测试出纸及提交失败。后续完整打印不进入本版完成标准。

## 验证与完成标准

- 执行 `go test ./internal/updater ./internal/httpserver ./internal/app`、`go test ./...`、`go vet ./...` 及受影响包的 race 检查。
- 验证根目录 `go build .`，检查 Windows/Linux/macOS 构建；构建产物写入临时位置。分别记录跨平台编译和真实平台运行结果，不能以交叉编译代替 Windows 文件占用验收。
- 多轮成功更新后，除明确保护的活动或恢复目录外，历史目录最多对应最近两个版本；旧版遗留目录可按兼容规则收敛，异常目录跳过原因可追踪。
- 更新签名校验、健康检查、失败恢复、共享文件及文本数据保持原有行为；重复清理结果稳定且不影响正常运行。
