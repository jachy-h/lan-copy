# Lan Copy v0.4.2 计划

## 目标

收拢共享空间的重复标题和分散操作，让文件列表保持稳定：根目录只出现一个可见的“全部文件”，常用工具和选择操作集中在右侧悬浮框，最近修改的文件带“新”标签，文件预览在当前页面弹窗中完成。

本次先确定修复方案，不在计划阶段修改页面实现。以下方案替代 v0.4.0 计划中与本次交互冲突的部分，尤其是列表上方的选择命令栏和跳转预览页的行为。

## 1. 三处“全部文件”的修复方案

### 当前问题

根目录下同时存在三个可见的“全部文件”：

- `web/index.html` 中的 `#goRoot` 回根目录按钮。
- `web/filesystem.js` 的 `crumbs()` 生成的面包屑根节点。
- `#currentFolderName` 展示的当前位置标题，根目录时也是“全部文件”。

三个入口表达同一个位置，增加视觉噪声，也占用了列表上方空间。

### 调整方式

- 以面包屑作为唯一的位置表达：根目录显示“全部文件”，子目录显示“全部文件 / … / 当前目录”。根节点继续承担回到根目录和拖放移动目标的职责，当前节点保留 `aria-current="location"`。
- 移除独立的 `#goRoot` 按钮及其事件绑定，回根目录统一点击面包屑根节点。
- 移除 `#currentFolderName` 及其渲染逻辑，不再单列重复的当前位置标题。
- 将 `#entrySummary` 合并到导航区的次级状态位置；窄屏可换行，但不再增加重复位置标题。
- 保留“上一级”和“刷新”。长路径允许横向滚动，根节点保持可达；修改面包屑时核对每一级真实目标路径，覆盖导航和拖放。

**验收：** 根目录的常规界面只显示一次“全部文件”；子目录仍能明确识别当前位置、回根目录、逐级导航和拖放移动。操作结果提示或确认弹窗中的必要文字不受此限制。

## 2. 名称后的“新”标签组件

### 展示规则

- 增加轻量、可复用的 tag 展示组件，首个用途为“新”标签；沿用原生 DOM 和现有样式体系，不引入 UI 库。
- 使用文件列表接口已有的 `modified` 字段，与“修改日期”列使用同一数据源，不根据上传时间、首次访问时间或本地缓存判断。
- 首版只标记文件，不标记文件夹。满足 `0 <= 当前时间 - 修改时间 < 4 小时` 时，在名称文字后紧接显示“新”。恰好满 4 小时、未来时间、缺失或无效时间均不显示。
- “新”表达最近修改，也包含原有文件被修改的情况；辅助说明使用“最近 4 小时内修改”，避免让用户误以为只代表新上传。
- tag 使用紧凑字号、圆角和轻量背景，文字可读；文件名过长时优先省略文件名，tag 不被挤掉、不另起一行、不改变行高。
- tag 是独立的名称旁展示元素，不拼入原始文件名；搜索高亮、名称排序、重命名、复制路径、下载文件名和预览标题继续使用原始名称。

### 时间更新

- 每次列表渲染重新判断；页面可见期间以轻量定时任务更新标签，到期后最多一分钟内移除。
- 标签更新只增删 tag，不重建整个列表，避免破坏焦点、选择和滚动位置。
- 页面重新可见时立即校准；页面退出时清理定时任务。时间使用时间戳比较，显示时区不影响四小时窗口；首版沿用客户端时钟，不扩展服务端 API。

**验收：** 0 小时、接近 4 小时、恰好 4 小时、超过 4 小时、未来时间和无效时间判断正确；停留页面跨过有效期后标签消失。长名称、搜索结果和选中行内的标签均清楚可见。

## 3. 多选状态与操作移入右侧悬浮框

- 从文件列表正常文档流中移除现有 `#selectionBar` 整行，不仅隐藏其中的文字；清理对应的间距、分隔线和样式。
- 将“x 项已选择”和现有“操作”入口迁入右侧悬浮框的固定选择区。未选择时显示“未选择文件”并禁用选择操作，保持区域高度稳定；选中一项和多项时均显示准确数量。
- 选择操作继续复用现有菜单和命令分发。只启用已有语义支持的操作，保留单项重命名等限制，不借布局调整新增批量写入能力。
- 悬浮框内提供明确的“取消选择”入口；选择数量保留 `aria-live="polite"`，不要在每次列表更新时重复播报。
- 点击悬浮框中的搜索、操作按钮或菜单不能被列表的空白点击逻辑误判为取消选择；输入框、菜单和弹窗中的键盘事件不触发文件列表快捷键。
- 搜索、切换目录、删除、移动、SSE 刷新后，数量与有效选择同步；已消失的条目不能继续计入或操作。

**验收：** 从零选择到单选、多选，再取消选择，列表表头和文件行的纵向位置均不发生变化；悬浮框始终显示正确数量和可用操作。

## 4. 预览改为当前页面弹窗

- 文件双击、Enter 打开及菜单“预览”统一调用页内预览入口，不再通过 `location.href` 跳转 `/preview.html`。
- 检查 `LanCopyFileUI.previewName()` 及文本快传页的预览入口，让普通点击也在所在页面打开同一弹窗，避免两套交互。
- 使用原生 `<dialog>` 与遮罩承载预览，包含文件名、关闭、下载、加载状态及内容区。打开和关闭都不改变当前页面 URL、目录历史、搜索、排序、选择或列表滚动位置。
- 从 `web/preview.js` 提取可挂载、可销毁的预览渲染能力，弹窗与原独立预览页共同复用。保留已有 `/preview.html` 深链接兼容入口；常规页面操作使用弹窗。
- 直接挂载预览内容，不通过 iframe 嵌入独立预览页；现有服务的 `frame-ancestors 'none'` 安全策略保持不变。
- 保留图片缩放、音视频播放、文本编码与截断提示、PDF 翻页缩放和下载能力，复用 `/preview-files/` 与现有预览类型判断。
- 不支持预览的文件维持原有下载或提示行为，不显示空弹窗；文件被移动、删除或请求失败时，在弹窗内清楚显示错误和可用动作。
- 打开时焦点进入弹窗，Tab 不离开弹窗；关闭按钮与 Escape 均可关闭。关闭后焦点返回触发条目或按钮，条目已不存在时返回列表。
- 关闭或切换文件时取消旧请求，停止音视频，销毁 PDF 渲染任务并释放监听器、定时器和临时资源，阻止旧响应覆盖新内容。预览关闭后不再后台播放。
- 桌面端居中并限制最大尺寸；窄屏采用接近全屏的弹窗，内容在内部滚动，关闭和下载保持可达；锁定背景滚动并在关闭后恢复。

**验收：** 各预览入口都在当前页面打开弹窗；关闭后页面状态不变。连续开关、快速切换文件、加载中关闭、错误、键盘关闭和移动端滚动均正常；旧预览链接仍可使用。

## 5. “共享空间”工具行移入右侧悬浮框

### 内容与结构

将当前 `.section-head` 整行中的“共享空间”、文件搜索、清除搜索、上传文件夹、新建文件夹迁入同一个右侧悬浮框，与选择状态统一组织：

1. 标题：“共享空间”。
2. 搜索区：文件搜索和清除入口，继续搜索当前文件夹及子文件夹。
3. 文件夹操作区：上传文件夹、新建文件夹。
4. 固定选择区：“x 项已选择”、操作入口和取消选择。

- 主内容区从导航与面包屑开始，下接条目统计、列表表头和文件列表；移除迁出工具行的占位与旧样式。
- 迁移真实控件而非复制第二套 DOM，保持 ID 唯一，复用已有事件和状态。隐藏的文件夹上传输入仍由同一个上传流程管理。
- 将 `#explorerTitle` 用于悬浮框标题，并调整列表区域的可访问名称引用，避免迁移后留下失效的 `aria-labelledby`。
- 新建和上传的目标继续是当前目录；搜索结果不会改变写入目标。目录切换和上传进度仍由现有文件系统状态管理。

### 定位与响应式

- 桌面端使用固定在视口右侧的悬浮面板，页面为其预留稳定侧边空间，文件列表不被遮挡；滚动文件列表时工具仍可操作。
- 悬浮框保持明确宽度、屏幕边距和最大高度，超出视口时内部滚动；与顶部栏、菜单、toast 的层级协调，预览及确认弹窗始终位于其上方。
- 窄屏和放大显示下改为右侧抽屉，提供固定、可触达的“共享空间工具”按钮；不挤压列表到不可读，也不把工具移回会随选择状态撑高的列表工具行。
- 抽屉打开时限制背景交互并管理焦点，关闭后返回触发按钮；隐藏时内部控件不能通过 Tab 聚焦。选择数量可在固定入口中显示，不引起列表重排。
- 拖放上传/移动范围保持清楚，工具控件不误触发背景拖放；保留长路径、长名称和移动端安全区的处理。

**验收：** 原工具行内容完整迁入右侧悬浮框，主列表上方不再保留重复入口；桌面滚动时面板可用，窄屏全部功能可达，列表不被遮挡，无横向溢出。

## 实施顺序与主要改动位置

1. **导航去重及布局收拢。** 调整 `web/index.html`、`web/filesystem.js`、`web/style.css`：先合并位置表达，再建立右侧悬浮框并迁移工具与选择区，清理旧 DOM 引用、监听和样式。
2. **tag 组件。** 在 `web/file-ui.js` 增加可复用的 tag 展示辅助；文件时间判断和定时更新由 `web/filesystem.js` 管理，`web/style.css` 定义标签样式，不向展示辅助模块转移列表状态。
3. **页内预览。** 重构 `web/preview.js` 的渲染生命周期，增加实际需要的弹窗入口模块；同步检查 `web/preview.html`、`web/file-ui.js`、`web/filesystem.js`、`web/app.js`、`web/transfer.html` 的调用与资源加载顺序。
4. **交互回归。** 核对布局稳定、焦点、快捷键、抽屉、预览资源清理及现有 API 行为，补充与实际行为对应的必要测试。

## 验证与兼容性

- 标签测试覆盖时间窗口边界和到期更新；预览测试覆盖重复打开、取消请求与资源销毁；选择测试覆盖控件点击不误清除选择及外部刷新后状态同步。不为纯颜色或静态间距写脆弱快照测试。
- 浏览器实测根目录/多级目录、空目录、递归搜索、长名称、多选、SSE 更新、拖放上传与移动，以及图片、音视频、文本和 PDF 预览。
- 对比选择前后表头位置与页面滚动位置，验证无布局下移；检查桌面、窄屏、页面缩放和纯键盘使用。
- 运行受影响的现有前端脚本测试与 Go 测试；通过 `go build .` 检查资源嵌入，通过 `go run .` 检查实际页面加载。若新增资源，核对静态服务、嵌入范围与构建输入。
- 保持单进程、单二进制及嵌入式前端，不引入前端框架；不更改文件系统 API、访问策略、存储格式、上传提交/回滚、启动恢复及更新身份校验语义。
- 本版范围为上述前端交互修复，不改动更新提示或 v0.5.0 的 MCP 计划。
